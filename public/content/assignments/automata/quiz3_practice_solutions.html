Unary Addition Turing Machine
TM SCHEMA · STATE DIAGRAM · DESIGN
▶
Problem
Input tape: \(\sqcup\, \underbrace{1\cdots1}_{x}\, \#\, \underbrace{1\cdots1}_{y}\, \sqcup\). Head starts on the first blank to the right of the input. Output: \(\sqcup\, \#\, \underbrace{1\cdots1}_{x+y}\, \sqcup\) with head on the first blank to the right.
a
Design a Turing Machine schema for a TM that adds two numbers in unary notation.
b

Part A — TM Schema
Key Insight
unary addition = concat erase the #
▶
\[ x \# y \;\xrightarrow{\text{TM}}\; \# \underbrace{1\cdots1}_{x+y} \]
Strategy: replace the # separator with a 1, then erase the leftmost 1 to keep the count correct (since we now have x+y+1 ones). Alternatively: move all y ones adjacent to x ones and delete the #.
TM Schema Notation ▶
A TM schema uses high-level building blocks: \(R\) (move right), \(L\) (move left), and named sub-machines like Find(\(a\)) to scan for symbol \(a\). Transitions are labeled with the symbol read and the action taken.
1
Move left to find the #
Starting from the blank to the right of the input, scan left until we find the # separator.
2
Replace # with 1
Overwrite the # with a 1. Now the tape looks like \(\sqcup\, \underbrace{1\cdots1}_{x+y+1}\,\sqcup\). We have one extra 1.
3
Scan left to the leftmost 1 and erase it
Move left past all 1s to the blank on the left edge. Move right one cell (onto the first 1) and overwrite it with #. This restores the count to \(x+y\) ones and puts the required # at the front.
4
Position the head
Scan right past all the 1s to the blank after the last 1. Halt. Tape is now \(\sqcup\,\#\,\underbrace{1\cdots1}_{x+y}\,\sqcup\) with head on the first blank to the right.
✓ Schema (high-level) Start at right blank → \(L\) until # → write 1 → \(L\) until \(\sqcup\) → \(R\) → write # → \(R\) until \(\sqcup\) → Accept.

No Pumping Lemma for Decidable Languages
DECIDABILITY · PUMPING LEMMA · CONCEPTUAL
▶
Problem
The pumping lemma gives a necessary property of regular and context-free languages that can be used to prove a language is not in those classes.
—
Explain why we cannot prove a pumping lemma for Turing Decidable languages.
Solution
Key Insight
pumping = infinite class decidable = closed under *
▶
\[ \text{Pumping Lemma} \Rightarrow \exists \text{ strings NOT in class} \]
The pumping lemma works because the class it applies to does NOT contain every language. The decidable languages contain every recursive language — including every finite language and many others — leaving no room for a pumping-style exclusion argument.
1
How pumping lemmas work
A pumping lemma proves a language is NOT in a class by showing that every long enough string in a class-language can be "pumped" — repeated — and still stay in the language. If pumping produces a string outside the language, it wasn't in the class. This only works if the class is strictly smaller than all languages.
2
Why it fails for decidable languages
Turing-decidable languages form a very large class. Every finite language is decidable. Every regular language is decidable. But there exist undecidable languages (e.g., \(A_{TM}\)), so the class is not ALL languages. The issue is that a pumping lemma would need to give a structural property shared by ALL decidable languages — but decidable languages have no simple structural regularity. A TM can implement arbitrary computation; there is no bounded "memory" or "stack depth" to exploit the way finite automata or PDAs have bounded state.
3
The key counterpoint
For regular languages, the pumping lemma comes from the pigeonhole principle on states: a DFA with \(p\) states must repeat a state on strings of length \(\geq p\), creating the pump. Turing machines have unbounded tape, so no such pigeonhole argument applies — a TM can "remember" arbitrarily more information as strings grow longer, preventing any finite pump length \(p\) from working universally.
✓ Answer The pumping lemma exploits bounded memory (states for DFAs, stack for PDAs) via the pigeonhole principle. Turing Decidable languages use unbounded tape, so no fixed pump length \(p\) can serve as a universal bound. There is no finite structural regularity shared by all decidable languages that could be "pumped."
In one sentence: Decidable TMs have unbounded tape and arbitrary computational power, so there is no pigeonhole-style bound that forces string repetition the way bounded-state or bounded-stack machines do.
Concept
PUMPING LEMMAPIGEONHOLE
▶

Regular Pumping Lemma: If \(L\) is regular with pumping length \(p\), then every \(s \in L\) with \(|s| \geq p\) can be written \(s = xyz\) where \(|xy| \leq p\), \(|y| \geq 1\), and \(xy^iz \in L\) for all \(i \geq 0\).

Exam tip: The pumping lemma is a necessary but not sufficient condition for membership. It can only DISPROVE membership in a class, never prove it.

03
Universal & Nondeterministic Turing Machines
UTM · NTM · DEFINITIONS
▶
Problem
Two fundamental TM variants appear throughout computability theory.
a
Explain the Universal Turing Machine.
b
Explain the Nondeterministic Turing Machine.
Part A — Universal Turing Machine (UTM)
1
Definition
A Universal Turing Machine \(U\) is a single TM that takes as input the encoding \(\langle M, w \rangle\) of any TM \(M\) and any string \(w\), and simulates \(M\) running on \(w\).
2
How it works
\(U\) uses three tape regions: (1) the encoded transitions of \(M\), (2) the simulated tape contents of \(M\), (3) the current state of \(M\). At each step, \(U\) looks up the transition \(\delta(q, a)\) by scanning region (1), then updates regions (2) and (3) accordingly.
3
Significance
The UTM demonstrates that a single fixed machine can compute anything any TM can compute — it is the theoretical basis for the modern stored-program computer. \(U\) accepts \(\langle M, w \rangle\) iff \(M\) accepts \(w\); this is exactly the language \(A_{TM}\), which is Turing-acceptable but not Turing-decidable.
✓ UTM The UTM \(U\) is a TM that takes \(\langle M, w \rangle\) and simulates \(M\) on \(w\). It accepts iff \(M\) accepts \(w\). It is a programmable computer in TM form.
Part B — Nondeterministic Turing Machine (NTM)
1
Definition
A Nondeterministic TM is a TM where the transition function is \(\delta: Q \times \Gamma \to \mathcal{P}(Q \times \Gamma \times \{L, R\})\) — multiple next configurations may be possible from any state and symbol.
2
Acceptance
An NTM accepts \(w\) if some branch of its computation tree leads to an accept state. It rejects if all branches either reject or loop.
3
Equivalence to DTM
Every NTM can be simulated by a deterministic TM (with potentially exponential time overhead). Therefore NTMs and DTMs recognize the same class of languages — Turing-recognizable languages. Nondeterminism does not increase the power of TMs, unlike the situation with finite automata vs. NFA (same power) or compared to time complexity (P vs. NP open question).
✓ NTM An NTM allows multiple choices at each step; it accepts if any computation branch accepts. NTMs are equivalent in power to deterministic TMs — they recognize exactly the Turing-recognizable languages.
Concept
UTM = A_TM RECOGNIZERNTM ≡ DTM IN POWER
▶

Key distinction: The UTM is a specific machine; the NTM is a model of computation. Both are equivalent to standard TMs in what they can compute, but the UTM is critical for undecidability proofs (it recognizes \(A_{TM}\)).

Exam tip: Do not confuse "NTM accepts if some branch accepts" with "NTM accepts if all branches accept" — the former is correct.

Decidable Languages Closed Under Kleene Star
CLOSURE PROPERTIES · DECIDABILITY · PROOF
▶
Problem
Closure properties tell us whether applying an operation to languages in a class keeps us in the same class.
—
Are Turing Decidable languages closed under the Kleene star operation? Prove your answer.
Solution — Yes, Closed Under Kleene Star
Key Insight
finite partitionsDP over prefixes
▶
\[ w \in L^* \iff \exists\, k \geq 0,\; \exists\, w_1,\ldots,w_k \in L : w = w_1 w_2 \cdots w_k \]
There are finitely many ways to split a finite string \(w\) into parts. We can try all of them and use a decider for \(L\) on each piece.
1
Claim
If \(L\) is Turing decidable, then \(L^*\) is Turing decidable.
2
Construction of the decider
Let \(M_L\) be a decider for \(L\). Construct TM \(M^*\) on input \(w\):

Use dynamic programming: let \(\text{dp}[i] = \text{true}\) if \(w[1..i] \in L^*\). Set \(\text{dp}[0] = \text{true}\) (\(\varepsilon \in L^*\)). For \(i = 1\) to \(|w|\): for each \(j = 0\) to \(i-1\): if \(\text{dp}[j] = \text{true}\) AND \(M_L\) accepts \(w[j+1..i]\), set \(\text{dp}[i] = \text{true}\). Accept iff \(\text{dp}[|w|] = \text{true}\).
3
Why it halts
\(w\) has length \(n\). There are \(O(n^2)\) substring pairs \((j, i)\). For each, \(M_L\) is run and always halts (since \(M_L\) is a decider). So \(M^*\) always halts.
4
Correctness
\(\text{dp}[|w|]\) is true iff there exists a split of \(w\) into pieces each in \(L\), iff \(w \in L^*\). The DP correctly captures all possible concatenations by induction on prefix length.
✓ Yes — Decidable languages are closed under Kleene star Given decider \(M_L\) for \(L\), build \(M^*\) that runs a DP over all \(O(n^2)\) substrings of \(w\), calling \(M_L\) on each. Since \(M_L\) always halts and there are finitely many substrings, \(M^*\) always halts and correctly decides \(L^*\).
Concept
CLOSURE PROPERTIESDECIDABLE LANGUAGES
▶

Decidable languages are closed under: union, intersection, complement, concatenation, and Kleene star. The key in each proof is showing the constructed TM always halts.

Exam tip: The hard part of Kleene star is avoiding infinite loops — make sure your construction only considers finitely many splits (all \(O(n^2)\) substrings), not recursively infinite ones.

Simulating a k-Head 1-Tape TM
TM VARIANTS · SIMULATION · MULTI-HEAD
▶
Problem
A \(k\)-head 1-tape TM has \(k\) read/write heads that can move independently on a single tape.
—
Show how to simulate a \(k\)-head 1-tape Turing Machine with a basic (1-head 1-tape) Turing Machine.
Solution — Marking Head Positions
Key Insight
mark head positionsencode in alphabet
▶
\[ \Gamma' = \Gamma \times \{0,1\}^k \]
Each tape cell stores the original symbol PLUS a bit-vector of length \(k\) indicating which heads are currently on that cell. The single head sweeps the tape to find marked cells and simulate each head's action.
1
Encoding
Replace each tape symbol \(a \in \Gamma\) with a pair \((a, b_1 b_2 \cdots b_k)\) where \(b_i = 1\) if head \(i\) is currently on this cell, 0 otherwise. The single TM's alphabet is \(\Gamma \times \{0,1\}^k\).
2
Simulating one step
To simulate one step of the \(k\)-head TM:
• Pass 1: Sweep left-to-right across the tape, reading the symbol under each marked head position (where \(b_i = 1\)). Store all \(k\) read symbols in the finite control (state).
• Compute: Using the \(k\)-head TM's transition function \(\delta\), determine what each head writes and which direction each head moves.
• Pass 2: Sweep the tape again, updating the written symbols at each marked cell and moving the marks according to the computed moves.
3
Overhead
Each simulated step requires \(O(n)\) steps of the basic TM (two sweeps over the tape of length \(n\)). The state space of the simulator is \(|Q| \times \Gamma^k\) — polynomial in the original — which is still finite.
✓ Simulation Encode the tape as \(\Gamma \times \{0,1\}^k\), marking which cells each head occupies. The basic TM sweeps the tape twice per step: once to read all head symbols, once to write and update marks. Each step costs \(O(n)\) basic steps. The \(k\)-head TM and basic TM recognize the same languages.
Concept
TM VARIANTS EQUIVROBUSTNESS THESIS
▶

Church–Turing Thesis: All "reasonable" models of computation are equivalent in what they can compute. Multi-head, multi-tape, and nondeterministic TMs all recognize exactly the Turing-recognizable languages.

Exam tip: Simulation proofs always have two parts: (1) how to encode the richer model into the simpler one, and (2) how the simpler one executes each step. Don't forget to argue the simulation always halts iff the original does.

C++ Program Simulated by C Program
CHURCH-TURING · COMPUTABILITY · PROGRAMMING LANGUAGES
▶
Problem
Both C and C++ are Turing-complete programming languages.
—
Can we take a program written in C++ and simulate its input-output relationship with a C program? Justify your answer carefully.
Solution — Yes, by Church–Turing Thesis
1
Both languages are Turing-complete
C and C++ are both Turing-complete: any function computable by a TM can be expressed in either language (given unlimited memory). Therefore they compute exactly the same class of functions.
2
The simulation argument
Given any C++ program \(P\), we can write a C program \(P'\) that:
• Reads the source code of \(P\) as a string (its encoding).
• Simulates the execution of \(P\) on any given input \(w\), step by step, using a C implementation of a C++ interpreter/virtual machine.
• Outputs exactly what \(P\) would output on \(w\).
This is analogous to the Universal TM simulating any TM.
3
Caveat: halting behavior is preserved
The C program \(P'\) correctly simulates \(P\)'s input-output relationship — including cases where \(P\) loops forever (in which case \(P'\) also loops). The simulation does not solve the halting problem; it merely replicates behavior.
✓ Yes Since both C and C++ are Turing-complete, any C++ program's input-output behavior can be simulated by a C program. Write a C program that acts as a C++ interpreter: it takes \(\langle P, w \rangle\) and simulates \(P\) on \(w\). This follows directly from the Church–Turing Thesis and the equivalence of Turing-complete models.
Key phrase to use on exam: "Both C and C++ are Turing-complete; by the Church–Turing Thesis, any computable function expressible in one can be expressed in the other."
Concept
TURING COMPLETENESSCHURCH-TURING THESIS
▶

Turing Completeness: A system is Turing-complete if it can simulate any Turing Machine. All Turing-complete systems compute exactly the same set of functions.

Exam tip: This question is essentially asking "can a UTM simulate another UTM?" — yes, because both are equivalent models. The answer is always yes for any two Turing-complete languages.

Finite Language — Undecidable, Acceptable?
UNDECIDABILITY · RICE'S THEOREM · REDUCTION
▶
Problem
We classify languages about TMs by whether they concern what the TM computes (a semantic property).
—
Prove that \(L_{FIN} = \{\langle M \rangle \mid L(M) \text{ is a finite set of strings}\}\) is Turing Undecidable. Is it Turing acceptable? Prove or disprove.
Part 1 — Undecidability (via Rice's Theorem)
Rice's Theorem
non-trivialsemantic property
▶
\[ \text{If } P \text{ is a non-trivial semantic property of TM languages, then } L_P \text{ is undecidable.} \]
Non-trivial means: some TMs have the property and some don't. Semantic means: it depends only on what the TM computes, not how it is written.
1
Verify the property is semantic
"L(M) is finite" depends only on which strings \(M\) accepts — not on the number of states, transitions, or internal structure of \(M\). So it is a semantic property. ✓
2
Verify the property is non-trivial
• A TM that accepts only the string "0" has \(L(M) = \{0\}\), which is finite. ✓
• A TM that accepts \(\{0^n \mid n \geq 0\}\) = \(\{0\}^*\) has an infinite language. ✗
So some TMs satisfy the property and some don't. Non-trivial. ✓
3
Apply Rice's Theorem
By Rice's Theorem, since "L(M) is finite" is a non-trivial semantic property, \(L_{FIN}\) is Turing undecidable. \(\blacksquare\)
✓ Undecidable "L(M) is finite" is a non-trivial semantic property of TMs. By Rice's Theorem, \(L_{FIN}\) is undecidable.
Part 2 — Not Turing Acceptable (Co-RE, not RE)
1
Claim
\(L_{FIN}\) is not Turing-acceptable (not in RE). Its complement \(\overline{L_{FIN}} = \{\langle M \rangle \mid L(M) \text{ is infinite}\}\) is Turing-acceptable (in RE), but \(L_{FIN}\) itself is not.
2
Why \(\overline{L_{FIN}}\) is acceptable
To accept \(\langle M \rangle\) when \(L(M)\) is infinite: dovetail (interleave) simulations of \(M\) on all strings in lexicographic order, keeping count of how many strings have been accepted so far. If the count ever exceeds any finite bound \(n\), accept. If \(L(M)\) is truly infinite, eventually more than \(n\) strings will be accepted for every \(n\), so we'll accept. (More carefully: enumerate strings \(s_1, s_2, \ldots\) and simulate \(M\) on all of them in dovetail fashion; accept when we've seen \(k+1\) distinct accepted strings for any desired \(k\).)
3
Why \(L_{FIN}\) is NOT acceptable
Suppose for contradiction \(L_{FIN}\) were Turing-acceptable. Then both \(L_{FIN}\) and \(\overline{L_{FIN}}\) would be Turing-acceptable. By the theorem that a language is decidable iff both it and its complement are acceptable, \(L_{FIN}\) would be decidable. But we proved it is undecidable — contradiction. Therefore \(L_{FIN}\) is not Turing-acceptable. \(\blacksquare\)
✓ Not Turing Acceptable \(\overline{L_{FIN}}\) is Turing-acceptable (dovetail over all inputs, accept when infinitely many are accepted). If \(L_{FIN}\) were also acceptable, it would be decidable — contradicting Part 1. So \(L_{FIN} \notin \text{RE}\).
Concept
RICE'S THEOREMRE vs co-RE
▶

Rice's Theorem: Every non-trivial semantic property of TM languages is undecidable. This is the fastest way to prove undecidability for "L(M) has property X" problems.

RE / co-RE / neither: A language \(L\) is decidable iff \(L \in \text{RE}\) and \(L \in \text{co-RE}\). If \(L\) is undecidable, it is either in RE only, co-RE only, or neither. \(L_{FIN}\) is in co-RE (its complement is acceptable) but not in RE.

Conceptual Matching — UTM Encoding
UTM · ENCODING · MATCHING
▶
Problem
Match each concept to the most precise description. Options: (A) A single TM that simulates any TM M on input w  (B) Encoding of input string w over {c, I}  (C) Encoding of TM M over {c, I}  (D) A TM that decides every language  (E) Combined input to UTM  (F) Encoding requiring three distinct symbols.
1
\(\rho(M)\)
2
Universal TM
3
\(\rho(M)\rho(w)\)
Solution
1
\(\rho(M)\) → Answer: (C)
\(\rho(M)\) is the encoding of the Turing Machine \(M\) over the alphabet \(\{c, I\}\). It encodes \(M\)'s states, alphabet, and transition function as a binary-like string. Option (F) is wrong — the encoding uses exactly two symbols \(\{c, I\}\), not three. Option (C) is the most precise match.
2
Universal TM → Answer: (A)
The Universal TM is a single TM that takes \(\langle M, w \rangle\) and simulates \(M\) on \(w\). Option (D) is wrong — the UTM does not decide every language; it merely simulates. (A) is the most precise match.
3
\(\rho(M)\rho(w)\) → Answer: (E)
\(\rho(M)\rho(w)\) is the combined input given to the UTM: the concatenation of the encoding of \(M\) and the encoding of \(w\). This is exactly what the UTM reads to simulate \(M\) on \(w\). (E) is the most precise match.
✓ Matches (1) \(\rho(M)\) → (C)  |  (2) Universal TM → (A)  |  (3) \(\rho(M)\rho(w)\) → (E)
Why not (D)? No TM can decide every language — that would violate the undecidability of \(A_{TM}\). The UTM only simulates, it does not decide.
Concept
UTM ENCODINGρ(M)ρ(w)
▶

Encoding \(\rho\): TMs and their inputs are encoded over \(\{c, I\}\) so that a single alphabet suffices for the UTM. The encoding maps states, symbols, and transitions to strings of c's and I's separated by delimiters.

Exam tip: \(\rho(M)\) encodes the machine; \(\rho(w)\) encodes the input string; \(\rho(M)\rho(w)\) is their concatenation — the full input to the UTM.

09
Three Consecutive c's in \(\rho(M)\rho(w)\)
UTM ENCODING · SHORT ANSWER
▶
Problem
The encoding \(\rho(M)\rho(w)\) is the combined input fed to the Universal TM.
—
The encoding \(\rho(M)\rho(w)\) contains exactly one occurrence of three consecutive c symbols (ccc). In 2–3 sentences, explain why this is the case and why this property is useful for the Universal TM.
Solution
Encoding Convention ▶
In the standard encoding: a single c separates fields within a single transition (e.g., state from symbol). Two consecutive cc separates different transitions from each other. Three consecutive ccc marks the boundary between the end of \(\rho(M)\) and the beginning of \(\rho(w)\).
1
Why exactly one ccc occurs
Within \(\rho(M)\), the encoding uses at most two consecutive c's (single c for intra-field separation, cc for inter-transition separation). Within \(\rho(w)\), the encoding of input symbols uses at most one c at a time. The boundary marker ccc is deliberately placed between \(\rho(M)\) and \(\rho(w)\) as a unique delimiter, and the encoding conventions ensure ccc never appears inside either part alone.
2
Why this is useful for the UTM
The UTM must separate \(\rho(M)\) from \(\rho(w)\) to know where the machine description ends and the input begins. Since ccc appears exactly once and nowhere else in the encoding, the UTM can scan for the unique ccc marker to locate this boundary unambiguously — without any additional length information or special tape marks.
✓ Answer The encoding uses c and cc as internal delimiters within \(\rho(M)\), so ccc never appears inside either \(\rho(M)\) or \(\rho(w)\) alone. The single ccc is placed at the boundary between them as a unique separator. The UTM uses this unique marker to reliably split the combined input into the machine encoding and the input string, enabling correct simulation.
Concept
DELIMITER ENCODINGUTM PARSING
▶

Delimiter hierarchy: c = field separator within a transition | cc = transition separator within \(\rho(M)\) | ccc = boundary between \(\rho(M)\) and \(\rho(w)\). This hierarchy guarantees uniqueness at each level.

Exam tip: The key insight is that the ccc marker must be unique — this is what makes the UTM's parsing deterministic. If ccc appeared inside \(\rho(M)\), the UTM could not reliably find the boundary.
