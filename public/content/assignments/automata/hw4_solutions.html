Encoding Finite Automata
ENCODINGS · ANALOGOUS TO TM ENCODING · {c, I}* ALPHABET
▶
Problem
Analogous to the encoding of Turing machines, show how to encode finite automata as strings over the alphabet \(\{c, I\}\). State potential applications.
a
Define an encoding scheme for DFAs over \(\{c, I\}\).
b
Describe potential applications of such an encoding.
Part A — The Encoding Scheme
Key Insight
unary encoding separator c marker I
▶
\[ M = (Q,\, \Sigma,\, \delta,\, q_0,\, F) \]
Every component of the 5-tuple must be mapped to strings over {c, I}. We use unary: the integer k encodes as Ik, and c acts as a separator/delimiter.
What is a DFA? (5-tuple reminder) ▶
A DFA \(M = (Q, \Sigma, \delta, q_0, F)\) consists of:
Q — finite set of states  |  Σ — input alphabet (disjoint from Q)  |  δ: Q × Σ → Q — transition function  |  q₀ ∈ Q — start state  |  F ⊆ Q — accept states.
\[ \delta : Q \times \Sigma \to Q \]
1
Number the states
Assign each state in \(Q\) an index: \(q_1, q_2, \ldots, q_k\). State \(q_i\) encodes as \(I^i\) (i copies of I). The start state \(q_0\) is always encoded as \(I\) (i.e., \(I^1\)).
2
Number the alphabet symbols
Assign each symbol in \(\Sigma\) an index: \(a_1, a_2, \ldots\). Symbol \(a_j\) encodes as \(I^j\).
3
Encode each transition
Each transition \(\delta(q_i, a_j) = q_k\) encodes as the triple \(I^i \; c \; I^j \; c \; I^k\). This triples uses c as an intra-transition separator.
4
Encode the accept states
List each accept state \(q_i \in F\) as \(I^i\), separated by \(c\).
5
Assemble the full encoding
\[ \langle M \rangle \;=\; \underbrace{I^{|Q|}}_{\text{\# states}} \;c\; \underbrace{I^{|\Sigma|}}_{\text{\# symbols}} \;c\; \underbrace{t_1 \; cc \; t_2 \; cc \; \cdots \; cc \; t_r}_{\text{transitions, separated by }cc} \;c\; \underbrace{I^{f_1} \; c \; I^{f_2} \; c \cdots}_{\text{accept states}} \]
Double \(cc\) separates distinct transitions; single \(c\) separates fields within one transition. This makes the encoding unambiguously parseable.
ComponentEncodingExample (2-state DFA over {0,1})
State \(q_i\)\(I^i\)\(q_1 = I,\; q_2 = II\)
Symbol \(a_j\)\(I^j\)\(0 = I,\; 1 = II\)
Transition \(\delta(q_i,a_j)=q_k\)\(I^i\,c\,I^j\,c\,I^k\)\(\delta(q_1,0)=q_2\) → \(IcIcII\)
Accept state \(q_f\)\(I^f\)\(F=\{q_2\}\) → \(II\)
Full machineall above joined by \(c\) / \(cc\)\(IIcIIcIcIcIIccIIcIIcIcIcIcII\)
✓ Encoding Scheme A DFA \(\langle M \rangle\) encodes as: (1) \(I^{|Q|}\) for state count, (2) \(I^{|\Sigma|}\) for alphabet size, (3) each transition \(\delta(q_i, a_j)=q_k\) as \(I^i c I^j c I^k\) with transitions separated by \(cc\), and (4) accept states listed as \(I^{f_1} c I^{f_2} \cdots\). All major sections separated by single \(c\).
Part B — Applications
1
Universal Acceptance / Simulation
A universal Turing machine can take \(\langle M \rangle\) as input and simulate \(M\) on any string \(w\). This is the basis of software itself — one machine interpreting another.
2
Decision Problems about DFAs
With a concrete encoding, we can now ask decision questions about DFAs as inputs. Examples: \(A_{\text{DFA}} = \{\langle M, w\rangle \mid M \text{ accepts } w\}\) (decidable), \(E_{\text{DFA}} = \{\langle M\rangle \mid L(M) = \emptyset\}\) (decidable), \(EQ_{\text{DFA}} = \{\langle M_1, M_2\rangle \mid L(M_1)=L(M_2)\}\) (decidable).
3
Undecidability Proofs via Reduction
Encoding FAs lets us reduce FA problems to TM problems (or vice versa). This is how we prove certain problems about more powerful models are undecidable by showing they subsume FA problems.
4
Serialization / Transmission
An encoded DFA can be stored, transmitted over a network, or embedded in a formal proof — enabling compiler specification, protocol verification, and regex exchange formats.
Concept
[SIPSER 3.1] TM ENCODING UNARY REPRESENTATION
▶

Why {c, I}? Any finite object can be encoded over a 2-symbol alphabet. Sipser uses \(\{0,1\}\) in the book; this problem uses \(\{c, I\}\) — same idea. The symbol c acts as a structural separator (comma-like), and I is the counting stroke. This mirrors how TMs are encoded in Sipser §3.1.

Exam tip: When encoding a machine, always specify how to unambiguously recover the original 5-tuple from the string. The choice of separator characters and their meaning must be explicit.

Church–Turing Thesis
COMPUTABILITY THEORY · INFORMAL VS FORMAL ALGORITHMS · 2–4 SENTENCES
▶
Problem
Explain the Church–Turing Thesis in 2–4 sentences, addressing: what two types of concepts it connects, and why it is not formally provable.
—
Give a precise 2–4 sentence answer covering both bullets.
Solution — Church–Turing Thesis
Key Insight
informal ↔ formal not a theorem philosophical claim
▶
\[ \text{Intuitive notion of algorithm} \;\;\equiv\;\; \text{Turing machine computation} \]
The ≡ here is a thesis (philosophical equivalence), not a mathematical theorem. It cannot be proven because the left side has no formal definition.
Historical context — Church and Turing ▶
Alonzo Church (1936) defined computability via the lambda calculus. Alan Turing (1936) independently defined it via Turing machines. Both formalisms turned out to compute exactly the same class of functions — strong evidence the thesis is correct, but not a proof.
1
What two types of concepts does it connect?
The thesis connects informal, intuitive notions of algorithm (the everyday idea of "a mechanical procedure a human could follow step by step") with formal mathematical models of computation (specifically, Turing machines). It asserts that anything computable by any reasonable, effective procedure can also be computed by a Turing machine.
2
Why is it not formally provable?
Because one side of the equivalence — "intuitive algorithm" — is an informal, undefined concept. Mathematical proof requires both sides to have precise, formal definitions. We cannot write a proof that pins down "what a human considers an algorithm" since that notion lives outside mathematics. The thesis is therefore an empirical/philosophical claim, supported by the fact that every known formalism (lambda calculus, recursive functions, RAM machines, etc.) computes exactly what Turing machines compute.
✓ Model Answer (≤4 sentences) The Church–Turing Thesis connects the informal, intuitive notion of algorithm (any effective, step-by-step mechanical procedure) with the formal model of Turing machine computation, asserting they are equivalent in power. It is not formally provable because one side of the equivalence — the informal notion of "algorithm" — lacks a precise mathematical definition, making a rigorous proof impossible. Instead, the thesis is supported empirically: every known formal model of computation (lambda calculus, recursive functions, RAM machines) has been shown to be equivalent in power to Turing machines, providing strong but not conclusive evidence.
Concept
[SIPSER 3.3] CHURCH–TURING THESIS EFFECTIVE COMPUTABILITY
▶

Church–Turing Thesis (Sipser §3.3): Every effectively computable function is computable by a Turing machine. This is a thesis — a definition of scope — not a theorem.

Exam tip: The two concepts are always (1) informal/intuitive algorithms and (2) formal Turing machine computation. Unprovability comes from the informal side being undefined. Students who say "we can't build a physical TM" or "computation is infinite" are wrong — the reason is specifically the lack of formal definition on the intuitive side.

Perfect Squares via NTM
NONDETERMINISTIC TM · HIGH-LEVEL DESCRIPTION · L = {Iⁿ | n is a perfect square}
▶
Problem
Let \(L = \{I^n \mid n \text{ is a perfect square}\}\). Give a high-level description of a nondeterministic Turing machine that accepts \(L\), clearly explaining where nondeterminism is used.
—
Describe an NTM accepting \(L\), including explicit use of nondeterminism.
Solution — NTM for Perfect Squares
Key Insight
n = k² guess k nondeterministically verify k² = n deterministically
▶
\[ n \text{ is a perfect square} \iff \exists\, k \in \mathbb{N} \text{ s.t. } k^2 = n \]
Nondeterminism is perfect for existential witnesses: guess \(k\), then verify \(k^2 = n\) deterministically.
How does a NTM differ from a DTM? ▶
A Nondeterministic TM (NTM) may have multiple possible transitions from any configuration. It accepts an input if any branch of the computation tree reaches an accept state. Conceptually: it can "guess" and then verify. An NTM accepts \(w\) iff there exists at least one accepting computation path.
1
Input
The tape initially contains \(I^n\) — a string of \(n\) strokes representing the number \(n\) in unary. If the input is empty (\(n=0\)), accept (since \(0 = 0^2\)).
2
Nondeterministically guess k
This is where nondeterminism is used. The NTM nondeterministically writes a unary number \(I^k\) on a second track (or in a separate tape region), for some \(k \geq 1\). All values of \(k\) are explored simultaneously along different branches of the computation tree. The machine does not deterministically try each \(k\) — it guesses one per branch.
3
Compute k² deterministically
On the branch that guessed \(k\), the machine deterministically computes \(k^2\) in unary. This can be done by repeated addition: add \(k\) to a running total \(k\) times. After \(k\) iterations, the counter holds \(I^{k^2}\).
\[ \underbrace{k + k + \cdots + k}_{k \text{ times}} \;=\; k^2 \]
4
Compare k² to n
The machine compares the computed value \(I^{k^2}\) to the input \(I^n\) by crossing off symbols one-to-one. If they match exactly, accept. If \(k^2 \neq n\), reject on this branch.
5
Acceptance condition
The NTM accepts \(I^n\) if and only if at least one branch — i.e., the branch that guessed \(k = \sqrt{n}\) — reaches accept. Since the NTM explores all \(k\) simultaneously, it accepts exactly when \(n\) is a perfect square.
✓ High-Level NTM Description On input \(I^n\): (1) If \(n=0\), accept. (2) Nondeterministically write some \(I^k\) (\(k \geq 1\)) to the work tape — this is the guess. (3) Deterministically compute \(k^2\) by adding \(k\) to itself \(k\) times in unary. (4) Compare \(I^{k^2}\) to the input \(I^n\); if equal, accept; else reject. The machine accepts iff some branch's guess \(k\) satisfies \(k^2 = n\), i.e., \(n\) is a perfect square.
Nondeterminism used at step 2: The NTM nondeterministically chooses the witness \(k\). This avoids needing to deterministically enumerate all possible \(k\) — the NTM explores them all in parallel via nondeterministic branching.
Concept
[SIPSER 3.2] NONDETERMINISTIC TM GUESS-AND-VERIFY PATTERN
▶

Nondeterministic TM (Sipser §3.2): An NTM accepts its input if any branch of its computation tree reaches an accepting state. For problems of the form "does there exist a \(k\) such that P(k)?", nondeterminism lets you guess \(k\) and verify in one shot.

Exam tip: Always be explicit about where the nondeterminism occurs. The standard pattern is: (1) nondeterministically guess a witness, (2) deterministically verify the witness. Saying "the NTM tries all values of k" without saying "nondeterministically" loses points.

ALL_TM is Undecidable
UNDECIDABILITY · REDUCTION FROM ATM · TURING ACCEPTABILITY
▶
Problem
Prove that \(ALL_{TM} = \{\langle M \rangle \mid L(M) = \Sigma^*\}\) is Turing undecidable. Is it Turing acceptable? Prove or disprove.
a
Prove \(ALL_{TM}\) is undecidable.
b
Determine whether \(ALL_{TM}\) is Turing-acceptable (recognizable).
Part A — Undecidability via Reduction
Key Insight
reduce from A_TM mapping reduction iff correspondence
▶
\[ A_{TM} \leq_m ALL_{TM} \]
We show: if \(ALL_{TM}\) were decidable, then \(A_{TM}\) would be decidable — contradiction since \(A_{TM}\) is undecidable (Sipser Thm 4.11).
A_TM undecidability (Sipser Thm 4.11) ▶
\(A_{TM} = \{\langle M, w\rangle \mid M \text{ is a TM that accepts } w\}\) is undecidable (proved by diagonalization). It is, however, Turing-recognizable (the universal TM accepts it). We use its undecidability as the starting point for reductions.
1
Assume for contradiction
Suppose \(ALL_{TM}\) is decidable. Let \(H\) be a decider for \(ALL_{TM}\).
2
Construct the reduction machine
On input \(\langle M, w \rangle\), construct a new TM \(M'\) defined as follows:
\[ M' \text{ on input } x: \text{ ignore } x, \text{ simulate } M \text{ on } w; \text{ if } M \text{ accepts, accept; else reject.} \]
So \(M'\) accepts every string if \(M\) accepts \(w\), and rejects every string if \(M\) does not accept \(w\).
3
Establish the iff
\(M\) accepts \(w\) \(\iff\) \(L(M') = \Sigma^*\) \(\iff\) \(H\) accepts \(\langle M' \rangle\).
Therefore: run \(H\) on \(\langle M' \rangle\) to decide whether \(M\) accepts \(w\), i.e., to decide \(A_{TM}\).
4
Contradiction
This contradicts the undecidability of \(A_{TM}\). Therefore \(ALL_{TM}\) is not decidable. \(\square\)
✓ Conclusion — Part A \(ALL_{TM}\) is Turing undecidable. Proof by mapping reduction: \(A_{TM} \leq_m ALL_{TM}\). Given any \(\langle M, w\rangle\), construct \(M'\) that ignores its input and simulates \(M\) on \(w\); then \(L(M')=\Sigma^* \iff M\) accepts \(w\). A decider for \(ALL_{TM}\) would therefore decide \(A_{TM}\), contradiction.
Part B — Is ALL_TM Turing Recognizable?
Key Insight
co-recognizable complement argument Sipser Cor 4.23
▶
\[ L \text{ decidable} \iff L \text{ recognizable AND } \overline{L} \text{ recognizable} \]
Equivalently: if \(L\) is recognizable but not decidable, then \(\overline{L}\) is NOT recognizable (Sipser Corollary 4.23).
1
Claim: ALL_TM is NOT Turing-recognizable
We prove this by showing its complement \(\overline{ALL_{TM}}\) is Turing-recognizable, and then applying the corollary above.
2
Show complement(ALL_TM) is recognizable
\(\overline{ALL_{TM}} = \{\langle M\rangle \mid L(M) \neq \Sigma^*\}\), meaning there exists some string \(x\) that \(M\) does NOT accept.

Build a recognizer \(R\) for \(\overline{ALL_{TM}}\): on input \(\langle M\rangle\), enumerate all strings \(x_1, x_2, x_3, \ldots\) over \(\Sigma^*\) in a dovetailing fashion, simultaneously simulating \(M\) on each \(x_i\). If \(M\) rejects any \(x_i\) (or loops without accepting), accept. This recognizer halts and accepts whenever \(L(M) \neq \Sigma^*\), so \(\overline{ALL_{TM}}\) is Turing-recognizable.
3
Apply the corollary
We know \(ALL_{TM}\) is undecidable (Part A). If \(ALL_{TM}\) were also recognizable, then since \(\overline{ALL_{TM}}\) is recognizable, Sipser Corollary 4.23 would imply \(ALL_{TM}\) is decidable — contradiction. Therefore \(ALL_{TM}\) is not Turing-recognizable.
✓ Conclusion — Part B \(ALL_{TM}\) is NOT Turing-recognizable. Its complement \(\overline{ALL_{TM}}\) is recognizable (dovetail-simulate \(M\) on all strings; accept when any is rejected). Since \(ALL_{TM}\) is undecidable but \(\overline{ALL_{TM}}\) is recognizable, Sipser Cor. 4.23 forces \(ALL_{TM}\) to be non-recognizable.
A language can be: (1) decidable, (2) recognizable but not decidable, or (3) neither recognizable nor co-recognizable. \(ALL_{TM}\) falls in category 3 — it is not recognizable, and its complement IS recognizable (co-recognizable).
Concept
[SIPSER 4.2] MAPPING REDUCTION [SIPSER 4.23] DECIDABLE IFF REC + CO-REC
▶

Mapping Reduction \(A \leq_m B\): A computable function \(f\) such that \(w \in A \iff f(w) \in B\). If \(B\) is decidable, so is \(A\). Contrapositive: if \(A\) is undecidable, so is \(B\).

Corollary 4.23 (Sipser): A language is decidable iff it is Turing-recognizable AND its complement is Turing-recognizable. This is the main tool for proving languages are non-recognizable without direct diagonalization.

Exam tip: To prove a language is not recognizable, show its complement IS recognizable, then cite Cor. 4.23 + undecidability.

Closure of Turing-Recognizable Languages
CLOSURE PROPERTIES · UNION · INTERSECTION · COMPLEMENT
▶
Problem
Prove that the class of Turing-recognizable (T-acceptable) languages is closed under Union and Intersection. Are they closed under complement? Justify carefully.
a
Prove closure under Union.
b
Prove closure under Intersection.
c
Are Turing-recognizable languages closed under complement? Justify.
Part A — Closure Under Union
Key Insight
dovetailing parallel simulation
▶
\[ L_1, L_2 \text{ recognizable} \implies L_1 \cup L_2 \text{ recognizable} \]
Why not just run M₁ then M₂? If M₁ loops on input, we'd never reach M₂. We must dovetail (interleave) the simulations.
1
Setup
Let \(M_1\) recognize \(L_1\) and \(M_2\) recognize \(L_2\). We construct TM \(M\) that recognizes \(L_1 \cup L_2\).
2
Construct M — dovetail simulation
\(M\) on input \(w\): Simulate both \(M_1\) and \(M_2\) on \(w\) in parallel (dovetailing). On step \(i\), simulate \(i\) steps of \(M_1\) and \(i\) steps of \(M_2\). If either machine accepts, accept.
\[ \text{For } i = 1, 2, 3, \ldots : \text{ run } i \text{ steps of } M_1 \text{ on } w;\; \text{run } i \text{ steps of } M_2 \text{ on } w \]
3
Correctness
If \(w \in L_1 \cup L_2\): then \(w \in L_1\) or \(w \in L_2\). Say \(M_1\) accepts \(w\) in \(k\) steps. Then at round \(k\), \(M\) will see \(M_1\) accept and halt-accept. So \(M\) accepts.
If \(w \notin L_1 \cup L_2\): Both \(M_1\) and \(M_2\) will not accept on \(w\). \(M\) never accepts, and may loop — which is fine for a recognizer.
✓ Conclusion — Part A The class of Turing-recognizable languages is closed under union. Given recognizers \(M_1\) for \(L_1\) and \(M_2\) for \(L_2\), construct \(M\) that dovetails simulation of both. \(M\) accepts \(w\) iff \(M_1\) or \(M_2\) accepts \(w\), recognizing \(L_1 \cup L_2\). \(\square\)
Part B — Closure Under Intersection
Key Insight
both must accept sequential works here why?
▶
\[ L_1, L_2 \text{ recognizable} \implies L_1 \cap L_2 \text{ recognizable} \]
For intersection we need both to accept. Running sequentially is dangerous if either loops. We still dovetail — but we accept only when both accept.
1
Construct M — dovetail, accept when both accept
\(M\) on input \(w\): Dovetail-simulate \(M_1\) and \(M_2\) on \(w\). Track whether each has accepted. Accept only when both \(M_1\) and \(M_2\) have accepted.
2
Alternative: run sequentially (careful!)
A simpler construction: run \(M_1\) on \(w\). If \(M_1\) rejects, reject. If \(M_1\) accepts, then run \(M_2\) on \(w\). Accept iff \(M_2\) accepts. This works for recognizers: if \(w \notin L_1\), \(M_1\) might loop — and that's fine, because \(M\) should also loop (not accept) on \(w \notin L_1 \cap L_2\). The recognizer only needs to accept exactly \(L_1 \cap L_2\).
3
Correctness
If \(w \in L_1 \cap L_2\): Both \(M_1\) and \(M_2\) accept \(w\). The dovetail eventually sees both accept → \(M\) accepts.
If \(w \notin L_1 \cap L_2\): At least one of \(M_1, M_2\) does not accept \(w\), so \(M\) never reaches the accept condition → \(M\) loops or rejects. Correct for a recognizer.
✓ Conclusion — Part B The class of Turing-recognizable languages is closed under intersection. Construct \(M\) that dovetails \(M_1\) and \(M_2\) on input \(w\), accepting iff both accept. Then \(L(M) = L_1 \cap L_2\). \(\square\)
Part C — Not Closed Under Complement
Key Insight
A_TM counterexample co-A_TM not recognizable
▶
\[ A_{TM} \text{ is recognizable, but } \overline{A_{TM}} \text{ is NOT recognizable} \]
One counterexample is enough to disprove a closure property.
1
Claim: NOT closed under complement
We exhibit a language that is Turing-recognizable whose complement is NOT Turing-recognizable.
2
Counterexample: A_TM
\(A_{TM} = \{\langle M, w\rangle \mid M \text{ accepts } w\}\) is Turing-recognizable: the universal TM \(U\) recognizes it by simulating \(M\) on \(w\) and accepting if \(M\) does.
3
Complement is not recognizable
\(\overline{A_{TM}}\) is NOT Turing-recognizable. Proof: \(A_{TM}\) is undecidable. If \(\overline{A_{TM}}\) were recognizable, then since \(A_{TM}\) is recognizable, Sipser Corollary 4.23 would give \(A_{TM}\) decidable — contradiction. \(\square\)
✓ Conclusion — Part C The class of Turing-recognizable languages is NOT closed under complement. Counterexample: \(A_{TM}\) is recognizable (universal TM), but \(\overline{A_{TM}}\) is not recognizable (if it were, \(A_{TM}\) would be decidable, contradicting Sipser Thm 4.11).
Summary of closure for Turing-recognizable languages: Closed under Union ✓ — Closed under Intersection ✓ — Closed under Complement ✗ — Closed under Concatenation ✓ — Closed under Kleene Star ✓.
Concept
[SIPSER 3.2] DOVETAILING [SIPSER 4.23] COMPLEMENT + DECIDABILITY
▶

Dovetailing: A technique to interleave computation on multiple TMs (or multiple inputs) so no single simulation can "hog" the machine and loop forever. Crucial for recognizability proofs.

Sipser Corollary 4.23: A language is decidable iff both it and its complement are Turing-recognizable. This implies: if \(L\) is recognizable but undecidable, \(\overline{L}\) cannot be recognizable.

Exam tip: For closure proofs, always construct the new TM explicitly. For non-closure, always give a concrete counterexample — don't just say "it fails in general."
