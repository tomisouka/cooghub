Q1 Regular Expressions — Description & Construction
Regular Expressions
▶
Key Definitions
Regular Expression A formal notation describing a set of strings using union (∪), concatenation, and Kleene star (*). Every regular expression describes a regular language.
Kleene Star (R*) Zero or more concatenations of strings matched by R. R* always includes the empty string ε.
Union (R ∪ S) Matches any string matched by R or by S.
Substring String v is a substring of w if w = xvy for some (possibly empty) x, y.
Part (a) — Describe (ab ∪ b)* in English
Describe the language generated by (ab ∪ b)* over Σ = {a, b}.
✏️
Show Your Work
Breaking down what (ab ∪ b)* generates
▶
1
Identify what the star operates on

The expression is (ab ∪ b)*. The Kleene star wraps (ab ∪ b), meaning we repeat that group zero or more times. Each repetition independently picks either "ab" or "b" — those are the only two building blocks available.

2
Ask: how can 'a' appear in any string?

The only block that produces an 'a' is "ab". The block "b" produces only a 'b'. So every 'a' in the output must come from choosing the "ab" block — which always brings a 'b' directly after it.

Conclusion: every 'a' in the string is immediately followed by a 'b'. There is no way to produce a lone 'a'.

3
Ask: can 'a' appear at the end of the string?

No — "ab" always contributes 'a' then 'b', so 'a' is never the final character. The block "b" contributes no 'a' at all. Therefore 'a' can never be the last symbol.

4
Verify with concrete examples
ε → zero repetitions ✓ b → one "b" block ✓ ab → one "ab" block ✓ bb → "b" then "b" ✓ bab → "b" then "ab" ✓ abbb → "ab" then "b" then "b" ✓ — a → impossible (no block gives lone 'a') ✗ ba → impossible ('a' must follow a 'b' in "ab", not precede it freely) ✗
✓ Reasoning confirmed

All strings over {a, b} where every 'a' is immediately followed by a 'b'. Equivalently: strings built by freely concatenating the blocks "ab" and "b" any number of times (including zero). No 'a' can appear at the end or without a 'b' directly after it.

Examples in the language: ε, b, ab, bb, bab, abab, babb, abbb

Part (b) — Write a Regex for "no substring bb"
Write a regular expression for L = {w ∈ {a,b}* | w does not contain bb as a substring}. Justify your answer.
✏️
Show Your Work
Building the regex with two-condition decomposition
▶
1
Understand the constraint

The condition is: the string must never contain "bb" as a consecutive pair anywhere. So wherever a 'b' appears in the interior of the string, the very next character cannot also be 'b'.

In other words: every 'b' that has something after it must be immediately followed by 'a'.

2
Identify the safe repeating blocks

From step 1, the interior of the string can only be built from two safe pieces:

"a" — a lone a (contributes no b at all, always safe) "ba" — a b immediately followed by a (the b is "covered")

Repeating any mix of these gives (a | ba)*. No matter what sequence we choose, no two b's will ever be adjacent inside this part.

3
Handle the trailing edge case

What if the string ends in 'b'? A final 'b' has nothing after it, so it can't form "bb" by itself. We need to allow it optionally without breaking anything.

Append (b | ε) to the end. This allows either a trailing 'b' or nothing. Since every 'b' inside (a|ba)* is already followed by 'a', the trailing 'b' is the only one that could ever be last — and it has no successor, so "bb" is impossible.

4
Combine the parts

Putting it together:

(a | ba)* · (b | ε)

The star handles any sequence of safe interior blocks. The optional trailing 'b' covers strings ending in 'b'.

5
Test on examples to verify
ε → (a|ba)⁰ · ε = ε ✓ in L a → (a)¹ · ε = "a" ✓ in L b → (a|ba)⁰ · b = "b" ✓ in L ba → (ba)¹ · ε = "ba" ✓ in L bab → (ba)(a|ba)⁰·b = "ba"+"b" ✓ in L aba → (a)(ba)·ε = "a"+"ba" ✓ in L — bb → need two consecutive b's → impossible from our blocks ✗ not in L abb → "a" then "b" then "b"? The second 'b' can only come from the trailing (b|ε) — but "b"+"b" at the end would require TWO trailing b's, which is not allowed. ✗ not in L
✓ All cases check out
(a | ba)*(b | ε)

Justification: Every 'b' inside (a|ba)* is immediately followed by 'a', so "bb" cannot form in the interior. The optional trailing 'b' ends the string, making it impossible for that 'b' to be followed by another 'b'. Together these two facts guarantee "bb" never appears anywhere in the string.

In L: ε ✓   a ✓   b ✓   ba ✓   ab ✓   aba ✓   bab ✓   abab ✓

Not in L: bb ✗   abb ✗   bba ✗   abba ✗

Q2 Pumping Lemma — Prove L = {aⁿb²ⁿ | n ≥ 0} is not regular
Pumping Lemma
▶
Key Definitions
Pumping Lemma If L is regular, ∃ pumping length p such that every w ∈ L with |w| ≥ p can be split as w = xyz where: (i) |xy| ≤ p, (ii) |y| ≥ 1, (iii) xyⁱz ∈ L for all i ≥ 0.
Proof Strategy Assume regular → get pumping length p → choose a concrete string w ∈ L with |w| ≥ p → show that for every valid split w = xyz, some pumped string xyⁱz ∉ L → contradiction.
Pump down (i = 0) Remove y entirely: xy⁰z = xz. Best when the language enforces a strict ratio between symbol counts — removing symbols breaks the ratio.
Conditions (i)(ii)(iii) (i) |xy| ≤ p — the pumped part stays near the front. (ii) |y| ≥ 1 — y is non-empty. (iii) xyⁱz ∈ L for all i ≥ 0 — pumping in either direction must stay in L.
Use the Pumping Lemma to prove that L = {aⁿb²ⁿ | n ≥ 0} is not regular. Clearly identify your assumption, string choice, split analysis, and contradiction.
✏️
Show Your Work
4-step pumping lemma proof — assumption → string → split → contradiction
▶
1
Assume for contradiction

Assume L = {aⁿb²ⁿ | n ≥ 0} is regular. Since L is infinite, the Pumping Lemma applies. Let p be the pumping length it guarantees.

Our goal is to derive a contradiction by finding a string in L that cannot be pumped.

2
Choose the right string

Pick w = aᵖb²ᵖ. We need to verify it satisfies the conditions:

w = aᵖb²ᵖ ∈ L (with n = p, so #b's = 2p = 2×#a's ✓) |w| = p + 2p = 3p ≥ p ✓

Why this string? Starting the string with p a's means the constraint |xy| ≤ p forces xy to land entirely in that a-only prefix. This locks in exactly what y can look like — making the contradiction clean and arithmetic.

3
Analyze every possible split w = xyz

The Pumping Lemma says there exists some split w = xyz satisfying (i) and (ii). We need to show that no matter how the split is chosen, condition (iii) fails.

By condition (i), |xy| ≤ p. Since the first p characters of w are all a's, the entire xy prefix is a-only. So:

x = aʲ (for some j ≥ 0) y = aᵐ (for some m ≥ 1, by condition ii) z = aᵖ⁻ʲ⁻ᵐb²ᵖ where j + m ≤ p

There is no other possibility — y cannot contain any b's, because xy only reaches as far as position p into the string, and all those positions are a's.

✓ y consists only of a's in every valid split
4
Pump down (i = 0) to get the contradiction

By condition (iii), xy⁰z must be in L. Compute it:

xy⁰z = xz = aʲ · aᵖ⁻ʲ⁻ᵐ · b²ᵖ = aᵖ⁻ᵐb²ᵖ

For aᵖ⁻ᵐb²ᵖ to be in L = {aⁿb²ⁿ}, we need:

2 × (# of a's) = # of b's 2(p − m) = 2p 2p − 2m = 2p −2m = 0 m = 0

But condition (ii) requires m = |y| ≥ 1. This is a direct contradiction. ✗

✗ xy⁰z ∉ L — condition (iii) is violated
5
Close the proof

We chose w ∈ L with |w| ≥ p, but showed that for every valid split w = xyz, the pumped string xy⁰z falls outside L. This directly contradicts the Pumping Lemma's guarantee that xy⁰z ∈ L must hold.

Our assumption that L is regular must therefore be false.

For any valid split w = aᵖb²ᵖ = xyz (where y = aᵐ, m ≥ 1), pumping down gives xz = aᵖ⁻ᵐb²ᵖ ∉ L because 2(p−m) ≠ 2p. This violates condition (iii), contradicting the Pumping Lemma. Therefore L = {aⁿb²ⁿ | n ≥ 0} is not regular.

□
String choice tip: always pick w so that the |xy| ≤ p constraint forces xy into a single uniform block (all a's here). This eliminates ambiguity in what y can be, making the contradiction a simple arithmetic equation.
Lecture Cross-Reference — Related Pumping Lemma Problems

L = {aᵖ | p is prime} (Lecture Ex. 01): pump up with i = q+1. Result: a^(q(1+m)) — composite since m ≥ 1, so ∉ L. Direction matters here: pumping down keeps the count a valid multiple.

L = {aⁿba²ⁿ | n ≥ 0} (Lecture Ex. 02): identical technique. Pump down: xz = aᵖ⁻ᵐba²ᵖ. The left block has p−m a's but the right still has 2p, breaking the 1:2 ratio.

L = {(010)ⁿ(101)ⁿ | n ≥ 0} (Lecture Ex. 03): pump up (i = 2). y falls inside the 010 pattern; doubling it disrupts the repeating structure so the pumped string leaves L.

Q3 DFA Design + Regular Expression Conversion
DFA Design State Elimination → Regex
▶
Key Definitions
DFA Deterministic Finite Automaton: M = (Q, Σ, δ, q₀, F). For every state and input symbol, exactly one transition exists. Accepts w if δ*(q₀, w) ∈ F.
Trap / Dead State A non-accepting state with all transitions looping back to itself. Once entered, acceptance is impossible. Safe to discard during state elimination.
GNFA Generalized NFA: edge labels are full regular expressions (not just single symbols). The DFA→regex conversion works by converting to GNFA then eliminating states one by one.
State Elimination Remove an intermediate state q by rerouting every (pred → q → succ) path as a direct edge labeled pred_label · q_self_loop* · succ_label, unioned with any existing pred → succ edge.
Design a DFA for L = {w ∈ {0,1}* | every 0 in w is immediately followed by at least one 1}. Then convert your DFA to a regular expression.
Part (a) — DFA Design
✏️
Show Your Work
Figuring out what states the DFA needs and why
▶
1
Ask: what does the DFA need to remember?

A DFA can only remember information through its current state. The condition is: "every 0 is immediately followed by at least one 1." The only dangerous moment is right after reading a '0' — we must verify the very next character is '1'.

So the DFA needs to track one thing: did we just see a '0' that hasn't been followed by a '1' yet? Three situations cover all cases:

q_ok — no pending 0 (safe, accept if string ends here) q_need1 — just saw a 0, must see 1 next (reject if string ends) q_dead — saw 0 then another 0 — condition violated, no recovery
2
Fill in transitions for q_ok (start state)

In q_ok, we're in a safe state with no pending '0'. What happens next?

q_ok on '1' → q_ok (reading 1 when safe stays safe) q_ok on '0' → q_need1 (now we have a pending 0 that needs a 1)

q_ok is the start state because at the beginning we have no pending 0. It is also an accept state because if the string ends here, every 0 we saw was already followed by a 1.

3
Fill in transitions for q_need1

In q_need1 we just read a '0' and are waiting for a '1' to satisfy it.

q_need1 on '1' → q_ok (the 1 satisfies the pending 0 — safe again) q_need1 on '0' → q_dead (0 followed by another 0 — condition violated)

q_need1 is not an accept state: if the string ends here, the last character was a '0' with nothing following it — that directly violates the condition.

4
Fill in transitions for q_dead (trap state)

In q_dead, we have already seen a '0' followed by another '0'. The condition is permanently violated — no future input can fix it.

q_dead on '0' → q_dead (stay trapped) q_dead on '1' → q_dead (stay trapped — too late)

q_dead is a trap / dead state: non-accepting, all transitions loop back to itself.

5
Verify with test strings

Part (b) — Convert DFA → Regular Expression via GNFA State Elimination
✏️
Show Your Work
4-step GNFA construction and state elimination
▶
1
Convert DFA → GNFA (add q_start and q_accept)

A GNFA requires: (1) a unique start state with no incoming edges, and (2) a unique accept state with no outgoing edges. Our DFA's q_ok has incoming edges (self-loop on 1), so we can't use it directly as the GNFA start.

Add two new states and ε-transitions:

q_start →ε→ q_ok (new start, no incoming edges) q_ok →ε→ q_accept (new accept, q_ok was the only old accept state)

The GNFA now has 5 states: q_start, q_ok, q_need1, q_dead, q_accept. We will eliminate the 3 middle states one by one until only q_start and q_accept remain, connected by a single regex edge — that edge is the answer.

2
Eliminate q_dead (trap state — easiest first)

To eliminate a state, we must reroute every path that passes through it into direct edges. The elimination formula for removing state q is:

For each pair (pred, succ): new edge label = (pred→q label) · (q self-loop)* · (q→succ label) ∪ (existing pred→succ label)

q_dead has a self-loop on {0,1} but no outgoing edge to q_accept. Every path through q_dead is a dead end — there is no (q_dead → q_accept) edge to reroute. So we simply drop q_dead entirely with no new edges needed.

✓ q_dead removed — GNFA now has 4 states
3
Eliminate q_need1

q_need1 has no self-loop. The only path through it is:

q_ok →0→ q_need1 →1→ q_ok

Apply the elimination formula with pred = q_ok, q = q_need1, succ = q_ok:

new edge label = (0) · (ε)* · (1) = 01

This becomes an additional self-loop on q_ok. q_ok already has a self-loop labeled 1. We union the two labels:

q_ok self-loop: 1 ∪ 01 = (1 | 01)
✓ q_need1 removed — GNFA now has 3 states: q_start, q_ok, q_accept
4
Eliminate q_ok

The remaining 3-state GNFA looks like:

q_start →ε→ q_ok →ε→ q_accept ↑_______(1|01)________| (self-loop)

Apply the elimination formula with pred = q_start, q = q_ok, succ = q_accept:

new edge label = (ε) · (1 | 01)* · (ε) = (1 | 01)*

Now q_start connects directly to q_accept with label (1 | 01)*. Only these two states remain.

✓ q_ok removed — only q_start and q_accept remain
5
Read off the final regex and verify

The label on the single remaining edge is the regular expression for L:

(1 | 01)*

Intuition check: every iteration of the star contributes either a lone '1' or the pair "01". In either case, every '0' is immediately followed by a '1'. So the regex exactly captures the language.

Accepted: ε, 1, 01, 11, 011, 101, 0101, 1011 ✓ Rejected: 0, 10, 00, 001 ✗
Part (a) — DFA with 3 states: q_ok (start + accept), q_need1 (reject), q_dead (trap).

Part (b) — After GNFA state elimination:
(1 | 01)*

Every '0' is immediately followed by '1' because "01" is the only block in the star that contains a '0', and it always pairs it with a '1' right after.

Q4 NFA for "contains aba AND no bbb" → DFA Conversion
NFA Subset Construction
▶
Key Definitions
NFA Nondeterministic Finite Automaton: allows multiple transitions per symbol and ε-transitions. Accepts if any computation path reaches an accept state.
ε-closure(S) The set of all NFA states reachable from any state in S using only ε-transitions (including S itself). Must be computed before/after each symbol transition in subset construction.
Subset Construction Converts NFA → equivalent DFA. DFA states are subsets of NFA states. Start state = ε-closure({q₀}). δ_DFA(S, c) = ε-closure(⋃_{q∈S} δ_NFA(q, c)).
DFA Accept States In the subset construction, a DFA state (set S) is accepting iff S contains at least one NFA accepting state.
(a) Construct an NFA for L = {w ∈ {a,b}* | w contains "aba" as a substring AND contains no "bbb" as a substring}.
(b) Convert your NFA to an equivalent DFA via subset construction.
Part (a) — NFA Design
✏️
Show Your Work
Designing NFA states to track two constraints at once
▶
1
Identify the two things to track simultaneously

The language has two independent constraints:

Constraint 1: string MUST contain "aba" as a substring Constraint 2: string must NOT contain "bbb" as a substring

States need to encode both how far along we are in matching "aba" and how many consecutive b's we've seen. The NFA uses nondeterminism to let both concerns run in parallel — when we see 'a', one branch restarts while another commits to tracking a new "aba" attempt.

2
Design states before "aba" is matched

We need states for every combination of (b-run length) × (aba-matching progress):

s — start: 0 b-run, no aba progress s_b1 — 1 consecutive b, no aba progress s_b2 — 2 consecutive b's, no aba progress p1 — matched 'a' (first char of "aba") p2 — matched "ab" dead — saw "bbb" → trap state, reject forever
3
Design states after "aba" is matched

Once "aba" is matched, we only still need to track b-runs to avoid "bbb". All three are accept states:

acc — "aba" matched, 0 b-run ← ACCEPT acc_b1 — "aba" matched, 1 consecutive b ← ACCEPT acc_b2 — "aba" matched, 2 consecutive b's ← ACCEPT

Reading 'a' from any acc state resets the b-run back to acc (matching "aba" once is permanent). A third consecutive 'b' goes to dead.

4
The key tricky transition: p2 on 'a'

In state p2 (matched "ab"), reading 'a' completes "aba". But the NFA also nondeterministically considers that this same 'a' could be the start of a new "aba" attempt, or a plain reset. So:

p2 on 'a' → {acc, s, p1} acc — completed "aba" ✓ s — reset, treat this 'a' as a fresh start p1 — this 'a' is also the first char of a new "aba" attempt

This three-way nondeterministic branch is the core of the NFA design.

5
The other tricky transition: p2 on 'b'

In state p2 (matched "ab"), reading 'b' breaks the "aba" attempt (we needed 'a', not 'b'). This 'b' starts a fresh b-run, so we go to s_b1:

p2 on 'b' → {s_b1} (1 b seen, back to tracking b-runs)

Note: this goes to s_b1, NOT s_b2. This single detail causes 3 extra DFA states in part (b) if you get it wrong.

Q5 Prove L/σ is Regular (Right Quotient / Closure Property)
Closure Properties DFA Construction
▶
Key Definitions
Right Quotient L/σ L/σ = {w | wσ ∈ L}. The set of strings that, when followed by σ, land in L.
Closure under L/σ Regular languages are closed under right quotient: if L is regular and σ ∈ Σ, then L/σ is also regular. Proven by modifying a DFA's accept states.
Extended Transition δ* δ*(q, w) is the state reached from q after reading string w. Key property: δ*(q, wσ) = δ(δ*(q, w), σ).
Prove that if L is any regular language over Σ and σ ∈ Σ, then L/σ = {w ∈ Σ* | wσ ∈ L} is also regular.
✏️
Show Your Work
Building the DFA for L/σ step by step
▶
1
Unpack what L/σ actually asks

The definition says L/σ = { w | wσ ∈ L }. Translate this into plain English: "w is in L/σ if and only if appending the single character σ to the end of w produces a string that was already in L."

Think of it as a look-ahead test: "if I were standing at the state I reach after reading w, and I took one more step on σ, would I land in an accept state?" If yes, w is in L/σ.

This is the key insight that tells us exactly which states need to become new accept states in the modified DFA.

2
Start from the DFA for L — name its parts

Since L is regular, fix a DFA M = (Q, Σ, δ, q₀, F) that recognizes L. Nothing about this DFA changes — we are going to re-use it entirely except for swapping out the accept set F.

Q = states (unchanged) Σ = alphabet (unchanged) δ = transition function (unchanged — every arrow stays) q₀ = start state (unchanged) F = original accept states (this is the only part we replace)

This is the economy of the proof: we pay zero cost in new states or new transitions. The entire structure of M is recycled.

3
Define the new accept set F′

From Step 1 we know: state q should accept in M′ iff "one more σ from q lands in F." So we define:

F′ = { q ∈ Q | δ(q, σ) ∈ F }

Go through every state q in Q, check where δ(q, σ) lands, and mark q as accepting in M′ if that destination is in F.

Concrete micro-example: Say M has states {s, t, u} with F = {u}, and δ(s, σ) = t, δ(t, σ) = u, δ(u, σ) = u. Then:

δ(s, σ) = t ∉ F → s ∉ F′ δ(t, σ) = u ∈ F → t ∈ F′ ← new accept state! δ(u, σ) = u ∈ F → u ∈ F′ ← still an accept state

Notice: the original accept state u stays in F′ (because δ(u, σ) ∈ F), and t gets promoted because "one more σ" takes it to u.

4
Write the biconditional chain — the formal proof core

Construct M′ = (Q, Σ, δ, q₀, F′). Now prove L(M′) = L/σ by showing membership in L(M′) is equivalent to membership in L/σ, one iff-step at a time:

w ∈ L(M′) ⟺ δ*(q₀, w) ∈ F′ [DFA acceptance in M′] ⟺ δ( δ*(q₀, w), σ ) ∈ F [definition of F′] ⟺ δ*(q₀, wσ) ∈ F [extended δ* property: δ*(q, wσ) = δ(δ*(q,w), σ)] ⟺ wσ ∈ L(M) = L [DFA acceptance in M] ⟺ w ∈ L/σ [definition of L/σ]

Each iff is a direct substitution of a definition. The critical link is line 3: the extended transition function property δ*(q, wσ) = δ(δ*(q, w), σ), which says "run w then do one step σ" is the same as "run wσ all at once."

✓ Both directions (⟹ and ⟸) hold since every step is a biconditional
5
Close the proof — M′ is a valid DFA, so L/σ is regular

M′ = (Q, Σ, δ, q₀, F′) is a DFA because:

• Q is finite (same finite set as M) • δ is total (same total function as M — no transitions were added or removed) • unique start state q₀ (unchanged) • F′ ⊆ Q (we only selected states already in Q)

Since M′ is a valid DFA and L(M′) = L/σ (proven in Step 4), L/σ is recognized by a DFA, and therefore L/σ is regular.

Common Exam Mistake to Avoid

Students sometimes try to construct a new NFA or add new states to handle "reading σ later." This is unnecessary and wrong — M′ uses the exact same Q and δ as M. The only change is the accept set. Do not touch the transitions.

Proof — Construct a DFA for L/σ

Since L is regular, there exists a DFA M = (Q, Σ, δ, q₀, F) with L(M) = L.

Construct M' = (Q, Σ, δ, q₀, F') with the same states and transitions, but new accept states:

F' = { q ∈ Q | δ(q, σ) ∈ F } (All states from which reading one more σ leads to an original accept state.)

Claim: L(M') = L/σ.

w ∈ L(M') ⟺ δ*(q₀, w) ∈ F' [by definition of DFA acceptance in M'] ⟺ δ(δ*(q₀, w), σ) ∈ F [by definition of F'] ⟺ δ*(q₀, wσ) ∈ F [by extended transition function] ⟺ wσ ∈ L(M) = L [DFA M accepts wσ] ⟺ w ∈ L/σ [by definition of L/σ]
Since M' is a valid DFA, L/σ = L(M') is regular.
The key trick: we don't change any transitions — we only change which states are accepting. A state q accepts in M' iff "one more σ from q" would have accepted in M.

Q6 Pumping Lemma Failure Case + Showing Regularity of a*b*
Pumping Lemma Regularity DFA
▶
Key Definitions
Pumping Lemma Direction The Pumping Lemma is a necessary condition for regularity, not sufficient. It can prove irregularity (by contradiction), but cannot prove regularity. Failing to find a contradiction proves nothing.
a*b* All strings of zero or more a's followed by zero or more b's. This is the canonical simple regular language where all a's precede all b's.
Closure under ∩ Regular languages are closed under intersection. This gives a powerful non-regularity proof technique: if L ∩ R is non-regular for some regular R, then L itself cannot be regular.
What goes wrong when using the Pumping Lemma on L = {w ∈ {a,b}* | w has no b before any a}? Show the language is actually regular.
✏️
Show Your Work — Part 1
Tracing exactly why the Pumping Lemma produces no contradiction
▶
1
Identify the language in plain terms

L = {w ∈ {a,b}* | w has no b before any a}. This means: every b must come after every a. No b is ever followed by an a. In other words, once you see a b, the string can only have more b's — never an a again.

That is precisely a*b*: any number of a's (possibly zero) followed by any number of b's (possibly zero). Examples in L: ε, a, b, aab, abb, aaabbb. Not in L: ba, abba, baa.

2
Set up the Pumping Lemma attempt — choose a string

Let p be the pumping length. We pick the "hardest-looking" string to try to break the lemma: s = aᵖbᵖ. It's in L (all a's before all b's) and |s| = 2p ≥ p. ✓

Now the Pumping Lemma guarantees we can write s = xyz such that:

(i) |xy| ≤ p (ii) |y| > 0 (iii) xyⁱz ∈ L for all i ≥ 0

Condition (i) says xy lies entirely within the first p characters of s = aᵖbᵖ. The first p characters are all a's. So xy is a block of a's, and therefore y = aᵏ for some 1 ≤ k ≤ p.

3
Try every pumping value — none break the language

With y = aᵏ, pumping produces:

i = 0 (pump down): xy⁰z = aᵖ⁻ᵏ bᵖ → still all-a's then all-b's ∈ a*b* ✓ i = 1 (unchanged): xy¹z = aᵖ bᵖ → original string ∈ a*b* ✓ i = 2 (pump up): xy²z = aᵖ⁺ᵏ bᵖ → still all-a's then all-b's ∈ a*b* ✓ i = n (any n): xyⁿz = aᵖ⁺⁽ⁿ⁻¹⁾ᵏbᵖ → always all-a's then all-b's ∈ a*b* ✓

Adding or removing a's from the front of a*b* string always gives another a*b* string. No matter what i we choose, xyⁱz stays in L. We cannot find a contradiction.

✓ The Pumping Lemma is satisfied — but this tells us nothing about regularity
4
Understand the logical trap — why this proves nothing

The Pumping Lemma is a one-way implication:

L is regular ⟹ L is pumpable The CONTRAPOSITIVE (what we use for proofs): L is NOT pumpable ⟹ L is NOT regular What we CANNOT conclude: L is pumpable ⟹ L is regular ← THIS IS WRONG (converse, not valid)

Failing to find a contradiction with the Pumping Lemma only means we haven't disproved regularity — it says nothing positive. Some non-regular languages (like {aⁿbⁿ | n ≥ 0} with a bad string choice, or lucky splits) can appear pumpable. The Pumping Lemma is a necessary condition for regularity, never a sufficient one.

The Root of the Failure Here

a*b* is "too forgiving." Pumping only ever changes the count of a's, and a*b* accepts any count of a's before any count of b's. There is no balance condition to violate. The language has no constraint that pumping can break.

What Goes Wrong

L = {w | no b appears before any a} = a*b*.

If we try s = aᵖbᵖ, then |xy| ≤ p forces xy to consist of a's only, so y = aᵏ (k ≥ 1).

Pump up (i = 2): xy²z = aᵖ⁺ᵏbᵖ — still in a*b* ✓ Pump down (i = 0): xy⁰z = aᵖ⁻ᵏbᵖ — still in a*b* ✓
Why No Contradiction Is Reached

Adding or removing a's from the front of aᵖbᵖ always gives another string in a*b*. The Pumping Lemma is a one-way implication: regular → pumpable. It cannot be used to prove regularity. Every regular language satisfies it — and some non-regular languages can accidentally look "pumpable" with a bad choice of string, so failing to find a contradiction tells us nothing.

Showing L is Regular
✏️
Show Your Work — Part 2
Two clean ways to prove a*b* is regular
▶
1
Method A — Give a regular expression (fastest on an exam)

The language a*b* is literally described by the regular expression a*b*. Since every regular expression describes a regular language (by the equivalence of regex and DFA/NFA), we are done in one line:

L = L(a*b*) → L is regular □

This is the fastest correct proof. No DFA construction needed if the question just asks you to "show it is regular."

✓ Valid — regex directly witnesses regularity
2
Method B — Build the DFA (required if asked to construct one)

Think about what memory the DFA needs. There are exactly three situations:

q_a : we have seen only a's so far (or nothing yet) — still "in the a-zone" q_b : we have seen at least one b — now "in the b-zone", no more a's allowed q_dead : we saw an a after a b — permanently rejected

Design transitions by asking: "which zone does the next character push us into?"

From q_a: read a → stay in q_a (still only a's) read b → move to q_b (first b seen, now in b-zone) From q_b: read b → stay in q_b (more b's, still fine) read a → move to q_dead (a after a b — violated!) From q_dead: read a or b → stay in q_dead (no escape from rejection)

Accept states: q_a and q_b (both represent valid a*b* strings so far). q_dead rejects.

✓ DFA has 3 states, is total, and exactly recognizes a*b*
3
Verify the DFA on example strings
ε → q_a (accept) ✓ (ε ∈ a*b*) a → q_a → q_a (accept) ✓ b → q_a → q_b (accept) ✓ aab → q_a→q_a→q_a→q_b (acc) ✓ abb → q_a→q_b→q_b→q_b (acc) ✓ ba → q_a→q_b→q_dead (rej) ✓ (b before a) abba → q_a→q_b→q_b→q_dead→q_dead (rej) ✓

Every string that should be accepted is, and every string that shouldn't be is rejected. The DFA is correct.

4
Key lesson — how to actually prove regularity

To prove a language is regular, use any one of these constructive methods — the Pumping Lemma is never one of them:

1. Exhibit a regular expression for it 2. Construct a DFA (or NFA) that recognizes it 3. Use closure properties: show it equals L₁ ∩ L₂, L₁ ∪ L₂, L₁*, complement(L₁), etc. where L₁, L₂ are already known regular languages
Common Exam Mistake

Writing "I tried all pumping values and none broke L, therefore L is regular." This is always wrong. The Pumping Lemma cannot prove regularity — only the three methods above can. A language that satisfies the Pumping Lemma may still be non-regular (the lemma is necessary but not sufficient).

L = a*b* is described by the regular expression a*b*. Every regex describes a regular language, so L is regular.

Alternatively, a simple 3-state DFA:

StateMeaningOn aOn bAccept?
q_a (start)Still reading a'sq_aq_b✓
q_bNow reading b'sq_deadq_b✓
q_deadSaw an a after a bq_deadq_dead✗
Lecture Note — Alternative Proof Technique: Closure Properties

The lecture (Lecture 11, pp. 33–35) shows a powerful alternative to pumping: use closure under intersection to prove non-regularity. If L is regular and R is regular, then L ∩ R must also be regular. So if you can find a regular R such that L ∩ R is provably non-regular (e.g., by pumping on the intersection), then L itself cannot be regular.

Example from lecture: To prove L = {w | #010(w) = #101(w)} is non-regular, intersect with R = (010)*(101)* (regular). The intersection equals {(010)ᵏ(101)ᵏ | k ≥ 1}, which is non-regular by pumping. Therefore L is not regular.

This technique avoids having to pump directly on the original language, which can be much harder.

Q7 Error in the "All Horses Same Color" Induction Proof
Proof by Induction
▶
Key Definitions
Strong Induction Prove P(1), then assume P(k) holds for all k ≤ N and prove P(N+1). The inductive step must work for every N ≥ 1.
Inductive Step Gap An inductive step may appear valid in general but fail at a specific boundary (e.g., the N=1→N=2 transition). Checking N=1 explicitly is critical.
Overlap Argument Many inductive proofs of size/partition results rely on two subsets sharing at least one element. If the subsets are disjoint, the argument breaks.
What is wrong with the inductive proof that all horses are the same color?
✏️
Show Your Work
Dissecting exactly where and why the induction collapses
▶
1
Reconstruct the argument — read it charitably first

The "proof" claims: P(N) = "any set of N horses all have the same color."

Base case P(1): A single horse trivially has one color. P(1) holds. ✓

Inductive step: Assume P(N) holds (any N horses share a color). Now consider N+1 horses: H₁, H₂, …, H_N, H_{N+1}.

Group A = {H₁, H₂, …, H_N} ← first N horses Group B = {H₂, H₃, …, H_{N+1}} ← last N horses

By the inductive hypothesis P(N): all horses in Group A share a color, and all horses in Group B share a color. The argument then says: since Groups A and B overlap (they share horses H₂ through H_N), their colors must be the same color. Therefore all N+1 horses share one color. P(N+1) holds. ✓?

This sounds airtight — the flaw is subtle. Read on.

2
Identify what the argument actually depends on

The entire logic of the inductive step rests on one claim: Groups A and B share at least one horse. That shared horse is the "bridge" — it belongs to both groups, so the color of Group A must equal the color of Group B.

The overlap is the set of horses that appear in both groups:

Overlap = Group A ∩ Group B = {H₁,…,H_N} ∩ {H₂,…,H_{N+1}} = {H₂, H₃, …, H_N}

This overlap has exactly N − 1 horses. The whole argument works if and only if N − 1 ≥ 1, i.e., N ≥ 2.

3
Test the boundary: plug in N = 1 explicitly

The first application of the inductive step is P(1) → P(2): we need to go from "any 1 horse has one color" to "any 2 horses have the same color." Set N = 1:

Group A = {H₁} (first N = 1 horse) Group B = {H₂} (last N = 1 horse) Overlap = {H₂, …, H_N} = {H₂, …, H₁} = ∅

The overlap is empty. There is no horse shared between Group A and Group B. We know H₁ is some color and H₂ is some color — but we have no link between them. They could be completely different colors.

The argument breaks at exactly the first place it needs to work: the step from N = 1 to N = 2.

✗ Step fails at N = 1 — empty overlap, no color bridge
4
Understand the structure of the gap

In a correct induction, the base case and inductive step form an unbroken chain:

P(1) ──[step]──▶ P(2) ──[step]──▶ P(3) ──[step]──▶ …

Here, P(1) holds, and the step works for all N ≥ 2. But the step fails for N = 1. So the chain looks like this:

P(1) ──[BROKEN step]──✗ P(2) P(2) ──[step]──▶ P(3) P(3) ──[step]──▶ P(4) ...

P(1) is an island. P(2) is never reached from it. Every P(N) for N ≥ 2 would follow from P(2) by valid steps — but P(2) itself is never established. The entire chain above P(2) is floating with no foundation.

Why This Is Easy to Miss

When N is large, the overlap {H₂, …, H_N} looks obviously non-empty — it has N−1 elements. The case N=1 feels like just another instance of "small N." The error is invisible unless you substitute N=1 explicitly and count the overlap size: N−1 = 0. Always test the inductive step at the minimum value of N where it must apply.

5
State the flaw precisely — exam-ready answer

A clean one-paragraph answer for full credit:

The inductive step assumes the two groups of N horses share at least one horse (the overlap {H₂, …, H_N}), which is required to link their colors. This overlap has N−1 elements. For N ≥ 2, N−1 ≥ 1, so the overlap is non-empty and the argument is valid. However, for N = 1, the overlap is {H₂, …, H₁} = ∅. Group A = {H₁} and Group B = {H₂} share no horse, so their colors cannot be compared. The step fails at N = 1, which is exactly the step needed to go from P(1) to P(2). Since P(2) is never established, no P(N) for N ≥ 2 is proven, and the argument is invalid.
✓ The flaw is the empty overlap at N = 1, not any error in the base case or large-N steps
The Error

The inductive step fails for N = 1 — the critical transition from base case to the first application.

The argument says: given N+1 horses, remove the last → N horses all same color (by IH). Remove the first → last N horses also all same color (by IH). So all N+1 horses share a color via the overlap.

The Flaw — Empty Overlap at N = 1

The reasoning requires the two groups of N horses to share at least one horse, so their colors can be "linked." The overlap is {horse 2, …, horse N}.

But when N = 1: Group 1 = {horse 1}, Group 2 = {horse 2}. The overlap {2, …, 1} = ∅. There is no shared horse, so we cannot conclude they have the same color.

The overlap is non-empty only when N ≥ 2. The base case N = 1 does not bridge to N+1 = 2.

Lesson: always check the inductive step at the smallest valid value of N. A step that works for N ≥ 2 may fail at N = 1, creating a "gap" between the base case and the first use of the step.

Q8 U − C is Uncountable; Implications for Languages
Countability Set Theory
▶
Key Definitions
Countable Set A set S is countable if there exists a bijection from S to ℕ (or S is finite). Examples: ℤ, ℚ, Σ*, all finite strings over any alphabet.
Uncountable Set A set that cannot be put into bijection with ℕ. Examples: ℝ, 𝒫(ℕ), the power set of Σ* (= all languages).
Cantor's Theorem For any set A, |𝒫(A)| > |A|. In particular if Σ* is countably infinite, then 𝒫(Σ*) (all languages) is uncountable.
Closure of Countable Sets The union of two countable sets is countable. This is the key lemma used in the proof below.
Show that U − C (uncountable minus countable) is uncountable. What does this tell us about languages?
✏️
Show Your Work
Building the contradiction and applying it to the landscape of languages
▶
1
Understand the setup — what are U and C?

We are given two sets:

U = some uncountable set (e.g., all languages over Σ, or ℝ) C = some countable set (e.g., all regular languages, or ℤ)

We want to show that U − C (the elements of U that are not in C) is uncountable. Intuitively: if you remove a "small" (countable) chunk from a "large" (uncountable) set, what's left must still be large. But intuition isn't a proof — we need the formal argument.

The key tool we'll use: the union of two countable sets is countable. This is the closure property of countability under union.

2
Set up the proof by contradiction

Proof by contradiction: assume U − C is countable and derive that U must be countable — contradicting the given fact that U is uncountable.

Assume: U − C is countable ← this is our assumption to contradict Given: C is countable ← given in the problem Goal: derive U is countable ← this contradicts "U is uncountable"

The structure of every proof by contradiction: assume the opposite of what you want to prove, then show that assumption leads to something you already know is false.

3
Build the key subset containment

Here's the critical observation. Every element of U is either in C or not in C. So U can be "covered" by two groups:

Elements of U not in C → these are in U − C Elements of U also in C → these are in U ∩ C ⊆ C Together: U ⊆ (U − C) ∪ C

This is always true as a set identity — any element x ∈ U either satisfies x ∉ C (so x ∈ U−C) or x ∈ C (so x ∈ C). Either way x ∈ (U−C) ∪ C. Therefore U ⊆ (U−C) ∪ C.

✓ This step uses no assumption — it's a pure set-theory fact
4
Apply countability closure to reach the contradiction

Now plug in our assumption from Step 2:

U − C is countable (assumption) C is countable (given) ⟹ (U − C) ∪ C is countable [union of two countable sets is countable] ⟹ U is countable [U ⊆ countable set ⟹ U is countable] ⟹ CONTRADICTION ✗ [U is uncountable by hypothesis]

The last implication uses: any subset of a countable set is countable. Since U ⊆ (U−C) ∪ C and (U−C) ∪ C is countable (under our assumption), U itself must be countable. But we were told U is uncountable. Contradiction.

Therefore our assumption was wrong: U − C must be uncountable.

✓ Contradiction reached — proof complete
5
Apply the result to languages — fill in U and C concretely

Now substitute the specific sets from automata theory:

U = 𝒫(Σ*) = all languages over Σ → uncountable by Cantor's theorem (Σ* is countably infinite, so its power set is strictly larger) C = all regular languages → countable: each is described by a finite DFA/regex, and there are only countably many finite descriptions

Then by our theorem:

Non-regular languages = U − C = uncountable − countable = uncountable

The same argument applies to any countable class of languages — context-free, decidable, Turing-recognizable — because all of these are also countable (each described by a finite grammar or Turing machine, and there are only countably many finite descriptions).

All languages (U): uncountable ← the full ocean − Turing-recognizable languages (C): countable ← a tiny island ───────────────────────────────────────────────── Unrecognizable languages (U − C): uncountable ← still the ocean
The Big Picture Takeaway

The languages we study in this course — regular, context-free, decidable — are all countable classes. The set of ALL languages is uncountable. So in a precise mathematical sense, the languages computers can handle are a measure-zero speck inside the space of all possible languages. Almost every language that exists cannot be recognized by any algorithm whatsoever. We just never encounter those languages because they can't be described finitely either.

Proof

Let U be uncountable and C be countable. Suppose for contradiction that U − C is countable.

Observe: U ⊆ (U − C) ∪ (U ∩ C) ⊆ (U − C) ∪ C If U − C is countable, then: (U − C) ∪ C = (countable) ∪ (countable) = countable But U ⊆ countable set → U is countable. Contradiction! U is uncountable by assumption.
Therefore U − C must be uncountable.
Implications for Languages
Key Consequence

All languages over Σ = 𝒫(Σ*) is uncountable by Cantor's theorem (Σ* is countably infinite).

Regular languages form a countable set — each is described by a finite regex, and there are countably many finite strings.

By our result: Non-regular languages = All languages − Regular languages = Uncountable − Countable = uncountable.

In fact the same argument applies to Turing-recognizable languages (also countable). So most languages cannot be recognized by any Turing machine. The computable languages are a tiny countable island in an uncountable sea.

Takeaway: the class of languages we can "solve" in this course (regular, context-free, decidable) is infinitesimally small compared to the space of all possible languages.
