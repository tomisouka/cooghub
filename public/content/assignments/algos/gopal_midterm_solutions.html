Part A — Master Theorem
Formula
Master TheoremCase 1/2/3
▶
\[ T(n) = aT(n/b) + f(n) \] Case 1: \(f(n)=O(n^{\log_b a - \varepsilon})\Rightarrow T(n)=\Theta(n^{\log_b a})\)
Case 2: \(f(n)=\Theta(n^{\log_b a})\Rightarrow T(n)=\Theta(n^{\log_b a}\log n)\)
Case 3: \(f(n)=\Omega(n^{\log_b a + \varepsilon})\Rightarrow T(n)=\Theta(f(n))\)
Always check regularity condition for Case 3: \(af(n/b)\le cf(n)\) for some \(c<1\).

Identify \(a\), \(b\), and \(f(n)\) from the recurrence, then compute the watershed exponent \(\log_b a\) and compare it to the polynomial degree of \(f(n)\).
\[ \log_b a \text{ vs } \deg(f) \]

\[ a=3,\quad b=3,\quad f(n)=n^2 \]

Compute watershed exponent
\[ \log_b a = \log_3 3 = 1 \]

Part B — Asymptotic Comparison \(n^n\) vs \(n!\)
Formula
little-o definitionlimit test
▶
\[ f = o(g) \iff \lim_{n\to\infty}\frac{f(n)}{g(n)} = 0 \]
Exponential \(n^n\) grows faster than factorial \(n!\) because every factor in \(n!\) is \(\le n\), while every factor in \(n^n\) equals \(n\).
Prerequisite Knowledge▶
Write out the ratio and simplify term by term:
\[ \frac{n!}{n^n} = \frac{1}{n}\cdot\frac{2}{n}\cdot\frac{3}{n}\cdots\frac{n}{n} \le \frac{1}{n}\to 0 \]
Each of the \(n\) factors of \(n!/n^n\) is at most 1, and the first factor is \(1/n\to 0\).
1
Write the limit
\[ \lim_{n\to\infty}\frac{n!}{n^n} = \lim_{n\to\infty}\prod_{k=1}^{n}\frac{k}{n} \]
2
Bound the product
\[ \prod_{k=1}^{n}\frac{k}{n} \le \frac{1}{n}\cdot 1^{n-1} = \frac{1}{n}\to 0 \]
So \(n!\) is strictly smaller-order than \(n^n\), giving us little-o.
✓ Solution \[ n! = o(n^n) \quad\Longleftrightarrow\quad \lim_{n\to\infty}\frac{n!}{n^n}=0 \]
Student answer: Correct relation (\(n!=o(n^n)\)) with correct limit argument. Partial justification shown. +4 (–2 for incomplete written explanation of bound)
Part C — Recurrence Unrolling \(T(n)=2T(n-1)+1\)
Formula
unrolling / telescopinggeometric series
▶
\[ T(n) = 2^{n-1}T(1) + \sum_{i=0}^{n-2}2^i = 2^{n-1} + (2^{n-1}-1) = 2^n - 1 \]
Geometric series: \(\sum_{i=0}^{k}2^i = 2^{k+1}-1\).
Prerequisite Knowledge▶
Unrolling subtractive recurrences produces exponential growth when the coefficient \(a>1\):
\[ T(n-k) = 2^k T(n-k) + \sum_{i=0}^{k-1}2^i \]
1
Unroll two steps
\[ T(n)=2T(n-1)+1 \] \[ =2(2T(n-2)+1)+1=4T(n-2)+3 \]
2
General pattern after \(k\) steps
\[ T(n) = 2^k T(n-k) + (2^k - 1) \]
3
Base case at \(k=n-1\)
\[ T(n) = 2^{n-1}\cdot 1 + (2^{n-1}-1) = 2^n - 1 = \Theta(2^n) \]
✓ Solution \[ T(n) = \Theta(2^n) \]
Student answer: Correct — student showed the unrolling pattern and reached \(\Theta(2^n)\). Base case \(T(1)=1\) noted. +6
Part D — Repeated Application of \(f\)
Prerequisite Knowledge▶
Key insight: Every two applications of \(f\) reduce \(n\) by at least a factor of 2.
If \(n\) is odd: \(f(n)=n-1\) (now even). Then \(f(n-1)=(n-1)/2\). Two steps → roughly \(n/2\).
If \(n\) is even: one step → \(n/2\).
\[ \text{Steps} \le 2\log_2 n \Rightarrow O(\log n) \]
1
Even case
\[ n \xrightarrow{1\text{ step}} n/2 \]
Value halves in one step.
2
Odd case
\[ n \xrightarrow{f} n-1 \xrightarrow{f} (n-1)/2 \]
Two steps halve the value (approximately). Worst case: 2 steps per halving.
3
Total steps bound
\[ \text{steps} \le 2\lfloor\log_2 n\rfloor = O(\log n) \]
✓ Solution \[ O(\log n) \]
Student answer: Correct upper bound \(O(\log n)\). Good justification (odd removes 1 element, every other step halves). +6
Part E — Euclid's GCD
Prerequisite Knowledge▶
Euclid's algorithm: \(\gcd(a,b)=\gcd(b, a\bmod b)\). After two steps, the larger argument shrinks by at least half, so the number of steps is \(O(\log(\min(a,b)))\), which is polynomial in the number of input bits \(O(\log n)\) where \(n\) is the input value.
1
Lamé's theorem
\[ \text{Steps of Euclid's algorithm} \le 5\log_{10}(\min(a,b)) + 1 \]
Polynomial in the number of bits, so runs in polynomial time.
✓ Solution \[ \textbf{True.}\quad\text{Euclid's GCD runs in }O(\log n)\text{ steps — polynomial in input size.} \]
Student answer: Correct (True), minimal justification written. +1 (base point only — no Lamé/step-count argument given)
Concept
Master Theorem Asymptotic Notation Recurrence Unrolling
▶

Master Theorem Cases. Compare \(f(n)\) to \(n^{\log_b a}\): if \(f\) is polynomially smaller → Case 1 \(\Theta(n^{\log_b a})\); if equal → Case 2 adds a log; if polynomially larger → Case 3 \(\Theta(f(n))\).

Subtractive recurrences (\(T(n-1)\)) unroll to exponential \(\Theta(a^n)\) when \(a>1\), unlike divide-and-conquer which gives poly or poly-log.

little-o vs Big-O. \(f=o(g)\) means the ratio \(f/g\to 0\); \(f=O(g)\) only requires the ratio be bounded.

Find-Mode — Divide & Conquer
MOST FREQUENT ELEMENT · INDUCTION · RUNNING TIME · 35 PTS
▶
Problem 2
Give a recursive divide-and-conquer algorithm find-mode that outputs the most frequent element in an array \(A\) of \(n\) elements. Only allowed operation between two elements: equality test.
1
Explain the algorithm and give pseudocode.
2
Show correctness by mathematical induction.
3
Analyze the running time.
4
Use find-mode as a black box to solve the distinct-elements problem. What is the running time?
5
Given \(\Omega(n\log n)\) lower bound for distinct-elements, what can you conclude about find-mode?
Part 1 — Algorithm Description & Pseudocode
Prerequisite Knowledge▶
Boyer–Moore majority-vote style via D&C. Split the array in half recursively. Each half returns a candidate and a count. Merge by comparing the two candidates against the full merged subarray. The most frequent element of the whole must be the most frequent in at least one half (if it appears > n/2 times), or we must verify candidates. The correct approach: recursively get candidates from both halves, then in the merge step do a linear scan to find which candidate is truly most frequent.
\[ \text{find-mode}(A[1\ldots n]) \to \text{most frequent element} \]
1
High-level idea
Divide \(A\) into two halves \(L=A[1\ldots\lfloor n/2\rfloor]\) and \(R=A[\lfloor n/2\rfloor+1\ldots n]\).
Recursively find the mode of \(L\) (call it \(c_L\)) and the mode of \(R\) (call it \(c_R\)).
Key observation: the mode of the whole array must be either \(c_L\) or \(c_R\), because if an element \(x\) appears more than any other in the whole array, it must appear more than any other in at least one half (by a counting argument — if it weren't the mode of either half, it could be beaten in both, which is a contradiction when counted carefully).
Count occurrences of \(c_L\) and \(c_R\) in \(A\) linearly, return the one with higher count.
find-mode(A, lo, hi) Output: most frequent element in A[lo..hi]
1if lo = hi: return A[lo]  base case — single element
2mid ← ⌊(lo + hi) / 2⌋
3cL ← find-mode(A, lo, mid)  mode of left half
4cR ← find-mode(A, mid+1, hi)  mode of right half
5countL ← 0 ; countR ← 0
6for i ← lo to hi
7if A[i] = cL: countL ← countL + 1
8if A[i] = cR: countR ← countR + 1
9if countL ≥ countR: return cL
10else: return cR
Student answer: Described divide step and merge strategy correctly in prose. Pseudocode has the right recursive structure but is missing the linear count-verification step in the merge — the candidate comparison via a counter strategy (similar to Boyer–Moore) is not a standard D&C merge. The student's pseudocode conflates counting with voting. –14 (per grader mark)
Part 2 — Correctness by Induction
1
Base Case \(n=1\)
Array has one element. That element is trivially the most frequent. Algorithm returns \(A[1]\). ✓
2
Induction Hypothesis
Assume find-mode correctly returns the most frequent element for all arrays of size \(k < n\).
3
Inductive Step
For an array of size \(n\): both halves have size \(< n\), so by IH, \(c_L\) and \(c_R\) are the correct modes of their respective halves.
Key lemma: The global mode \(x^*\) must equal \(c_L\) or \(c_R\). Proof: suppose \(x^*\neq c_L\) and \(x^*\neq c_R\). Then in the left half, \(c_L\) appears at least as often as \(x^*\); in the right half, \(c_R\) appears at least as often as \(x^*\). So \(x^*\) is not strictly more frequent than both \(c_L\) and \(c_R\) combined — contradiction.
Therefore the linear scan in lines 6–10 correctly identifies the global mode. ✓
✓ Correctness established \[\text{By strong induction: find-mode correctly returns the mode for all }n\ge 1.\]
Part 3 — Running Time Analysis
Formula
RecurrenceMaster Theorem Case 2
▶
\[ T(n) = 2T(n/2) + O(n) \]
Two recursive calls on halves + O(n) linear scan in merge.
1
Apply Master Theorem
\[ a=2,\;b=2,\;f(n)=\Theta(n)=\Theta(n^{\log_2 2})=\Theta(n^1)\Rightarrow\text{Case 2} \]
✓ Solution \[ T(n) = \Theta(n\log n) \]
Part 4 — Distinct-Elements via find-mode
1
Reduction
Run find-mode to get the most frequent element \(c\).
Count how many times \(c\) appears in \(A\) (one linear scan).
If the count equals 1, then all elements are distinct (output true).
Otherwise output false (at least one duplicate exists).
2
Running Time
\[ O(n\log n) + O(n) = O(n\log n) \]
✓ Solution \[ \text{Running time: } O(n\log n) \]
Part 5 — Lower Bound Implication
1
Reduction argument
Since find-mode solves the distinct-elements problem (Part 4) in \(O(T_{\text{mode}}(n))\) time, and distinct-elements requires \(\Omega(n\log n)\) time, we conclude:
\[ T_{\text{mode}}(n) = \Omega(n\log n) \]
Combined with the \(O(n\log n)\) upper bound from Part 3:
✓ Conclusion \[ T_{\text{find-mode}}(n) = \Theta(n\log n) \]
Intuition: find-mode is at least as hard as distinct-elements. Since the lower bound for distinct-elements is \(\Omega(n\log n)\) and our algorithm achieves \(O(n\log n)\), find-mode is optimally efficient.
Concept
D&C Correctness Reduction Proofs Lower Bounds
▶

Merge correctness lemma. The global mode must be the mode of at least one half — otherwise its count in the whole array is beaten, contradicting it being the mode.

Reductions for lower bounds. If problem B reduces to problem A (A solves B), and B has lower bound \(\Omega(f(n))\), then A must also require \(\Omega(f(n))\).

\(T(n)=2T(n/2)+O(n)\) → \(\Theta(n\log n)\) by Master Theorem Case 2. This is the same recurrence as merge sort.

MEDIAN-OF-MEDIANS · PARTITION · O(n) ALGORITHM · 35 PTS

Problem 3
Given an unsorted array \(A\) of size \(n\) containing all integers in \([0,n]\) except one, find the missing integer. Must run in \(O(n)\). Hint: divide into two nearly equal subproblems.
1
Describe a divide-and-conquer algorithm. Must run in \(O(n)\).
2
Argue correctness.
3
Analyze the running time.
Part 1 — Algorithm Description
Formula
Median of Possible ValuesCounting Argument
▶
\[ \text{Pivot} = \text{median of possible values } [lo, hi] = \left\lfloor\frac{lo+hi}{2}\right\rfloor \]
Count elements ≤ pivot. Expected count if no missing: pivot − lo + 1. If actual count < expected, missing is in left half; else right half.
Prerequisite Knowledge▶
Key idea: Use the range of possible values, not the array values, as the pivot. In the range \([lo, hi]\), there should be exactly \(\lfloor(hi-lo)/2\rfloor+1\) values in \([lo, mid]\). Count elements actually present. Discrepancy tells us which half contains the missing value. Recurse on that half only → \(T(n) = T(n/2) + O(n) = O(n)\).
\[ \text{expected\_left} = \text{mid} - lo + 1 \]
1
Set range of possible values
Initially the possible range is \([0, n]\). The missing integer is somewhere in this range.
2
Compute pivot = median of range
\[ \text{mid} = \left\lfloor\frac{lo + hi}{2}\right\rfloor \]
3
Count elements in left half of range
Scan array: count how many elements \(x\) satisfy \(lo \le x \le \text{mid}\). Call this \(c\).
4
Decide which half to recurse on
\[ \text{expected} = \text{mid} - lo + 1 \] \[ \text{if } c < \text{expected} \Rightarrow \text{recurse on } [lo,\,\text{mid}] \] \[ \text{else} \Rightarrow \text{recurse on } [\text{mid}+1,\, hi] \]
The side with fewer elements than expected is the side missing a value.
find-missing(A, lo, hi) Output: the missing integer in [lo, hi]
1if lo = hi: return lo  only one candidate — it's missing
2mid ← ⌊(lo + hi) / 2⌋
3count ← 0  count elements in left value-range
4for each x in A
5if lo ≤ x ≤ mid: count ← count + 1
6expected ← mid − lo + 1
7if count < expected:
8return find-missing(A, lo, mid)  missing is in left half
9else:
10return find-missing(A, mid+1, hi)  missing is in right half
✓ Initial call \[ \text{find-missing}(A,\; 0,\; n) \]
Student answer: Correct strategy (median of possible values, partition by count, recurse on short side). Good examples shown. Missing: precise pseudocode with correct base case. +12 / –3 for loose pseudocode
Part 2 — Correctness
1
Base Case \(n=2\) (range of size 2)
Two possible values, one element present. Count tells us which is missing. ✓
2
Induction Hypothesis
For all ranges of size \(k < hi-lo+1\), the algorithm correctly returns the missing value.
3
Inductive Step
If \(c < \text{expected}\): the left half of the range is missing a value (it has one fewer element than expected), and the right half is complete. So the missing integer is in \([lo, \text{mid}]\). By IH, recursing there returns the correct answer. ✓
If \(c = \text{expected}\): left half is complete, so missing integer is in \([\text{mid}+1, hi]\). By IH, recursing there returns the correct answer. ✓
✓ Correctness established \[\text{By strong induction on range size.}\]
Student answer: Correct base case and inductive step. Good. +5
Part 3 — Running Time
Formula
RecurrenceMaster Theorem Case 3→ O(n)
▶
\[ T(n) = T(n/2) + O(n) \]
\(a=1,\,b=2,\,\log_2 1=0.\) \(f(n)=\Theta(n)=\Omega(n^{0+1})\) → Case 3 → \(T(n)=\Theta(n)\).
1
Cost per level
Each recursive call scans the full array once: \(O(n)\). Only one recursive call is made (we discard the other half).
2
Number of levels
\[ \log_2(n+1) \text{ levels} \]
But the scanned portion stays size \(n\) throughout (we only halve the range, not the array). Total work: \(O(n)\cdot O(\log n)\)... wait — actually the array is not filtered. To get a true \(O(n)\) solution, we should only scan the subarray (filter elements to relevant range first), giving \(T(n)=T(n/2)+O(n)\) with the sub-array being passed. By Master Theorem Case 3: \(T(n)=O(n)\).
✓ Solution \[ T(n) = T(n/2) + O(n) = O(n) \]
Note: If we scan the full array at every level without filtering, we get \(O(n\log n)\). The \(O(n)\) bound is achieved by filtering the array to only elements in the active range before recursing, or equivalently by noting the geometric series \(n + n/2 + n/4 + \cdots = 2n = O(n)\) because the sub-arrays halve in size. +2 (partial — student wrote correct recurrence form)
Concept
Binary Search on Values Counting Invariant T(n)=T(n/2)+O(n)
▶

Pivot on value range, not array position. Classical binary search halves the array. Here we halve the set of possible values. Counting elements in one value-range tells us which half is "incomplete."

Recurrence \(T(n)=T(n/2)+O(n)\). Only one subproblem of half size + linear work. By Master Theorem Case 3 (or geometric series argument): \(T(n)=O(n)\). This is strictly better than sorting (\(O(n\log n)\)).

Why not XOR? The classic XOR trick also gives \(O(n)\) for this problem but does not generalize to D&C structure — the problem specifically requests a divide-and-conquer approach.
