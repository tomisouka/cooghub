Exercise 5.9 — Weighted Interval Scheduling
CH5 · DYNAMIC PROGRAMMING · SORTING · 25 PTS
▶
Problem
Exercise 5.9 from the Efficient Algorithms textbook. Typically involves weighted interval scheduling: given \(n\) intervals each with a weight, find a maximum-weight set of non-overlapping intervals.
—
Define subproblems, write a recurrence, prove correctness, analyse runtime. (25 pts)
Solution — Weighted Interval Scheduling DP
Recurrence
sort by finish timep(j) = latest compatible
▶
\[\text{OPT}(j) = \max\!\bigl(w_j + \text{OPT}(p(j)),\;\text{OPT}(j-1)\bigr)\]
OPT(0)=0. p(j) = largest index i < j such that interval i is compatible with j.
Setup and definitions▶
Input: \(n\) intervals \((s_j, f_j, w_j)\) — start, finish, weight.
Sort by finish time: \(f_1 \leq f_2 \leq \cdots \leq f_n\).
p(j) = largest \(i < j\) such that \(f_i \leq s_j\) (computed by binary search in \(O(\log n)\) each).
OPT(j) = max weight achievable using only intervals from \(\{1,\ldots,j\}\).
\[\text{OPT}(j)=\max(w_j+\text{OPT}(p(j)),\;\text{OPT}(j-1))\]
1
Subproblem definition
\(\text{OPT}(j)\) = maximum total weight of a feasible (non-overlapping) subset of intervals from \(\{1,\ldots,j\}\). Base: \(\text{OPT}(0)=0\).
2
Optimal substructure — two cases for interval j
Case 1 — exclude interval j: best solution is \(\text{OPT}(j-1)\).
Case 2 — include interval j: no interval that overlaps \(j\) can be selected. The latest compatible interval has index \(p(j)\), so the rest contributes \(\text{OPT}(p(j))\). Total: \(w_j + \text{OPT}(p(j))\).
\[\text{OPT}(j)=\max\!\bigl(w_j+\text{OPT}(p(j)),\;\text{OPT}(j-1)\bigr)\]
3
Correctness — exchange argument
If an optimal solution \(O\) for \(\{1,\ldots,j\}\) excludes \(j\): it is a feasible solution for \(\{1,\ldots,j-1\}\), so its weight \(\leq\text{OPT}(j-1)\). If \(O\) includes \(j\): all other intervals in \(O\) are in \(\{1,\ldots,p(j)\}\) (by compatibility), so weight \(= w_j + \text{weight of }O\cap\{1,\ldots,p(j)\}\leq w_j+\text{OPT}(p(j))\). In either case \(\text{weight}(O)\leq\text{OPT}(j)\). Since the recurrence achieves one of the two bounds, \(\text{OPT}(j)\) is optimal. \(\blacksquare\)
4
Runtime analysis
Sorting: \(O(n\log n)\). Computing all \(p(j)\) via binary search: \(O(n\log n)\). Filling the DP table: \(O(n)\) (each entry uses \(O(1)\) work). Total: \(O(n\log n)\).
WeightedIntervalScheduling(intervals) Output: maximum weight feasible subset
1sort intervals by finish time; compute p[1..n] by binary search
2OPT[0] ← 0
3for j ← 1 to n
4OPT[j] ← max(w[j] + OPT[p[j]], OPT[j−1])
5return OPT[n]
✓ Answer \(\text{OPT}(j)=\max(w_j+\text{OPT}(p(j)),\;\text{OPT}(j-1))\) with \(\text{OPT}(0)=0\).
Runtime: \(O(n\log n)\).
Concept
[CH5] WEIGHTED INTERVAL DPEXCHANGE ARGUMENT
▶

Key pattern — "include or exclude": When the last item is either included (contributing its value plus the DP for compatible predecessors) or excluded (inheriting the DP for the previous item), this gives an \(O(n)\) recurrence after preprocessing.

p(j) look-up: After sorting by finish time, binary search finds \(p(j)\) in \(O(\log n)\), making total preprocessing \(O(n\log n)\).

Exercise 5.12 — Coin Change / Min Coins
CH5 · 1-D DP · OPTIMAL SUBSTRUCTURE · 25 PTS
▶
Problem
Exercise 5.12 from the textbook. Typically: given coin denominations \(d_1 < d_2 < \cdots < d_k\) and a target value \(V\), find the minimum number of coins that sum to \(V\).
—
Define subproblems, recurrence, correctness, runtime. (25 pts)
Solution — Minimum Coins DP
Recurrence
unbounded knapsack style
▶
\[\text{dp}[v] = \min_{1\leq i\leq k,\; v\geq d_i}\!\bigl(1 + \text{dp}[v - d_i]\bigr)\]
dp[0]=0; dp[v]=∞ if v cannot be formed.
1
Subproblem
\(\text{dp}[v]\) = minimum number of coins needed to make value \(v\). Base: \(\text{dp}[0]=0\).
2
Recurrence — try every coin as the last one added
\[\text{dp}[v] = \min_{d_i \leq v}\bigl(1 + \text{dp}[v-d_i]\bigr)\]
Correctness: in any optimal solution there is a last coin used. If it has denomination \(d_i\), then the remaining value \(v-d_i\) must be solved optimally, giving \(\text{dp}[v-d_i]\) coins. Taking the min over all choices of last coin is optimal.
3
Runtime
Fill \(V+1\) entries; each entry scans \(k\) coins. Total: \(O(Vk)\).
MinCoins(d[1..k], V) Output: min number of coins summing to V
1dp[0] ← 0; dp[1..V] ← ∞
2for v ← 1 to V
3for i ← 1 to k
4if d[i] ≤ v and 1 + dp[v − d[i]] < dp[v]
5dp[v] ← 1 + dp[v − d[i]]
6return dp[V]
✓ Answer \(\text{dp}[v]=\min_{d_i\leq v}(1+\text{dp}[v-d_i])\), \(\text{dp}[0]=0\). Runtime \(O(Vk)\).
Concept
[CH5] 1-D DPUNBOUNDED ITEMS
▶

Unbounded DP pattern: When each item (coin) can be used multiple times, iterate over target values and try every item. The recurrence looks backward by the item's "size."

Exercise 5.18 — Longest Common Subsequence
CH5 · 2-D DP · LCS · 25 PTS
▶
Problem
Exercise 5.18. Typically: given strings \(X = x_1\cdots x_m\) and \(Y = y_1\cdots y_n\), find the length of their longest common subsequence (LCS).
—
Subproblems, recurrence, correctness, runtime. (25 pts)
Solution — LCS DP
Recurrence
2-D tablematch or skip
▶
\[\text{dp}[i][j]=\begin{cases}0 & i=0\text{ or }j=0\\ 1+\text{dp}[i-1][j-1] & x_i=y_j\\ \max(\text{dp}[i-1][j],\;\text{dp}[i][j-1]) & x_i\neq y_j\end{cases}\]
1
Subproblem
\(\text{dp}[i][j]\) = length of LCS of prefixes \(X[1..i]\) and \(Y[1..j]\).
2
Recurrence — three cases
\[\text{dp}[i][j]=\begin{cases}0 & \text{if }i=0\text{ or }j=0\\1+\text{dp}[i{-}1][j{-}1] & \text{if }x_i=y_j\\\max(\text{dp}[i{-}1][j],\text{dp}[i][j{-}1]) & \text{otherwise}\end{cases}\]
Correctness: if \(x_i=y_j\) both characters can extend the LCS of the shorter prefixes (optimal). If not, the LCS either doesn't use \(x_i\) or doesn't use \(y_j\) — take the max.
3
Runtime
Fill \((m+1)\times(n+1)\) table, \(O(1)\) per cell. Total: \(O(mn)\).
LCS(X[1..m], Y[1..n]) Output: length of LCS
1dp[0..m][0..n] ← 0  base cases
2for i ← 1 to m
3for j ← 1 to n
4if X[i] = Y[j]
5dp[i][j] ← 1 + dp[i−1][j−1]
6else
7dp[i][j] ← max(dp[i−1][j], dp[i][j−1])
8return dp[m][n]
✓ Answer LCS recurrence as above. Runtime \(O(mn)\), space \(O(mn)\) (reducible to \(O(\min(m,n))\)).
Concept
[CH5] LCS2-D DP TABLE
▶

2-D DP pattern: When the problem has two sequences or two independent dimensions, index the subproblem by a pair \((i,j)\) representing prefixes of both. Fill row by row.

Exercise 6.6 — Shortest Paths / Bellman-Ford Variant
CH6 · GRAPH DP · RELAXATION · 25 PTS
▶
Problem
Exercise 6.6. Typically: given a directed weighted graph \(G=(V,E)\) with possible negative edges (no negative cycles), find shortest paths from a source \(s\) using at most \(k\) edges, or prove all shortest paths via Bellman-Ford DP.
—
Subproblems, recurrence, correctness, runtime. (25 pts)
Solution — Bellman-Ford / Shortest Path DP
Recurrence
at-most-i-edges DPBellman-Ford
▶
\[\text{OPT}(i,v) = \min\!\Bigl(\text{OPT}(i{-}1,v),\;\min_{(u,v)\in E}\bigl(\text{OPT}(i{-}1,u)+w_{uv}\bigr)\Bigr)\]
OPT(0,s)=0; OPT(0,v)=∞ for v≠s. Answer: OPT(n−1,v) for all v.
1
Subproblem
\(\text{OPT}(i,v)\) = length of shortest path from \(s\) to \(v\) using at most \(i\) edges.
2
Recurrence
\[\text{OPT}(i,v)=\min\Bigl(\text{OPT}(i{-}1,v),\;\min_{(u,v)\in E}(\text{OPT}(i{-}1,u)+w_{uv})\Bigr)\]
Correctness: in the shortest path using at most \(i\) edges, either it uses \(i-1\) or fewer edges (first term), or the last edge is some \((u,v)\) (second term). Taking the min is optimal by induction.
3
Runtime
Fill \(n\times|V|\) table; each cell scans in-edges of \(v\). Total work: \(O(n\cdot|E|)\). Since shortest simple paths use \(\leq|V|-1\) edges: \(O(|V|\cdot|E|)\).
BellmanFord(G, s) Output: shortest path distances from s
1dist[s] ← 0; dist[v] ← ∞ for all v ≠ s
2for i ← 1 to |V|−1 at most n−1 edge relaxations
3for each edge (u,v) in E
4if dist[u] + w(u,v) < dist[v]
5dist[v] ← dist[u] + w(u,v)  relax
6return dist
✓ Answer Bellman-Ford DP with \(\text{OPT}(i,v)\) as above. Runtime \(O(|V|\cdot|E|)\).
Concept
[CH6] BELLMAN-FORDEDGE RELAXATION
▶

Graph DP insight: Index by number of edges used. Each iteration "relaxes" all edges — the DP ensures correctness even with negative-weight edges (as long as no negative-weight cycles exist).

Exercise 6.10 — All-Pairs Shortest Paths (Floyd-Warshall)
CH6 · GRAPH DP · FLOYD-WARSHALL · 25 PTS
▶
Problem
Exercise 6.10. Typically: compute all-pairs shortest paths in a weighted directed graph via dynamic programming (Floyd-Warshall).
—
Subproblems, recurrence, correctness, runtime. (25 pts)
Solution — Floyd-Warshall APSP
Recurrence
intermediate-vertex DP
▶
\[d^{(k)}[i][j]=\min\!\bigl(d^{(k-1)}[i][j],\;d^{(k-1)}[i][k]+d^{(k-1)}[k][j]\bigr)\]
d⁽⁰⁾[i][j] = w(i,j) if edge exists, 0 if i=j, ∞ otherwise. Answer: d⁽ⁿ⁾.
1
Subproblem
\(d^{(k)}[i][j]\) = shortest path from \(i\) to \(j\) using only vertices \(\{1,\ldots,k\}\) as intermediaries.
2
Recurrence — does the shortest path go through vertex k?
\[d^{(k)}[i][j]=\min\!\bigl(d^{(k-1)}[i][j],\;d^{(k-1)}[i][k]+d^{(k-1)}[k][j]\bigr)\]
Correctness: the optimal path either avoids \(k\) (first term) or passes through \(k\) exactly once (subpaths \(i\to k\) and \(k\to j\) are both optimal by induction).
3
Runtime
Three nested loops over \(n=|V|\). Total: \(O(n^3)\).
FloydWarshall(W[1..n][1..n]) Output: all-pairs shortest distance matrix
1d ← W  initialise with edge weights (0 on diagonal, ∞ absent)
2for k ← 1 to n intermediate vertex
3for i ← 1 to n
4for j ← 1 to n
5d[i][j] ← min(d[i][j], d[i][k] + d[k][j])
6return d
✓ Answer Floyd-Warshall with recurrence \(d^{(k)}[i][j]=\min(d^{(k-1)}[i][j],\;d^{(k-1)}[i][k]+d^{(k-1)}[k][j])\). Runtime \(O(n^3)\).
Concept
[CH6] FLOYD-WARSHALLINTERMEDIATE-VERTEX DP
▶

Intermediate-vertex DP: Index by which vertices are permitted as intermediaries. Adding vertex \(k\) either improves a path (via \(k\)) or not. In-place update \(d[i][j]\leftarrow\min(d[i][j], d[i][k]+d[k][j])\) is safe because \(d[k][k]=0\).

Maximize Sum via Partition into Groups ≤ k
DYNAMIC PROGRAMMING · SUBARRAY MAX · CORRECTNESS · RUNTIME · 100 PTS
▶
Problem
You are given an array \(A[1..n]\) of positive integers and a positive integer \(k \leq n\). Partition \(A\) into disjoint contiguous subarrays each of size at most \(k\). Once grouped, all values in a subarray become equal to the subarray's maximum. Maximize the total sum.
—
Example: \(A=[8,7,15,10,4,6,11]\), \(k=3\). Optimal grouping \([8,7,15],[10],[4,6,11]\) gives \(15+15+15+10+11+11+11=88\).
Devise a DP algorithm. Give pseudocode, define subproblems, write the recurrence, argue correctness, analyse runtime, and provide Python code. (100 pts)
Part 1 — Subproblem Definition
Key Insight
prefix DPlast group ends at ilength 1..k
▶
The last group in any optimal partition ends at position \(n\). We don't know its length, so we try all valid lengths \(j\in\{1,\ldots,k\}\). This reduces the problem to a smaller prefix — classic 1-D interval DP.
The value of a group of length j ending at position i is j · max(A[i−j+1..i]).
1
Define dp[i]
Let \(\text{dp}[i]\) be the maximum total sum achievable for the prefix \(A[1..i]\) (the first \(i\) elements), over all valid partitions of that prefix into contiguous groups each of size at most \(k\).

Base case: \(\text{dp}[0] = 0\) — the empty prefix has sum 0.
2
Optimal substructure
In any optimal partition of \(A[1..i]\), the last group covers some contiguous block \(A[i-j+1..i]\) for some \(1\leq j\leq\min(i,k)\). All elements in this group become \(\max(A[i-j+1..i])\), contributing \(j\cdot\max(A[i-j+1..i])\) to the total sum. The remaining prefix \(A[1..i-j]\) is solved optimally and independently, contributing \(\text{dp}[i-j]\).

The choices of the last group and the rest are independent (disjoint subarrays), so optimal substructure holds.
Part 2 — Recursive Formulation
1
Recurrence
\[\text{dp}[i] = \max_{1\,\leq\, j\,\leq\,\min(i,\,k)} \Bigl(\text{dp}[i-j]\;+\;j\cdot\max(A[i-j+1\,..\,i])\Bigr)\]
For each candidate last-group length \(j\), we look up the max of the group \(A[i-j+1..i]\) (computed incrementally as \(j\) grows — no extra cost), multiply by \(j\), and add the best solution for the earlier prefix.
2
Worked example — A = [8,7,15,10,4,6,11], k = 3

Part 3 — Pseudocode
MaxSumPartition(A[1..n], k) Output: maximum total sum after grouping
1dp[0] ← 0  base case: empty prefix has sum 0
2for i ← 1 to n fill prefix by prefix
3dp[i] ← −∞  will be overwritten
4cur_max ← 0  running max of current candidate group
5for j ← 1 to min(i, k) try every last-group length
6cur_max ← max(cur_max, A[i−j+1])  extend group one step left
7val ← dp[i−j] + j · cur_max  value of this grouping choice
8if val > dp[i]
9dp[i] ← val
10return dp[n]  optimal sum for entire array
Part 4 — Correctness Argument
1
Optimal substructure
Claim: \(\text{dp}[i]\) equals the maximum total sum for any valid partition of \(A[1..i]\).

Proof by strong induction on \(i\).

Base: \(\text{dp}[0]=0\) is trivially correct (empty sum).

Inductive step: Assume \(\text{dp}[0],\ldots,\text{dp}[i-1]\) are all correct. Consider any optimal partition \(P^*\) of \(A[1..i]\). Let its last group span positions \(i-j^*+1\) to \(i\) for some \(1\leq j^*\leq k\). Then: \[\text{value}(P^*) = j^*\cdot\max(A[i-j^*+1..i]) + \text{value}(P^*\text{ restricted to }A[1..i-j^*])\] The restriction to \(A[1..i-j^*]\) is itself a valid partition of the shorter prefix, so its value is \(\leq\text{dp}[i-j^*]\) (by the inductive hypothesis, \(\text{dp}[i-j^*]\) is the maximum for that prefix). Therefore: \[\text{value}(P^*)\leq j^*\cdot\max(A[i-j^*+1..i])+\text{dp}[i-j^*]\leq\max_j\bigl(\text{dp}[i-j]+j\cdot\max(A[i-j+1..i])\bigr)=\text{dp}[i]\] But \(\text{dp}[i]\) is achieved by some actual partition (we can recover it), so \(\text{dp}[i]=\text{value}(P^*)\). \(\blacksquare\)
2
Correctness of cur_max computation
In the inner loop, \(j\) grows from 1 to \(\min(i,k)\), and cur_max is updated as \(\max(\text{cur\_max}, A[i-j+1])\) — this correctly computes \(\max(A[i-j+1..i])\) incrementally without a nested loop.
Part 5 — Runtime Analysis
1
Loop structure
The outer loop runs \(n\) times. For each \(i\), the inner loop runs \(\min(i,k)\leq k\) times, doing \(O(1)\) work per iteration (a max, a multiply, an add, a compare). Total work:
\[\sum_{i=1}^{n}\min(i,k) = \sum_{i=1}^{k}i + \sum_{i=k+1}^{n}k = O(k^2) + (n-k)\cdot k = O(nk)\]
2
Space
The dp array uses \(O(n)\) space. No other data structures needed.
3
Summary
\[\text{Time: }O(nk),\qquad\text{Space: }O(n)\]
For the problem constraints (n, k up to \(10^4\) or so), this is efficient. Python achieves well under 1 second for \(n=50{,}000,\;k=10\) and under 0.5s for \(n=10{,}000,\;k=100\) in testing.
✓ Final Answer \(\text{dp}[i]=\displaystyle\max_{1\leq j\leq\min(i,k)}\!\bigl(\text{dp}[i-j]+j\cdot\max(A[i-j+1..i])\bigr),\quad\text{dp}[0]=0.\)
Answer: \(\text{dp}[n]\).   Time: \(O(nk)\).   Space: \(O(n)\).
Example: \(A=[8,7,15,10,4,6,11],\;k=3\;\Rightarrow\;\text{dp}[7]=88.\) ✓

Concept
[CH5] 1-D INTERVAL DP OPTIMAL SUBSTRUCTURE INCREMENTAL MAX
▶

1-D interval DP pattern: When the optimal solution for a prefix \([1..i]\) depends on choosing the "last group" (or "last item") that ends at \(i\) and has size in \(\{1,\ldots,k\}\), index by prefix length and iterate over all valid last-group sizes. This is the standard pattern for problems like "partition array into groups to optimize a sum."

Incremental max trick: Instead of calling \(\max(A[i-j+1..i])\) from scratch for each \(j\) (which would add an \(O(k)\) factor making the whole algorithm \(O(nk^2)\)), maintain a running maximum as \(j\) increases. This brings the per-entry work to \(O(k)\) total, preserving the \(O(nk)\) bound.

Correctness proof strategy: Strong induction on \(i\). The key step: any optimal partition has a last group of length \(j^*\leq k\); its value is at most \(\text{dp}[i-j^*] + j^*\cdot\max(\text{last group})\), which is exactly the candidate considered by our recurrence for that value of \(j\).
