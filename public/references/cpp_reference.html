Memory Management
C++ gives you full control — and full responsibility
Stack vs Heap
Two memory regions
Stack: automatic, fast, limited (~8 MB). Variables declared locally live here. Freed when scope exits. No fragmentation.

Heap: manual (new/delete), slow (OS call), unlimited (RAM). You control lifetime. Fragmentation possible. Leaks if you forget delete.
Pointers
Addresses as values
int* p = &x; — p holds address of x.
*p — dereference: read/write the value at address.
p++ — pointer arithmetic: moves by sizeof(int) bytes.

Null pointer: nullptr (C++11) — always initialize pointers. Dereferencing null = undefined behavior (crash).
References
Aliases — safer than pointers
int& ref = x; — ref is another name for x. Cannot be null, cannot be reseated. Must be initialized on declaration.

void f(int& x) — pass by reference: function can modify the original. No copy made. Preferred over pointers for function parameters.
Smart Pointers
RAII — automatic memory management
unique_ptr: sole owner, freed on scope exit. Zero overhead.
shared_ptr: reference counted, freed when count hits 0. Small overhead.
weak_ptr: non-owning reference to shared_ptr — breaks circular references.

Rule: never use raw new in modern C++.
// Modern C++ memory management
auto ptr = std::make_unique<MyClass>(42);   // heap, auto-freed
auto sp  = std::make_shared<Node>();         // shared ownership

// RAII: resource tied to object lifetime
{
  std::ifstream file("data.txt");           // file opens
}                                               // file auto-closes here
Object-Oriented Programming
Classes, inheritance, and polymorphism in C++
Classes
Data + behavior bundled
Struct with access control. public: accessible anywhere. private: only inside class. protected: class + derived classes.

Constructor: initializes object. Destructor (~Class()): cleanup. Rule of 3/5/0: if you define one, define all.
Inheritance
IS-A relationships
class Dog : public Animal — Dog is an Animal. Inherits public/protected members. Use virtual for functions you want derived classes to override.

Diamond problem: multiple inheritance + shared base → use virtual base classes. Generally avoid multiple inheritance.
Polymorphism
Runtime dispatch via vtable
virtual void speak() — resolved at runtime. Object has a hidden vtable pointer — array of function pointers. Calling a virtual method = indirect jump through vtable.

= 0 makes it pure virtual → abstract class. Always make destructors virtual in base classes.
class Animal {
public:
  virtual void speak() const = 0;  // pure virtual → abstract
  virtual ~Animal() = default;      // always virtual destructor
};

class Dog : public Animal {
public:
  void speak() const override { /* woof */ }  // override keyword: compiler checks
};
STL Containers
The right container makes algorithms trivial — pick based on access patterns
vector<T>
Dynamic array — your default choice
O(1) random access, O(1) amortized push_back, O(n) insert/erase at middle. Contiguous memory — cache-friendly. Doubles capacity on resize.

reserve(n) pre-allocates to avoid copies. emplace_back constructs in-place.
unordered_map<K,V>
Hash map — O(1) lookup
O(1) average insert/find/erase. O(n) worst case. No ordering.

map<K,V> = Red-Black Tree: O(log n) but always sorted. Use unordered_map unless you need sorted iteration or ordered range queries.
priority_queue<T>
Max-heap by default
O(log n) push/pop, O(1) top. Use priority_queue<int, vector<int>, greater<int>> for min-heap.

Essential for Dijkstra's algorithm, scheduling, and any "always process the largest/smallest" pattern.
Iterators + Algorithms
<algorithm> — don't reinvent
sort(v.begin(), v.end()) — O(n log n) introsort.
find(begin, end, val) — linear search.
lower_bound — binary search, first ≥ val.
accumulate — reduce. transform — map.

All work on any container via iterators.
Modern C++ (11/14/17/20)
The language that replaced the old C++ — use these features
C++11
The big rewrite
auto type inference, range-for loops, nullptr, lambda expressions, unique_ptr/shared_ptr, move semantics (&& rvalue refs), constexpr, static_assert, variadic templates, std::thread.
Move Semantics
Steal instead of copy
Rvalue references (T&&) let you "move" resources instead of copying. A moved-from object is left in a valid but unspecified state.

std::move() — casts to rvalue, enables move constructor/assignment. Critical for performance — returning vectors from functions is free (NRVO + move).
Lambdas
Inline anonymous functions
[captures](params) { body }

[=] capture all by value. [&] capture all by reference. [x, &y] mix.

Lambdas are just syntactic sugar for a compiler-generated struct with operator(). Used everywhere with STL algorithms.
C++17 / C++20
Continued evolution
C++17: structured bindings (auto [k,v] = pair), if constexpr, std::optional, std::variant, parallel algorithms, filesystem library.

C++20: Concepts (constrain templates), Ranges (composable views), Coroutines, Modules (replace #include), std::format.
Common Gotchas
Things that compile, run, and silently destroy you
Undefined Behavior
The compiler assumes it never happens
UB includes: null dereference, out-of-bounds access, signed integer overflow, using moved-from objects, reading uninitialized variables. The compiler optimizes assuming UB doesn't occur — this can delete your safety checks. Use -fsanitize=address,undefined.
Object Slicing
Polymorphism killed by value copy
Assigning a derived object to a base type by value cuts off the derived parts.

Animal a = dog; — Dog's extra fields lost, virtual dispatch broken.

Fix: always use pointers or references for polymorphism: Animal& a = dog; or Animal* a = &dog;
Iterator Invalidation
Modifying a container breaks iterators
Adding to a vector may reallocate — all existing iterators, pointers, and references become dangling. erase() invalidates iterators at and after the erased element.

Fix: use the returned iterator from erase(): it = v.erase(it);
History of C++
From Simula to C++23 — 50 years of the language that runs the world
1967
Simula — The Inspiration
Dahl and Nygaard create Simula 67, the first object-oriented language. Introduces classes, objects, and inheritance. Bjarne Stroustrup encounters it as a student and is inspired.
1972
C Language (Ritchie)
Dennis Ritchie at Bell Labs creates C for Unix. Fast, portable, low-level. Becomes the lingua franca of systems programming. C++ is built on top of it — nearly all C is valid C++.
1979–1983
"C with Classes" → C++
Bjarne Stroustrup at Bell Labs adds Simula-style classes to C. Originally called "C with Classes." Renamed C++ in 1983 (++: increment). First compiler: Cfront, which translated C++ to C.
1998
C++98 — First Standard
ISO standardization. Introduced the STL (Standard Template Library) — designed by Alexander Stepanov. Templates, exceptions, RTTI. The language that dominated the 2000s.
2003
C++03 — Bug Fix Release
Minor fixes to C++98. No major features. The stagnation era — other languages (Java, Python) started winning mindshare. Criticism of C++ as too complex and unsafe grew.
2011
C++11 — The Renaissance
The biggest change in the language's history. Move semantics, smart pointers, lambdas, auto, range-for, threading. Stroustrup calls it "a different language." Revitalized C++ development globally.
2014 / 2017 / 2020
Continuous Evolution
C++14 (generic lambdas, relaxed constexpr), C++17 (structured bindings, parallel algorithms, optional/variant), C++20 (concepts, ranges, modules, coroutines). Now on a 3-year release cycle. C++23 adds more standard library quality-of-life features.
2015–present
Rust Challenge
Mozilla creates Rust as a memory-safe systems language. NSA, CISA, and White House recommend moving away from C/C++ for new systems code. C++ community responds with profiles and safety guidelines. The debate over C++'s future is ongoing.
