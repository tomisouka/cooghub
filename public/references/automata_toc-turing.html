The Turing Machine

7-TUPLE · INFINITE TAPE · READ/WRITE HEAD · CONFIGURATIONS

model
Definition — 7-tuple (Q, Σ, Γ, δ, q₀, q_accept, q_reject)
A Turing Machine is a 7-tuple (Q, Σ, Γ, δ, q₀, q_accept, q_reject):

Q — finite set of states  ·  Σ — input alphabet (⊔ ∉ Σ)  ·  Γ — tape alphabet (Σ ⊂ Γ, ⊔ ∈ Γ)
δ: Q × Γ → Q × Γ × {L, R} — transition: read symbol, write symbol, move head
q₀ — start state  ·  q_accept — accept state  ·  q_reject — reject state
Tape alphabet
SYMPLAIN ENGLISHNAMEMEANING
Σinput symbolsInput alphabetSymbols on the input tape. ⊔ ∉ Σ.
Γtape symbolsTape alphabetEverything the TM can write. Σ ⊂ Γ, ⊔ ∈ Γ.
⊔blankBlank symbolFills all tape cells beyond the input. ⊔ ∈ Γ \ Σ.
L, Rmove directionHead movementEach transition specifies which way the head moves next.
DFA vs. TM — key differences

DFA / NFA

  • Read-only, strictly left-to-right
  • Halts when input runs out
  • No scratch space
  • Always halts

Turing Machine

  • Read and write on tape
  • Head moves freely left or right
  • Tape is infinite (⊔ beyond input)
  • May loop — not guaranteed to halt
Church-Turing Thesis: Every effectively computable function can be computed by a Turing Machine. TMs are the formal definition of what an "algorithm" is.
Tape & Head — visual model one read/write head · infinite blank tape · current state
Basic TM tape — head reading "1" at position 4 · machine in state q₃
One step: δ(q, a) = (r, b, L/R) means — in state q reading symbol a: write b, move head left or right, enter state r.
Configurations & Three Outcomes uqv notation · accept · reject · loop
A configuration is written uqv where u = tape left of head, q = current state, v = tape from head right. The TM starts in q₀w. Configuration C₁ yields C₂ if one step takes C₁ to C₂.

Variants & Combining Turing Machines

MULTI-TAPE · NONDETERMINISTIC · ENUMERATORS · ALL EQUIVALENT

variants
Multitape Turing Machine k tapes · k heads · equivalent to standard TM
A multitape TM has k tapes each with its own independent read/write head. The transition function becomes δ: Q × Γᵏ → Q × Γᵏ × {L,R}ᵏ — it reads one symbol from each tape, writes one symbol to each tape, and moves each head independently.
Tape diagram — 3-tape TM
Each tape has its own head · all heads move independently each step
Equivalence theorem: Every multitape TM has an equivalent single-tape TM.

Proof sketch: Simulate all k tapes on one tape by interleaving their contents separated by a delimiter #. Use a special "dotted" symbol to track each virtual head position. The single-tape TM makes multiple passes to simulate one multitape step. Time overhead is at most O(t²) for a t-step simulation.
Why it matters: Multitape TMs are much easier to program (use tape 2 as a counter, tape 3 as a stack, etc.), but they don't add computational power. Any algorithm describable with multiple tapes can be done with one.
Nondeterministic Turing Machine (NTM) branching computation · accept if ANY branch accepts
A nondeterministic TM has transition function δ: Q × Γ → 𝒫(Q × Γ × {L,R}) — at each step, multiple transitions may apply. The NTM accepts if any branch of the computation tree accepts. Think of it as exploring all branches in parallel.
Computation tree — NTM branching
NTM explores all branches simultaneously · accepts if any path reaches q_accept
Equivalence theorem: Every NTM has an equivalent deterministic TM.

Proof sketch: Simulate the NTM's computation tree using BFS on a 3-tape DTM: tape 1 = input, tape 2 = current node address (sequence of branch choices), tape 3 = simulation scratch. For each address, follow that branch path from the root. Accept if any simulated branch accepts. Reject only if all branches reject or loop (BFS ensures we find accepting branches if they exist).
Key insight: Nondeterminism does not add computational power to TMs (unlike for finite automata where NFA = DFA). An NTM may be exponentially faster, but it cannot decide languages that a DTM cannot — same class.
Enumerators prints strings · generates a language · equivalent to recognizer
An enumerator is a TM with an attached printer. It runs forever, occasionally printing strings. The language of an enumerator E is the set of all strings it eventually prints. No input — it generates rather than decides.
Equivalence theorem: A language is Turing-recognizable ↔ some enumerator enumerates it.

(→) If TM M recognizes L: Enumerate all strings s₁, s₂, s₃, … in lexicographic order. For each i, run M on s₁, s₂, …, sᵢ for i steps each. Print any that accept. This ensures every accepted string is eventually printed.

(←) If enumerator E enumerates L: On input w, run E; accept if w is ever printed.
Why the naive approach fails: You can't run M on s₁ to completion before moving to s₂ — M might loop on s₁ forever. The dovetailing trick (run all strings for i steps in round i) avoids this.

Bottom line: All reasonable variations on the TM model compute the same set of functions. This robustness is part of why the Church-Turing Thesis is so compelling — the definition of "computable" doesn't depend on the exact model.

Undecidability & The Halting Problem

A_TM · DIAGONALIZATION · HALT_TM · PROOF BY CONTRADICTION

undecidable
A_TM is Undecidable recognizable but not decidable · diagonalization
A_TM = {⟨M, w⟩ | M is a TM and M accepts w}

A_TM is Turing-recognizable: the Universal TM U simulates M on w and accepts if M accepts. But A_TM is not decidable — no TM can always halt and correctly decide. Proof is by diagonalization.
Diagonalization proof
A_TM is undecidableproof by contradiction · assume H decides A_TM
1Assume for contradiction: TM H decides A_TM.
2Construct TM D: on input ⟨M⟩ (the encoding of any TM M):
3Run H on ⟨M, ⟨M⟩⟩ ▷ ask "does M accept its own description?"
4if H accepts → D rejects   if H rejects → D accepts ▷ do opposite
5Now ask: what does D do on input ⟨D⟩?
6D accepts ⟨D⟩ ↔ H says D rejects ⟨D⟩ ↔ D does not accept ⟨D⟩
7D rejects ⟨D⟩ ↔ H says D accepts ⟨D⟩ ↔ D accepts ⟨D⟩
8Both cases give contradictions → H cannot exist → A_TM is undecidable. □
Diagonalization — visual
Cell (i,j) = "does Mᵢ accept ⟨Mⱼ⟩?" · D inverts the diagonal → differs from every Mᵢ
HALT_TM = {⟨M,w⟩ | M halts on w} is also undecidable. If HALT_TM were decidable by R: first run R on ⟨M,w⟩ — if M loops, reject. If M halts, simulate. This decides A_TM — contradiction.

Reductions

MAPPING REDUCIBILITY · A ≤ₘ B · RICE'S THEOREM

reductions
Mapping Reducibility A ≤ₘ B via computable f · hardness flows upward
Language A is mapping reducible to B, written A ≤ₘ B, if there exists a computable function f: Σ* → Σ* such that for every w:

w ∈ A  ↔  f(w) ∈ B

If A ≤ₘ B and B is decidable, then A is decidable. Contrapositive: if A ≤ₘ B and A is undecidable, then B is undecidable.
Reduction proof template
Prove A is undecidable via B ≤ₘ AB already known undecidable
1Assume for contradiction: TM M_A decides A.
2Construct decider M_B for B: on input w:
3Compute f(w) ▷ the computable reduction function
4Run M_A on f(w) and output its answer
5M_B decides B. But B is undecidable → contradiction → A is undecidable. □
Common undecidable languages (all reduce from A_TM)
LANGUAGEPLAIN ENGLISHREDUCTIONNOTES
HALT_TMdoes M halt on w?A_TM ≤ₘ HALT_TMDeciding halting implies deciding acceptance.
E_TMis L(M) empty?A_TM ≤ₘ E_TMBuild M′ accepting only w; if E_TM says empty, M rejected w.
EQ_TMsame language?E_TM ≤ₘ EQ_TMNot recognizable in either direction.
REGULAR_TMis L(M) regular?A_TM ≤ₘ REGULAR_TMSpecial case of Rice's Theorem.
Rice's Theorem: Every non-trivial property of the language of a TM is undecidable. Non-trivial means the property holds for some TMs and fails for others. This covers virtually every interesting question about what a TM computes: emptiness, regularity, finiteness, containment, etc.

Variants & Combining Turing Machines

Multi-tape · NTM · Enumerators · All equivalent

Multitape TM

k tapes · k independent heads · equivalent to 1-tape
Has k tapes each with its own head. δ: Q × Γᵏ → Q × Γᵏ × {L,R}ᵏ — reads from all tapes, writes to all, moves each head. Far easier to program (use tape 2 as a counter, tape 3 as scratch), but no extra computational power.
Simulation — multitape → single tape
Interleave k tapes on one tape separated by # · dotted symbols track virtual head positions
Simulating a k-tape TM running in time t on a single-tape TM requires O(t²) steps. Overhead is polynomial — decidability is preserved.

Nondeterministic TM (NTM)

branching · accept if any branch accepts · equivalent to DTM
δ: Q × Γ → 𝒫(Q × Γ × {L,R}) — multiple transitions may fire. NTM accepts if any branch of its computation tree accepts. Equivalent to standard TM — same languages, potentially exponentially faster.
Simulation — NTM → DTM via BFS
Use a 3-tape DTM: tape 1 = original input (never changes), tape 2 = current branch address (sequence of choices at each nondeterministic step), tape 3 = scratch for simulating that branch. Enumerate all addresses in BFS order. Accept if any simulation accepts. The BFS ordering ensures no branch is starved — even if some branches loop, accepting branches will eventually be found.
Unlike for DFAs, nondeterminism doesn't add power to TMs — it only adds speed. NTMs and DTMs recognize exactly the same class of languages.

Enumerators

generates strings · prints rather than decides · equivalent to recognizer
A TM with a printer attached. Runs forever, printing strings on demand. L(E) = all strings it ever prints. No input needed.

Equivalence: L is Turing-recognizable ↔ some enumerator enumerates L.

Key trick — dovetailing: to avoid looping on s₁ forever, run all strings for i steps in round i. Round 1: run M on s₁ for 1 step. Round 2: run M on s₁ and s₂ for 2 steps each. Round i: run M on s₁…sᵢ for i steps each. Print any that accept.
The dovetailing trick is used throughout computability theory whenever you need to run infinitely many TMs "simultaneously" without looping.

Language Classes

Recognizable · Decidable · Hierarchy

Decidable vs. Recognizable

decidable ⊊ recognizable ⊊ all languages

Decidable (Recursive)

  • ∃ TM that always halts
  • Accepts iff w ∈ L
  • Rejects iff w ∉ L
  • Never loops — guaranteed answer

Recognizable (r.e.)

  • ∃ TM that accepts if w ∈ L
  • May loop if w ∉ L
  • You can never be sure it won't halt
  • Decidable ⊊ Recognizable
Key theorem: L is decidable ↔ both L and L̄ are Turing-recognizable. Run both recognizers in parallel (dovetail) — if L-recognizer accepts, accept; if L̄-recognizer accepts, reject.

Undecidability & Halting Problem

A_TM · diagonalization · HALT_TM

A_TM is Undecidable

recognizable but not decidable · diagonalization
A_TM = {⟨M, w⟩ | M is a TM and M accepts w}

Recognizable (universal TM simulates M on w). Not decidable — proved by constructing TM D that inverts whatever decider H predicts, then applying D to itself.
Diagonalizationassume H decides A_TM → contradiction
1Build D: on input ⟨M⟩, run H on ⟨M, ⟨M⟩⟩.
2if H accepts → D rejects.  if H rejects → D accepts.
3Run D on ⟨D⟩: D accepts ↔ D rejects. Contradiction. □
HALT_TM = {⟨M,w⟩ | M halts on w} is undecidable. If HALT_TM decidable: check if M halts, then simulate — decides A_TM. Contradiction.

Mapping Reducibility

A ≤ₘ B · hardness flows upward
A ≤ₘ B if ∃ computable f with w ∈ A ↔ f(w) ∈ B. To prove A undecidable: show known-undecidable B ≤ₘ A. If A were decidable, composing with f would decide B — contradiction.
Reduction templateB ≤ₘ A · B undecidable → A undecidable
1Assume M_A decides A. Build M_B on input w:
2Compute f(w). Run M_A on f(w). Output result.
3M_B decides B. B undecidable → contradiction → A undecidable. □
Rice's Theorem: Any non-trivial semantic property of L(M) is undecidable. Non-trivial = holds for some TMs, fails for others. Covers emptiness, regularity, finiteness — essentially everything interesting about what a TM computes.
