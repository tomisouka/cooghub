Basics & Structure

Every Java program lives inside a class. Execution starts at public static void main(String[] args). Source files are .java; the compiler produces .class bytecode run on the JVM.

// Hello World public class HelloWorld { public static void main(String[] args) { System.out.println("Hello, World!"); } }

Control Flow

If / Else

if (score >= 90) { grade = "A"; } else if (score >= 80) { grade = "B"; } else { grade = "C"; }

Switch (Classic & Enhanced)

// Classic switch (Java 1+) switch (day) { case "MON": System.out.println("Monday"); break; case "FRI": System.out.println("Friday"); break; default: System.out.println("Other"); } // Enhanced switch expression (Java 14+) String label = switch (day) { case "MON", "TUE", "WED" -> "Weekday"; case "SAT", "SUN" -> "Weekend"; default -> "Unknown"; };

Loops

// For loop for (int i = 0; i < 5; i++) { ... } // Enhanced for (for-each) for (String name : names) { ... } // While loop while (x > 0) { x--; } // Do-while (runs at least once) do { input = scanner.nextLine(); } while (input.isEmpty()); // break & continue for (int i = 0; i < 10; i++) { if (i == 5) break; // exit loop entirely if (i % 2 == 0) continue; // skip even numbers System.out.println(i); }

Pattern Matching (Java 16+)

// instanceof pattern matching if (shape instanceof Circle c) { System.out.println("Radius: " + c.radius()); } // Switch with patterns (Java 21+) String result = switch (obj) { case Integer i -> "int: " + i; case String s -> "str: " + s; case null -> "null"; default -> "other"; };

Methods

Methods in Java must live inside a class. They can be instance methods (need an object) or static methods (called on the class itself).

Method Anatomy

// modifier returnType name(params) throws? public static int add(int a, int b) { return a + b; } // Void method — returns nothing public void greet(String name) { System.out.println("Hello, " + name); } // Variable arguments (varargs) public int sum(int... nums) { int total = 0; for (int n : nums) total += n; return total; }

Method Features

FeaturePlain EnglishNotes
Overloadingsame name, different paramsadd(int,int) and add(double,double) can coexist
Overridingreplace parent's versionMust match signature; use @Override annotation
varargsflexible argument countString... args — must be last parameter
Recursionmethod calls itselfMust have a base case to avoid StackOverflowError
static methodsno object neededMath.sqrt(16) — called on the class

Common Math Methods

Math.abs(-5) // 5 — absolute value Math.max(3, 7) // 7 — maximum Math.min(3, 7) // 3 — minimum Math.pow(2, 10) // 1024.0 — power Math.sqrt(16) // 4.0 — square root Math.round(3.6) // 4 — round to nearest int Math.random() // 0.0 to 0.999... random double

Classes & OOP

Java is built around four OOP pillars: Encapsulation, Inheritance, Polymorphism, and Abstraction.

Class Anatomy

public class Animal { // Fields (instance variables) private String name; private int age; // Constructor public Animal(String name, int age) { this.name = name; this.age = age; } // Getter / Setter (Encapsulation) public String getName() { return name; } public void setName(String name) { this.name = name; } // Instance method public void speak() { System.out.println(name + " makes a sound."); } // Static method public static Animal createDefault() { return new Animal("Unknown", 0); } // toString override @Override public String toString() { return "Animal{name=" + name + ", age=" + age + "}"; } }

Inheritance

public class Dog extends Animal { private String breed; public Dog(String name, int age, String breed) { super(name, age); // call parent constructor this.breed = breed; } @Override public void speak() { System.out.println(getName() + " barks!"); } }

Interfaces & Abstract Classes

implementsfulfill interfaceA class can implement multiple interfaces
extendsinherit fromA class can extend only one class (single inheritance)
@Overridereplacing parent methodAnnotation — compiler errors if not actually overriding
sealedrestrict subclassesJava 17+: sealed class Shape permits Circle, Square

Records (Java 16+)

Generics

Generics let you write type-safe, reusable code that works with any object type. The type is specified at compile time, eliminating casts and catching type errors early.

Generic Classes & Methods

// Generic class — T is a type placeholder public class Box<T> { private T value; public Box(T value) { this.value = value; } public T get() { return value; } } Box<String> s = new Box<>("hello"); Box<Integer> n = new Box<>(42); // Generic method public <T extends Comparable<T>> T max(T a, T b) { return a.compareTo(b) >= 0 ? a : b; }

Wildcards

SyntaxPlain EnglishUse When

Exceptions

Java exceptions fall into two categories: checked (must declare or catch) and unchecked (RuntimeException — optional). All exceptions extend Throwable.

Exception Hierarchy

TypePlain EnglishExamples
Errorunrecoverable JVM problemOutOfMemoryError, StackOverflowError
RuntimeExceptionprogrammer mistake (unchecked)NullPointerException, ArrayIndexOutOfBoundsException, ClassCastException
Checked Exceptionexternal failures (must handle)IOException, SQLException, FileNotFoundException

Try-Catch-Finally

try { int result = 10 / 0; // throws ArithmeticException } catch (ArithmeticException e) { System.out.println("Division by zero: " + e.getMessage()); } catch (Exception e) { System.out.println("Generic: " + e); // broader catch } finally { System.out.println("Always runs — cleanup here"); } // Multi-catch (Java 7+) try { ... } catch (IOException | SQLException e) { ... } // Try-with-resources (auto-closes) try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) { String line = br.readLine(); }

Custom Exceptions

// Checked: extend Exception public class InsufficientFundsException extends Exception { public InsufficientFundsException(String msg) { super(msg); } } // Unchecked: extend RuntimeException public class InvalidAgeException extends RuntimeException { public InvalidAgeException(String msg) { super(msg); } } // Throwing throw new InvalidAgeException("Age must be positive");

Concurrency

Java has built-in threading support. Modern Java prefers high-level constructs like ExecutorService, CompletableFuture, and virtual threads over raw Thread management.

Threads

// Option 1: implement Runnable Runnable task = () -> System.out.println("Running!"); Thread t = new Thread(task); t.start(); // Option 2: extend Thread class MyThread extends Thread { public void run() { System.out.println("Thread!"); } } // Option 3: ExecutorService (preferred) import java.util.concurrent.*; ExecutorService pool = Executors.newFixedThreadPool(4); pool.submit(() -> System.out.println("Task!")); pool.shutdown();

Operator Precedence

Higher numbers = evaluated first. When in doubt, use parentheses.

  1. Postfix: expr++ expr--
  2. Unary: ++expr --expr +expr -expr ~ !
  3. Cast & new: (type)expr new
  4. Multiplicative: * / %
  5. Additive: + -
  6. Shift: << >> >>>
  7. Relational: < > <= >= instanceof
  8. Equality: == !=
  9. Bitwise AND: &
  10. Bitwise XOR: ^
  11. Bitwise OR: |
  12. Logical AND: &&
  13. Logical OR: ||
  14. Ternary: ? :
  15. Assignment: = += -= *= /= %= &= |= ^= <<= >>=

Pro Tips

  • == vs equalsNever use == to compare Strings or objects — it checks reference equality. Use .equals() for value equality. "hello" == "hello" may be true by coincidence (string pool) but is never reliable.
  • NullPointerExceptionJava's most common runtime error. Use Objects.requireNonNull(), Optional, or null checks. Java 14+ gives helpful NPE messages telling you exactly what was null.
  • StringBuilderString concatenation in a loop (str += x) creates a new object each iteration. Use StringBuilder for O(n) instead of O(n²) performance.
  • Interface firstProgram to interfaces: List<String> list = new ArrayList<>() not ArrayList<String> list = .... This lets you swap implementations easily.
  • try-with-resourcesAny class implementing AutoCloseable (streams, connections, readers) should be opened in a try(...) block so it's closed automatically even on exception.
  • final & immutabilityPrefer final fields and immutable objects (like records). Immutable objects are inherently thread-safe and easier to reason about.
  • checked vs uncheckedUse checked exceptions for recoverable conditions callers should handle (e.g., IOException). Use unchecked (RuntimeException) for programming errors (e.g., invalid arguments).
  • streams vs loopsStreams are expressive but add overhead. Use them for clarity on moderate-sized data. For tight performance-critical loops, traditional for loops are often faster.
  • hashCode + equalsIf you override equals(), you must also override hashCode(). Violating this contract breaks HashMap and HashSet.
  • prefer recordsFor simple data-holding classes, use record (Java 16+) instead of writing boilerplate constructors, getters, equals, and toString by hand.
