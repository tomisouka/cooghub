TypeScript ⊃ JavaScript

TypeScript is a strict superset of JavaScript. Every valid .js file is also a valid .ts file. TypeScript adds a type layer on top — that layer is entirely erased at compile time, producing plain JavaScript that runs in any browser or Node.js environment.

Key insight: TypeScript has zero runtime — it only exists during development. The types you write are checked by the compiler, then stripped out. What actually runs is plain JavaScript.

The Relationship

// This is valid JavaScript — and also valid TypeScript const greet = (name) => "Hello, " + name; // This is TypeScript — adds a type annotation const greet = (name: string): string => "Hello, " + name; // ^^^^^^ ^^^^^^ ← TS only, erased at compile time // After tsc compiles it, you get back: const greet = (name) => "Hello, " + name; // Identical to the JS — types are gone!

Basics & Variables

Remember: var, let, const, and all variable scoping rules come from JavaScript. TypeScript simply adds type annotations on top.

Variable Declarations

JS
// No types — inferred at runtime let count = 0; const name = "Alice"; var legacy = true; // avoid var // Reassign freely (no type check) count = "oops"; // allowed in JS!
TS
// Types — checked at compile time let count: number = 0; const name: string = "Alice"; // Type inferred — no annotation needed let score = 42; // TypeScript infers: number // Reassign blocked if wrong type count = "oops"; // ❌ Error: string not assignable to number

Type System

TypeScript's type system lives entirely at compile time. All annotations are TypeScript-only and are erased before any JavaScript runs.

Core Type Annotations TS

// Primitives let n: number; let s: string; let b: boolean; // Arrays let nums: number[] = [1, 2, 3]; let strs: Array<string> = ["a", "b"]; // generic form // Tuples — fixed-length, typed array let point: [number, number] = [10, 20]; let entry: [string, number] = ["age", 30]; // Object literal type let user: { name: string; age: number } = { name: "Alice", age: 30 }; // Union — one of these types let id: number | string = 42; id = "abc"; // also valid // Intersection — must satisfy both type AdminUser = User & Admin; // Literal types — exact value let direction: "north" | "south" | "east" | "west" = "north"; let statusCode: 200 | 400 | 404 | 500 = 200; // Optional property let config: { timeout?: number; retries: number } = { retries: 3 }; // Readonly let point: { readonly x: number; readonly y: number } = { x: 0, y: 0 }; // Type assertion (you know better than TS) const el = document.getElementById("btn") as HTMLButtonElement;

Interfaces & Type Aliases

Both define the shape of objects. interfaces are extendable and best for objects/classes. type aliases are more flexible — they can describe unions, primitives, and computed types too.

Interface TS

interface User { id: number; name: string; email?: string; // optional property readonly createdAt: Date; // can't be changed after creation } // Extending interfaces interface Admin extends User { role: "admin" | "superadmin"; permissions: string[]; } // Interfaces can be merged (declaration merging) interface Window { myCustomProp: string; // extends the global Window type } // Implementing an interface in a class class UserService implements User { id = 1; name = "Alice"; }

Type Aliases TS

// Object shape (like interface) type Point = { x: number; y: number }; // Union type type ID = number | string; type Status = "active" | "inactive" | "pending"; // Intersection type type AdminUser = User & { permissions: string[] }; // Tuple type Pair = [string, number]; // Function signature type Handler = (event: MouseEvent) => void; // Generic type alias type Maybe<T> = T | null | undefined; type Result<T, E> = { ok: true; value: T } | { ok: false; error: E };

Functions

JS foundation: Function declarations, arrow functions, default params, rest params, and destructuring all come from JavaScript. TypeScript adds parameter and return type annotations.

Function Syntax

JS
// Named function function add(a, b) { return a + b; } // Arrow function const double = (x) => x * 2; // Default parameter function greet(name = "World") { return "Hello, " + name; } // Rest parameters function sum(...nums) { return nums.reduce((a, b) => a + b, 0); }
TS
// Named function — typed params + return function add(a: number, b: number): number { return a + b; } // Arrow function with types const double = (x: number): number => x * 2; // Default parameter function greet(name: string = "World"): string { return "Hello, " + name; } // Rest parameters function sum(...nums: number[]): number { return nums.reduce((a, b) => a + b, 0); }

TypeScript Function Features TS

// Optional parameter (must come after required) function log(msg: string, level?: "info" | "warn" | "error"): void { console.log(`[${level ?? "info"}] ${msg}`); } // Function overloads — multiple signatures, one implementation function format(value: string): string; function format(value: number, decimals: number): string; function format(value: string | number, decimals = 2): string { if (typeof value === "string") return value.trim(); return value.toFixed(decimals); } // Function type type Predicate<T> = (item: T) => boolean; const isEven: Predicate<number> = (n) => n % 2 === 0; // Void vs never function log(msg: string): void { console.log(msg); } // returns undefined function fail(msg: string): never { throw new Error(msg); } // never returns

Destructuring & Spread JS

// Object destructuring — JS feature, TS adds types const { name, age }: { name: string; age: number } = user; const { name, age = 0 } = user; // default value // Array destructuring const [first, second, ...rest]: number[] = [1, 2, 3, 4, 5]; // Spread — copy/merge objects and arrays const merged = { ...defaults, ...overrides }; const combined = [...arr1, ...arr2]; // Function param destructuring function greet({ name, age }: User): string { return `${name} is ${age}`; }

Classes & OOP

JS foundation: Classes, constructors, inheritance (extends), super(), static methods, and getters/setters are all JS features from ES6+. TypeScript adds access modifiers, implements, abstract classes, and parameter properties.

Class Anatomy

JS
class Animal { // No field declarations needed constructor(name, sound) { this.name = name; this.sound = sound; } speak() { return `${this.name}: ${this.sound}`; } static create(name) { return new Animal(name, "..."); } get label() { return this.name.toUpperCase(); } }
TS
class Animal { // Typed field declarations name: string; private sound: string; // TS only constructor(name: string, sound: string) { this.name = name; this.sound = sound; } speak(): string { return `${this.name}: ${this.sound}`; } static create(name: string): Animal { return new Animal(name, "..."); } get label(): string { return this.name.toUpperCase(); } }

TypeScript-Only Class Features TS

// Parameter properties — shorthand to declare AND assign in constructor class Point { constructor( public x: number, // declares this.x and assigns public y: number, private label?: string // optional private field ) {} } // Equivalent to: declaring fields + assigning in constructor body // Access modifiers class BankAccount { public owner: string; // anyone can access private balance: number; // class only protected accountNo: string; // class + subclasses readonly id: string; // can't be changed after construction constructor(owner: string, balance: number) { this.owner = owner; this.balance = balance; this.id = crypto.randomUUID(); } } // Abstract class — cannot be instantiated directly abstract class Shape { abstract area(): number; // subclass must implement describe(): string { // concrete method return `Area: ${this.area()}`; } } class Circle extends Shape { constructor(private radius: number) { super(); } area(): number { return Math.PI * this.radius ** 2; } } // Implementing interfaces interface Printable { print(): void; } interface Serializable { serialize(): string; } class Report implements Printable, Serializable { print(): void { console.log(this.serialize()); } serialize(): string { return JSON.stringify(this); } }

Generics

TS Generics let you write code that works with any type while still being type-safe. The type parameter is filled in by the caller. Think of it as a type-level placeholder.

Generic Functions, Classes & Interfaces

// Generic function — T is inferred from argument function identity<T>(value: T): T { return value; } identity(42); // T inferred as number identity("hello"); // T inferred as string // Generic with constraint function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key]; } getProperty({ name: "Alice", age: 30 }, "name"); // → "Alice" // Generic interface interface Repository<T> { findById(id: number): T | null; save(item: T): void; delete(id: number): void; } // Generic class class Stack<T> { private items: T[] = []; push(item: T): void { this.items.push(item); } pop(): T | undefined { return this.items.pop(); } peek(): T | undefined { return this.items[this.items.length - 1]; } } const numStack = new Stack<number>(); numStack.push(1); numStack.push("oops"); // ❌ Error: string not assignable to number

Generic Constraints

// extends — constrain what T can be function longest<T extends { length: number }>(a: T, b: T): T { return a.length >= b.length ? a : b; } longest("hello", "hi"); // string has .length ✅ longest([1,2,3], [1,2]); // array has .length ✅ longest(10, 20); // ❌ number has no .length // Multiple constraints function merge<T extends object, U extends object>(a: T, b: U): T & U { return { ...a, ...b }; } // Default type parameter (TS 2.3+) interface Container<T = string> { value: T; } const box: Container = { value: "hello" }; // T defaults to string

Narrowing & Type Guards

TypeScript tracks which types are possible at each point in your code. When you check a type at runtime (using JavaScript constructs), TypeScript narrows the type in that branch automatically.

JS runtime: All narrowing checks (typeof, instanceof, truthiness, in) are plain JavaScript — they execute at runtime. TypeScript just uses them to understand the type better.

Narrowing Techniques

function process(value: string | number) { // typeof narrowing (JS) — TS narrows type in each branch if (typeof value === "string") { console.log(value.toUpperCase()); // TS knows: string here } else { console.log(value.toFixed(2)); // TS knows: number here } } // instanceof narrowing (JS) function formatError(err: unknown) { if (err instanceof Error) { return err.message; // TS knows: Error here } return String(err); } // in operator narrowing (JS) interface Dog { bark(): void } interface Cat { meow(): void } function speak(pet: Dog | Cat) { if ("bark" in pet) { pet.bark(); // TS knows: Dog here } else { pet.meow(); // TS knows: Cat here } } // Truthiness narrowing (JS) function print(value: string | null | undefined) { if (value) { console.log(value.length); // TS knows: non-null string here } } // Custom type guard (TS) — function that asserts a type function isString(value: unknown): value is string { return typeof value === "string"; } // Discriminated union — TS narrows by a shared literal field type Shape = | { kind: "circle"; radius: number } | { kind: "rect"; width: number; height: number }; function area(s: Shape): number { switch (s.kind) { case "circle": return Math.PI * s.radius ** 2; case "rect": return s.width * s.height; } } // Exhaustiveness check with never function assertNever(x: never): never { throw new Error("Unhandled case: " + x); }

Modules & Imports

JS foundation: ES Modules (import/export) are a JavaScript feature. TypeScript adds the ability to import/export types in addition to values.

Exports & Imports

JS
// Named exports export const PI = 3.14159; export function add(a, b) { return a + b; } export class Vector2 { ... } // Default export export default class App { ... } // Named imports import { PI, add } from "./math.js"; // Default import import App from "./App.js"; // Rename on import import { add as sum } from "./math.js"; // Import everything import * as Math from "./math.js"; Math.add(1, 2);
TS
// Named exports (same as JS + types) export const PI: number = 3.14159; export function add(a: number, b: number): number { ... } export interface Vector { x: number; y: number } // Export types explicitly (TS 3.8+) export type { Vector }; export type { User } from "./types"; // Type-only import (erased completely) import type { User } from "./types"; // Mixing value and type imports import { createUser, type User } from "./user"; // Re-export export { add, PI } from "./math"; export * from "./helpers";

Async / Promises (JS Runtime)

All JS: Promises, async/await, fetch, setTimeout, and the event loop are JavaScript runtime features. TypeScript adds return type annotations and better error typing. Nothing here is erased by the compiler.

Promises & Async/Await

JS
// Promise chain fetch("/api/user") .then(res => res.json()) .then(data => console.log(data)) .catch(err => console.error(err)); // async/await async function getUser(id) { try { const res = await fetch(`/api/user/${id}`); const data = await res.json(); return data; } catch (err) { console.error(err); } } // Parallel const [a, b] = await Promise.all([ fetchUser(1), fetchUser(2), ]);
TS
// Promise with typed result function fetchUser(id: number): Promise<User> { return fetch(`/api/user/${id}`).then(r => r.json()); } // async function — return type is always Promise<T> async function getUser(id: number): Promise<User | null> { try { const res = await fetch(`/api/user/${id}`); if (!res.ok) return null; return await res.json() as User; // type assertion } catch (err: unknown) { // err typed as unknown if (err instanceof Error) console.error(err.message); return null; } } // Parallel with typed results const [user, posts]: [User, Post[]] = await Promise.all([ fetchUser(1), fetchPosts(1), ]);

Common Async Patterns

JS Runtime Concepts

These are JS features that TypeScript simply types — they exist at runtime and are never erased by the compiler.

Closures & Scope JS

// Closure: inner function remembers outer scope function makeCounter() { let count = 0; // captured by closure return { increment: () => ++count, decrement: () => --count, value: () => count, }; } const counter = makeCounter(); counter.increment(); // 1 counter.increment(); // 2 counter.value(); // 2

Prototypes & this JS

// 'this' depends on how function is CALLED, not defined const obj = { name: "Alice", greet() { return "Hi, " + this.name; }, // this = obj ✅ greetArrow: () => "Hi, " + this?.name, // this = outer scope ❌ }; // Arrow functions capture 'this' from enclosing scope class Timer { count = 0; start() { setInterval(() => { this.count++; // 'this' = Timer instance ✅ (arrow captures it) }, 1000); } } // TypeScript can type 'this' explicitly function greet(this: User): string { return `Hello, ${this.name}`; }

Iterators & Generators JS

// Generator function — yields values lazily function* range(start: number, end: number): Generator<number> { for (let i = start; i < end; i++) yield i; } for (const n of range(0, 5)) console.log(n); // 0 1 2 3 4 // Iterable object — works with for...of, spread, destructuring const iterable = { [Symbol.iterator](): Iterator<number> { let n = 0; return { next: () => ({ value: n++, done: n > 3 }) }; } }; // Async generator async function* streamLines(url: string): AsyncGenerator<string> { const res = await fetch(url); for await (const chunk of res.body!) yield chunk.toString(); }

Proxies & Reflect JS

Pro Tips

  • avoid anyUsing any turns off TypeScript for that value. Use unknown instead — it forces you to narrow the type before using it. Reserve any for true escape hatches like migrating old JS code.
  • == vs ===JS Always use === (strict equality) not == (loose equality). Loose equality coerces types: 0 == false is true, "1" == 1 is true. TypeScript can't always catch this — train the habit.
  • type vs interfacePrefer interface for object shapes that represent things (User, Config, Request) — they support declaration merging and read more naturally. Use type for unions, intersections, mapped types, and anything non-object.
  • as constconst colors = ["red", "green", "blue"] as const makes TypeScript infer the narrowest possible type — readonly ["red", "green", "blue"] instead of string[]. Essential for deriving union types from arrays.
  • optional chainingJS user?.address?.city short-circuits to undefined instead of throwing if any link is null/undefined. Combine with ?? (nullish coalescing) for defaults: user?.name ?? "Guest".
    • non-null assertionel! tells TypeScript "trust me, this isn't null." It's a compile-time lie — if you're wrong, you get a runtime crash. Prefer a real null check or if (!el) return.
  • discriminated unionsInstead of optional properties ({ type: "circle", radius?: number }), use discriminated unions: { type: "circle", radius: number } | { type: "rect", w: number; h: number }. TypeScript's switch narrowing then gives you perfect type safety.
  • var hoistingJS var declarations are hoisted to the top of their function. That means you can reference a var before its line — it's undefined, not an error. This is one of the main reasons let and const replaced var.
  • satisfies operatorconst config = { ... } satisfies Config (TS 4.9+) validates that a value matches a type without widening it. You keep the narrow inferred type for use in the file, but TS checks the shape. Better than : Config for local objects.
  • strict modeAlways enable "strict": true in tsconfig. It catches null errors, implicit any, and dozens of subtle bugs. Starting without it is technical debt — retrofitting strict mode onto a large codebase is painful.
