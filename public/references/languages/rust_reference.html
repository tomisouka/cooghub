Basics & Structure

Rust programs start with fn main(). Files end in .rs; packages are called crates, organized by Cargo. Rust enforces memory safety at compile time — no garbage collector, no runtime.

// Hello World fn main() { println!("Hello, {}!", "World"); }

Ownership

Ownership is Rust's most unique feature — a set of rules that the compiler enforces to manage memory without a garbage collector. Violating these rules causes a compile error, not a runtime crash.

The Three Rules of Ownership:
1. Each value in Rust has exactly one owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the value is dropped (memory freed).
// Move semantics — ownership transfers let s1 = String::from("hello"); let s2 = s1; // s1 is MOVED to s2. s1 is no longer valid! // println!("{}", s1); // ← COMPILE ERROR: value used after move // Clone — deep copy when you need two owners let s1 = String::from("hello"); let s2 = s1.clone(); // s1 AND s2 are valid; heap data is copied // Copy types — stack-only, cheap to copy, no move semantics let x: i32 = 5; let y = x; // x is COPIED, not moved. Both x and y are valid. // Copy types: all integers, floats, bool, char, tuples of Copy types // Ownership and functions fn takes_ownership(s: String) { // s is moved in println!("{}", s); } // s is dropped here let s = String::from("hello"); takes_ownership(s); // s is moved — no longer valid here // println!("{}", s); // ← COMPILE ERROR

The Drop Trait

When a value goes out of scope, Rust automatically calls its drop method. This is how memory, file handles, and other resources are automatically released — this is RAII in Rust.

Borrowing & Lifetimes

Instead of transferring ownership, you can borrow a reference to a value. The borrow checker ensures references are always valid.

The Borrowing Rules:
At any given time, you can have either:
  • One mutable reference (&mut T), or
  • Any number of immutable references (&T)
but never both at the same time. References must always be valid.
// Immutable borrow — read-only, many allowed at once let s = String::from("hello"); let r1 = &s; // borrow s let r2 = &s; // borrow again — fine! println!("{} {}", r1, r2); // s still valid here // Mutable borrow — only ONE at a time let mut s = String::from("hello"); let r = &mut s; // mutable borrow r.push_str(" world"); // let r2 = &mut s; // ← COMPILE ERROR: cannot borrow twice as mutable // Dangling references are impossible in Rust // fn dangle() -> &String { // let s = String::from("hi"); // s created // &s // ← COMPILE ERROR: s dropped here! // }

Lifetimes

Lifetimes are how Rust tracks how long references are valid. The compiler infers most lifetimes automatically — you only need to annotate when it can't figure it out (usually with multiple references in function signatures).

// Lifetime annotation: 'a means "reference lives at least as long as 'a" fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { if x.len() > y.len() { x } else { y } } // Both inputs and the output must live at least as long as 'a // 'static lifetime — lives for the entire program duration let s: &'static str = "I live forever"; // Lifetime in structs struct Excerpt<'a> { part: &'a str, // struct cannot outlive the string it borrows }

Control Flow

In Rust, everything is an expression — if, match, loop, and blocks all return values. The last expression in a block is its value (no semicolon!).

// if is an expression let abs = if x < 0 { -x } else { x }; // match — exhaustive pattern matching let msg = match score { 90..=100 => "A", 80..=89 => "B", 70..=79 => "C", _ => "F", // wildcard — must cover all cases }; // Matching on enum match coin { Coin::Penny => 1, Coin::Nickel => 5, Coin::Quarter(state) => { println!("{:?}", state); 25 } } // if let — match one pattern, ignore the rest if let Some(val) = maybe_value { println!("Got: {}", val); } // while let — loop while pattern matches while let Some(top) = stack.pop() { println!("{}", top); } // loop — infinite, can return a value let result = loop { counter += 1; if counter == 10 { break counter * 2; } }; // for — iterators for i in 0..5 { print!("{} ", i); } // 0 1 2 3 4 for item in &collection { /* borrows */ } for item in collection { /* consumes (moves) */ } // Loop labels for nested break/continue 'outer: for x in 0..5 { for y in 0..5 { if x == y { break 'outer; } } }

Traits

Traits define shared behavior — like interfaces in other languages, but more powerful. A type can implement multiple traits. Trait bounds specify what types a generic can accept.

// Define a trait trait Speak { fn speak(&self) -> String; // required method fn shout(&self) -> String { // default method self.speak().to_uppercase() } } // Implement a trait for a type struct Dog; impl Speak for Dog { fn speak(&self) -> String { String::from("Woof!") } } // Trait bounds — require a type to implement a trait fn make_noise<T: Speak>(animal: &T) { println!("{}", animal.speak()); } fn make_noise(animal: &impl Speak) { // same, shorter syntax } // Multiple trait bounds fn display_and_debug<T: Display + Debug>(val: &T) { } fn display_and_debug<T>(val: &T) where T: Display + Debug { } // where clause // Trait objects — dynamic dispatch, different types at runtime let animals: Vec<Box<dyn Speak>> = vec![Box::new(Dog), Box::new(Cat)]; for a in &animals { println!("{}", a.speak()); }

Generics

Generics enable zero-cost abstractions — code works for any type satisfying the constraints. Unlike dynamic dispatch (dyn Trait), generics are monomorphized at compile time: no runtime overhead.

Memory & Smart Pointers

Rust has no garbage collector and no manual free(). Memory is freed when the owner goes out of scope. Smart pointers extend ownership semantics for special cases.

Error Handling

Rust has no exceptions. Errors are values. Use Result<T, E> for recoverable errors and panic! for unrecoverable ones. The ? operator makes error propagation ergonomic.

// Result<T, E> — either Ok(value) or Err(error) use std::fs; use std::io; fn read_username() -> Result<String, io::Error> { let s = fs::read_to_string("username.txt")?; // ? propagates Err Ok(s) } // Handling results match read_username() { Ok(name) => println!("Hello, {}!", name), Err(e) => eprintln!("Error: {}", e), } // Combinators — transform Result without unwrapping let n: Result<i32, _> = "42".parse(); let doubled = n.map(|x| x * 2); // Ok(84) let val = n.unwrap_or(0); // 42, or 0 on Err let val = n.unwrap_or_else(|_| default()); // ? operator expands to: // match result { Ok(v) => v, Err(e) => return Err(e.into()) } // panic! — unrecoverable; unwinds the stack let v = vec![1, 2, 3]; // v[99]; // ← panics: index out of bounds let x: Option<i32> = None; // x.unwrap(); // ← panics: called unwrap on None x.expect("Expected a value!"); // panics with custom message // Custom error type (with thiserror crate) // #[derive(Debug, thiserror::Error)] // enum AppError { // #[error("IO error: {0}")] IoError(#[from] io::Error), // #[error("Parse failed")] ParseError, // }

Concurrency

Rust's ownership system makes concurrency fearless — the compiler prevents data races at compile time. The Send and Sync marker traits encode thread-safety in the type system.

use std::thread; use std::sync::{Arc, Mutex}; // Spawning threads let handle = thread::spawn(|| { println!("Hello from a thread!"); }); handle.join().unwrap(); // wait for thread to finish // move closure — transfer ownership into thread let v = vec![1, 2, 3]; let handle = thread::spawn(move || { println!("{:?}", v); // v moved into thread }); // Mutex — shared mutable state let counter = Arc::new(Mutex::new(0)); let mut handles = vec![]; for _ in 0..10 { let counter = Arc::clone(&counter); handles.push(thread::spawn(move || { let mut num = counter.lock().unwrap(); *num += 1; })); } for h in handles { h.join().unwrap(); } println!("Result: {}", *counter.lock().unwrap()); // 10 // Message passing with channels use std::sync::mpsc; let (tx, rx) = mpsc::channel(); thread::spawn(move || { tx.send("hello from thread").unwrap(); }); let msg = rx.recv().unwrap(); println!("{}", msg);

Tips & Gotchas

  • semicolonsA line ending with ; is a statement that returns (). A line without ; is an expression that returns its value. This is how implicit returns work in functions.
  • move semanticsTypes that don't implement Copy are moved, not copied, on assignment. After a move, the original variable is unusable. This is checked at compile time, not runtime.
  • String vs &strUse &str for function parameters that just need to read a string — it's more flexible (accepts both &String and string literals). Use String when you need to own or build a string.
  • unwrap in prodAvoid .unwrap() in production code — use ?, .unwrap_or(), or proper error handling. .expect("message") is better when you're certain but want a clear panic message.
  • clone sparinglyReaching for .clone() to fix borrow checker errors often means there's a better design. It's not wrong, but think first: can you restructure to avoid the clone?
  • iter flavors.iter() borrows (&T), .iter_mut() mutably borrows (&mut T), .into_iter() consumes the collection (gives T). For loops on &vec use .iter() implicitly.
  • collect().collect() needs to know what type to collect into — either annotate the variable type or use the turbofish: .collect::<Vec<_>>(). The _ lets the compiler infer the inner type.
  • Box for recursionRecursive types (enum List { Cons(i32, List) }) don't compile because the size is infinite. Wrap the recursive field in Box<> to give it a known pointer size.
  • NLLNon-Lexical Lifetimes (NLL, stable since 2018) mean borrows end as soon as they're last used, not at the end of the block. This makes many "borrow checker fights" a thing of the past.
  • derive DebugAlways add #[derive(Debug)] to your structs and enums during development. It lets you use println!("{:?}", val) for debugging without effort.
  • entry APIDon't do if !map.contains_key(k) { map.insert(k, v) } — use map.entry(k).or_insert(v). It's one lookup instead of two, and avoids borrow checker headaches.
  • panic vs ResultUse panic! for bugs (things that should never happen). Use Result for expected failures (file not found, network error, invalid input). Never use panic for normal control flow.
