Basics & Structure

Every Go file belongs to a package. The main package with a main() function is the program entry point. Go uses static typing, compiles to native binaries, and has a garbage collector. No classes, no inheritance — just types, functions, and interfaces.

package main import "fmt" func main() { fmt.Println("Hello, World!") }

Control Flow

Go has one loop keyword (for), no while/do-while. Switch cases don't fall through by default. Curly braces are always required.

// if — parens not required, braces always required if x > 0 { fmt.Println("positive") } else if x < 0 { fmt.Println("negative") } else { fmt.Println("zero") } // if with init statement — v scoped to the if block if v, err := strconv.Atoi("42"); err == nil { fmt.Println(v) } // switch — no fallthrough by default; cases are NOT exclusive integers switch os { case "darwin": fmt.Println("macOS") case "linux", "freebsd": // multiple values in one case fmt.Println("Unix-like") default: fmt.Println("other") } // switch with no condition — like if-else chain switch { case t.Hour() < 12: fmt.Println("morning") case t.Hour() < 17: fmt.Println("afternoon") default: fmt.Println("evening") } // for — the only loop. Classic form: for i := 0; i < 10; i++ { } // while-style (condition only) for n < 100 { n *= 2 } // infinite loop for { /* break to exit */ } // range — iterate over slice, array, map, string, or channel for i, v := range mySlice { /* index, value */ } for k, v := range myMap { /* key, value */ } for i, ch := range "hello" { /* index, rune */ } for v := range myChan { /* value from channel (blocks until close) */ } for _, v := range mySlice { /* value only (ignore index) */ } // Labels for nested loops outer: for i := 0; i < 5; i++ { for j := 0; j < 5; j++ { if i == j { break outer } } }

07

Functions

Functions are first-class values in Go. They can return multiple values — conventionally used to return a result and an error. Deferred calls run in LIFO order when the function exits.

// Basic function func add(a, b int) int { return a + b } // Multiple return values — very idiomatic Go func divide(a, b float64) (float64, error) { if b == 0 { return 0, fmt.Errorf("division by zero") } return a / b, nil } result, err := divide(10, 2) if err != nil { log.Fatal(err) } // Named return values — useful for documentation; defer can modify them func minMax(arr []int) (min, max int) { min, max = arr[0], arr[0] for _, v := range arr { if v < min { min = v } if v > max { max = v } } return // bare return — returns min and max } // Variadic function func sum(nums ...int) int { total := 0 for _, n := range nums { total += n } return total } sum(1, 2, 3) s := []int{1, 2, 3} sum(s...) // spread slice into variadic // First-class functions and closures apply := func(f func(int) int, x int) int { return f(x) } func makeCounter() func() int { n := 0 return func() int { n++; return n } // closes over n } // defer — runs at function exit, LIFO order func readFile(path string) error { f, err := os.Open(path) if err != nil { return err } defer f.Close() // guaranteed to run, even on early return // ... read f ... return nil } // panic and recover func safeDiv(a, b int) (result int, err error) { defer func() { if r := recover(); r != nil { err = fmt.Errorf("panic: %v", r) } }() return a / b, nil }

Pointers

Go has pointers but no pointer arithmetic. Pointers are simpler than C — you mostly use them to allow functions to mutate a value or to avoid copying large structs.

var x int = 42 p := &x // p is *int — pointer to x fmt.Println(*p) // 42 — dereference *p = 100 // x is now 100 // new — allocate zeroed value, return pointer p2 := new(int) // *int pointing to 0 *p2 = 7 // Pointer to struct — Go auto-dereferences fields type Point struct { X, Y int } p3 := &Point{1, 2} p3.X = 10 // same as (*p3).X = 10 — auto-deref // Pointer method receiver — allows mutation func (pt *Point) Scale(factor int) { pt.X *= factor pt.Y *= factor } // nil pointer — check before dereferencing! var ptr *int // nil if ptr != nil { fmt.Println(*ptr) }
No pointer arithmetic: Go deliberately omits pointer arithmetic. If you need it, you're likely in unsafe territory. Use slices instead of pointer + offset patterns.

Structs & Methods

Go has no classes. Methods are functions with a receiver attached to a type. Composition over inheritance — embed types to reuse behavior.

// Struct definition type Person struct { Name string Age int addr address // unexported field (lowercase) } // Struct literals p1 := Person{Name: "Alice", Age: 30} // named — preferred p2 := Person{"Bob", 25, address{}} // positional — fragile // Methods — value receiver (gets copy) func (p Person) Greet() string { return fmt.Sprintf("Hi, I'm %s", p.Name) } // Methods — pointer receiver (can mutate) func (p *Person) Birthday() { p.Age++ } // Embedding — compose behavior type Employee struct { Person // embedded — Employee inherits Person's methods Company string } e := Employee{Person: Person{Name: "Carol", Age: 28}, Company: "Acme"} e.Greet() // promoted from Person e.Birthday() // Anonymous struct — great for one-off shapes point := struct{ X, Y int }{X: 1, Y: 2} // Struct tags — metadata used by encoding/json, etc. type User struct { ID int `json:"id"` Email string `json:"email,omitempty"` pass string // no tag; unexported — won't be serialized }

Interfaces

Interfaces in Go are satisfied implicitly — a type implements an interface by having the required methods, no declaration needed. This enables duck typing with static safety.

// Define an interface type Animal interface { Sound() string Name() string } // Types implicitly satisfy the interface (no "implements" keyword) type Dog struct{} func (d Dog) Sound() string { return "Woof" } func (d Dog) Name() string { return "Dog" } // Dog now satisfies Animal — no explicit declaration // Use the interface func describe(a Animal) { fmt.Printf("%s says %s\n", a.Name(), a.Sound()) } describe(Dog{}) // Type assertion — extract the concrete type var a Animal = Dog{} d, ok := a.(Dog) // ok = true; d is Dog if !ok { /* a is not a Dog */ } // Type switch — dispatch on concrete type switch v := val.(type) { case int: fmt.Println("int:", v) case string: fmt.Println("string:", v) case Dog: fmt.Println("Dog:", v.Name()) default: fmt.Println("unknown") } // Empty interface — holds any value (pre-generics: any = interface{}) var anything any = 42 anything = "now a string" // Key standard interfaces // error: Error() string // fmt.Stringer: String() string (used by fmt.Println etc.) // io.Reader: Read([]byte) (int, error) // io.Writer: Write([]byte) (int, error) // io.Closer: Close() error

Error Handling

Errors are values in Go — just a type implementing the error interface. There are no exceptions. Functions return errors as the last return value; callers check explicitly.

// The error interface: type error interface { Error() string } // Creating errors err1 := errors.New("something went wrong") err2 := fmt.Errorf("file %s: %w", path, err1) // %w wraps the error // Checking errors result, err := someOperation() if err != nil { return fmt.Errorf("operation failed: %w", err) } // Custom error type type ValidationError struct { Field string Message string } func (e *ValidationError) Error() string { return fmt.Sprintf("%s: %s", e.Field, e.Message) } // errors.Is — check error chain if errors.Is(err, os.ErrNotExist) { fmt.Println("file not found") } // errors.As — extract concrete error type from chain var ve *ValidationError if errors.As(err, &ve) { fmt.Println("invalid field:", ve.Field) } // panic — for unrecoverable programmer errors if len(args) == 0 { panic("args must not be empty") } // recover — catch panics in deferred functions defer func() { if r := recover(); r != nil { log.Printf("recovered: %v", r) } }()
Convention: Always handle errors. The compiler won't force you — but leaving err unchecked is how bugs happen. Use errors.Is / errors.As instead of string comparisons. Wrap errors with %w to preserve the chain.

Goroutines

Goroutines are Go's lightweight threads — not OS threads. Starting one costs just ~2–8KB of stack. The Go runtime multiplexes them onto OS threads. Launch with go; coordinate with channels or sync.

import ( "sync" "time" ) // Launch a goroutine go fmt.Println("concurrent!") // fire and forget go func() { // anonymous goroutine doWork() }() // WaitGroup — wait for multiple goroutines to finish var wg sync.WaitGroup for i := 0; i < 5; i++ { wg.Add(1) go func(id int) { defer wg.Done() fmt.Printf("worker %d done\n", id) }(i) // pass i as arg to avoid closure capture bug! } wg.Wait() // block until all Done() calls received // Mutex — protect shared state var mu sync.Mutex var count int go func() { mu.Lock() defer mu.Unlock() count++ }() // sync.Once — run something exactly once var once sync.Once once.Do(func() { initDB() }) // safe for concurrent calls // sync.Map — concurrent-safe map (for high contention) var m sync.Map m.Store("key", 42) v, ok := m.Load("key")

Channels

"Don't communicate by sharing memory; share memory by communicating." Channels are Go's primary mechanism for goroutine coordination and data transfer.

// Unbuffered channel — sender blocks until receiver is ready ch := make(chan int) go func() { ch <- 42 }() // send (blocks until received) v := <-ch // receive (blocks until sent) // Buffered channel — sender blocks only when buffer is full bch := make(chan string, 3) bch <- "a" // doesn't block (buffer has room) bch <- "b" bch <- "c" // bch <- "d" // would block — buffer full // close — signal no more values; receivers drain then get zero value close(ch) v, ok := <-ch // ok = false means channel closed and drained // Range over channel — receives until closed for v := range ch { fmt.Println(v) } // Directional channels — restrict to send-only or receive-only func producer(out chan<- int) { // send-only for i := 0; i < 5; i++ { out <- i } close(out) } func consumer(in <-chan int) { // receive-only for v := range in { fmt.Println(v) } } // select — wait on multiple channels simultaneously select { case msg := <-ch1: fmt.Println("ch1:", msg) case msg := <-ch2: fmt.Println("ch2:", msg) case ch3 <- "hello": fmt.Println("sent to ch3") case <-time.After(1 * time.Second): fmt.Println("timeout") default: // non-blocking — runs immediately if no case ready fmt.Println("nothing ready") }

Tips & Gotchas

  • unused importsUnused imports and unused variables are compile errors in Go. If you need to import for side effects only, use import _ "pkg/path". Remove unused vars or assign to _.
  • slice sharingSlicing a slice (s[1:3]) doesn't copy — both slices share the underlying array. Mutations through one affect the other. Use copy() to make an independent copy.
  • nil map writeReading from a nil map returns the zero value safely. But writing to a nil map panics. Always initialize: m := make(map[K]V) or use a literal.
  • map key existsDon't test if m["key"] != "" — the zero value could be a valid value. Always use the two-value form: v, ok := m["key"] and check ok.
  • goroutine loop varCapturing a loop variable in a goroutine closure is a classic bug — by the time the goroutine runs, the loop has advanced. Pass i as a parameter: go func(i int) { ... }(i). (Fixed in Go 1.22!)
  • defer + loopsdefer runs when the function exits, not the loop iteration. Don't defer inside hot loops — the deferred calls accumulate. Extract the loop body to a helper function instead.
  • error wrappingWrap errors with fmt.Errorf("context: %w", err). Then use errors.Is and errors.As to inspect the chain. Never compare error strings.
  • value vs pointer receiverUse pointer receivers (*T) when the method needs to modify the struct, or when the struct is large. Be consistent — if any method is pointer, make them all pointer.
  • interface nilA non-nil interface holding a nil pointer is not == nil. var p *MyType = nil; var i MyInterface = p; i == nil is false. This surprises everyone at least once.
  • go fmtRun go fmt religiously. Go has a single canonical style — there's no debate about braces, spacing, or tabs. CI will reject non-formatted code in most serious projects.
  • close channelsOnly the sender should close a channel. Closing a nil channel panics. Sending to a closed channel panics. Use a sync.WaitGroup or a done channel to coordinate shutdown.
  • contextPass context.Context as the first argument to any function that may block, do I/O, or call external services. Never store context in a struct. This enables cancellation and deadline propagation.
