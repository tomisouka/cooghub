Linear Structures
Sequential data — access patterns define which to use
Array
Contiguous Memory Block
Fixed-size, index-based. O(1) random access. Cache-friendly — elements are adjacent in memory. Insertion/deletion at middle is O(n) due to shifting.

Use when: size is known, frequent random access, cache performance matters.
Linked List
Node Chain
Nodes hold data + pointer to next. O(1) insert/delete at head. O(n) access — must traverse. No wasted allocation, but pointer overhead and poor cache locality.

Use when: frequent insert/delete at ends, size unknown.
Stack
LIFO — Last In, First Out
Push and pop only from the top. O(1) push/pop. The call stack is a stack. Used for: undo systems, expression parsing, DFS, balanced parentheses.

push() pop() peek()
Queue
FIFO — First In, First Out
Enqueue at back, dequeue from front. O(1) both ends. Used for: BFS, task scheduling, print queues, message buffers.

Deque: double-ended queue — O(1) insert/delete at both ends.
Trees
Hierarchical structures — the backbone of most algorithms
Binary Tree
At Most 2 Children
Each node has left and right children. Foundation for BST, heaps, and expression trees. Traversals: preorder (root-left-right), inorder (left-root-right, gives sorted order in BST), postorder (left-right-root).
BST
Binary Search Tree
Left subtree < root < right subtree. O(log n) average search/insert/delete. Degrades to O(n) if unbalanced (sorted input = linked list).

Key insight: inorder traversal yields sorted sequence.
AVL Tree
Self-Balancing BST
Maintains |height(left) - height(right)| ≤ 1 at every node via rotations. Guaranteed O(log n) for all ops. More rotations than Red-Black — better for read-heavy workloads.
Red-Black Tree
Approximately Balanced BST
Nodes colored red/black. 5 invariants ensure height ≤ 2·log(n+1). O(log n) guaranteed. Fewer rotations than AVL — preferred for write-heavy. Used in: Linux kernel, Java TreeMap, C++ std::map.
Heap
Priority Queue
Complete binary tree. Max-heap: parent ≥ children. Min-heap: parent ≤ children. O(1) peek at max/min. O(log n) insert/extract. Stored efficiently as array: children of i at 2i+1 and 2i+2.
Trie
Prefix Tree
Each node = one character. Path from root to leaf = a word. O(m) search where m = word length — independent of n. Used for: autocomplete, spell-check, IP routing tables.
B-Tree
Disk-Optimized Tree
Generalization of BST — nodes can have many children. Minimizes disk reads by keeping tree shallow and nodes large (matching page size). The data structure behind every database index. O(log n) all ops.
Graphs
Vertices + edges — the most general structure, models almost anything
Adjacency Matrix
2D Array Representation
matrix[u][v] = 1 if edge exists. O(1) edge lookup. O(V²) space — wasteful for sparse graphs. Good for dense graphs or when you need fast edge existence checks.
Adjacency List
Array of Lists
Each vertex stores a list of its neighbors. O(V + E) space. O(degree) edge lookup. Standard representation for most graph algorithms — BFS, DFS, Dijkstra all use this.
Union-Find
Disjoint Sets
Tracks connected components. find(x) — what component is x in? union(x,y) — merge components. With path compression + union by rank: nearly O(1) amortized (inverse Ackermann). Used in Kruskal's MST.
Hashing
O(1) average case — the most practical data structure in daily programming
Hash Table
Key → Index via Hash Function
O(1) average insert/search/delete. O(n) worst case (all keys collide). Load factor = n/capacity — resize when > 0.7 typically.

Separate chaining: buckets hold linked lists.
Open addressing: probe for next empty slot (linear, quadratic, double-hash).
Hash Function
What makes a good hash?
Must be: deterministic (same input = same output), uniform (spreads keys evenly), fast to compute.

Common: djb2, MurmurHash, FNV. Cryptographic hashes (SHA-256) are too slow for hash tables — use them for security, not indexing.

History of Data Structures
Each structure was invented to solve a specific problem that existing ones couldn't
1945
Arrays & Linked Lists
Arrays implicit in early assembly and ENIAC programming. Linked lists formalized by Newell, Shaw & Simon at RAND (1956) for their Logic Theorist AI program.
1946
Stack (Turing)
Alan Turing described the "bury" and "unbury" operations — the first formal description of a stack — for handling subroutines on the ACE computer.
1956
Hash Tables
Invented independently by Hans Peter Luhn at IBM and Arnold Dumey. Luhn's internal memo described using hashing for information retrieval — the first chaining approach.
1960
Binary Search Trees
Formally described by multiple researchers. The concept follows directly from binary search (1946). The problem of unbalanced BSTs leading to O(n) performance was immediately obvious.
1962
AVL Trees
Adelson-Velsky and Landis publish the first self-balancing BST. Named AVL for their initials. Solved the degenerate BST problem with guaranteed O(log n) via height-balancing rotations.
1972
Binary Heap
J.W.J. Williams describes the binary heap and heapsort. Robert Floyd improves it with the O(n) build-heap algorithm. The heap's array representation makes it memory-efficient and cache-friendly.
1972
B-Trees
Rudolf Bayer and Edward McCreight at Boeing Research Labs invent B-trees for disk storage. The goal: minimize disk reads by keeping the tree shallow and nodes sized to disk pages. Every database index still uses this idea.
1973
Tries
The word "trie" comes from "retrieval," coined by Edward Fredkin. The structure itself was described earlier by Brandais (1959). Became essential for dictionary lookups and later IP routing tables.
1978
Red-Black Trees
Leonidas Guibas and Robert Sedgewick formalize red-black trees from symmetric binary B-trees. Fewer rotations than AVL on insertions. Adopted by nearly every language's standard library map implementation.
1984
Union-Find with Path Compression
Tarjan and van Leeuwen prove the near-O(1) amortized bound for union-find with both path compression and union by rank. Practically the fastest possible for connected component tracking.
