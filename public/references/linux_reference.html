Linux History

From UNIX at Bell Labs to powering 100% of the world's supercomputers

Timeline
1965
MULTICS — The Overly Ambitious Ancestor
MIT, Bell Labs, and GE attempt a grand multi-user OS. Too complex, too slow. Bell Labs walks away — but the ideas survive.
1969
UNIX Born at Bell Labs
Ken Thompson & Dennis Ritchie build a simpler alternative on a spare PDP-7. "Unics" — a pun on Multics. Everything is a file. One thing, done well.
1973
UNIX Rewritten in C
Ritchie creates C; UNIX is rewritten in it. Game-changer: now portable to other hardware. The first truly portable OS.
1977
BSD — Berkeley's Fork
UC Berkeley creates their own UNIX variant. Bill Joy adds vi and the C shell. Foundation for FreeBSD, macOS, iOS, and PlayStation OS.
1983
GNU Project — Stallman's Crusade
Richard Stallman at MIT: "GNU's Not Unix." Goal: a completely free OS. Writes gcc, bash, emacs, coreutils... everything except the kernel.
1987
MINIX — The Textbook OS
Andrew Tanenbaum builds MINIX for his OS textbook. Educational microkernel, $69, source included. A Finnish student will read it carefully.
1991
Linux 0.01 — "Just a Hobby"
August 25, 1991. Linus Torvalds, 21, posts to comp.os.minix: "just a hobby, won't be big and professional." 10,239 lines of code.
1992
GPL + GNU/Linux Complete
Linux adopts GPL. GNU userland + Linux kernel = a complete free OS. The Tanenbaum-Torvalds debate: microkernel vs monolithic. Linus wins by shipping.
1993–1994
First Distros: Slackware, Debian, Red Hat
Slackware makes Linux usable. Debian launches community-driven development. Red Hat brings Linux to business. The distro ecosystem begins.
2004
Ubuntu — Linux for Human Beings
Mark Shuttleworth launches Ubuntu 4.10. Free CDs mailed worldwide. 6-month releases, based on Debian. Finally: Linux that normal people could use.
2008
Android — Linux Goes Mobile
Google ships Android 1.0 on the Linux kernel. Would become the world's most-used OS. 3 billion devices. Linux in every pocket.
2025
Linux Everywhere
96% of top web servers. 100% of supercomputers. 85% of smartphones (Android). Cloud infrastructure, IoT, routers, smart TVs, your car.

The Unix Philosophy
The rules that made Linux conquer the world
Rule 1
Do one thing and do it well
ls lists files. grep searches text. wc counts words. No more, no less. Every program solves exactly one problem completely.

Contrast with Windows: Notepad, WordPad, and Word all "edit text." Unix has one tool, configurable. Compose complexity from simple parts.
Rule 2
Everything is a file
Regular files, directories, devices, sockets, pipes — all accessed through the same file interface. Read/write works on everything.

/dev/sda is your disk. /dev/null discards data. /proc/cpuinfo is your CPU info. No special APIs — just open, read, write, close.
Rule 3
Compose with pipes
The pipe | connects programs: stdout of one becomes stdin of the next. Small tools become powerful in combination.

cat log.txt | grep ERROR | sort | uniq -c | sort -rn | head -10 — top 10 most common errors. No new program needed.
Rule 4
Text is the universal interface
Programs communicate through plain text streams. Any language can read any output. Config files are human-readable. Logs are text.

The CLI is not a limitation — it's a protocol that enables composition. Shell scripts are pipelines made permanent.
Kernel
Monolithic but modular
Linux uses a monolithic kernel — all core services run in kernel space for performance. But modular: drivers load/unload at runtime via insmod/rmmod.

Beat Tanenbaum's prediction that monolithic kernels were "obsolete." Pragmatism won.
Open Source
GPL — the viral license
The GNU GPL requires: any distribution of a GPL program must include source under the same license. Freedom is viral.

Why Android must publish kernel changes — but Google's apps don't have to be open source. The kernel is GPL. The apps are not.
Filesystem Hierarchy
The Linux directory tree — know where everything lives
Root
/ — One tree, no drive letters
Unlike Windows (C:\, D:\), Linux has one unified tree rooted at /. Other drives are mounted into subdirectories. There are no drive letters — just paths.

Key rule: / is not a folder you open. It is the entire filesystem.
/home & /root
User space
/home/username/ — your files, configs, downloads. ~ is shorthand.
/root/ — root user's home. Separate from /.

Dotfiles (.bashrc, .config/) live here. ls -a to see hidden files. Don't touch other users' /home.
/etc
System configuration — all text files
/etc/passwd — user accounts.
/etc/fstab — mount points.
/etc/hostname — machine name.
/etc/apt/sources.list — package repos.
/etc/hosts — local DNS overrides.

Rule: to configure the system, edit files here.
/bin, /sbin, /usr
Programs
/bin — essential binaries (ls, cp, bash). Available even in recovery mode.
/sbin — system binaries (fsck, mount) — root only.
/usr/bin — most user programs.
/usr/local/bin — manually installed programs.

Modern distros: /bin → symlink to /usr/bin.
/var & /tmp
Variable & temporary data
/var/log/ — system logs. Check here when things break.
/var/lib/ — database files, package state.
/tmp/ — cleared on reboot.

Debug tip: tail -f /var/log/syslog watches system events live.
/dev & /proc
Virtual filesystems — generated by kernel
/dev/sda — disk 1. /dev/null — discard input. /dev/random — random bytes. /dev/stdin — standard input.

/proc/$(pid)/ — live info about any process. /proc/meminfo, /proc/cpuinfo.

These aren't real files — the kernel generates them on read.
# Navigate the tree
pwd                       # print working directory
cd ~                      # go home
cd /etc                   # absolute path
cd ../..                  # relative — up two levels
ls -la /var/log           # list with hidden files, long format
find /etc -name "*.conf"  # find all .conf files under /etc
du -sh ~/Downloads        # disk usage, human-readable
df -h                     # free space on all mounted filesystems
Permissions
rwx — the three-letter system that controls everything
Permission Bits
r w x — read write execute
Every file has 9 permission bits: 3 for owner, 3 for group, 3 for others.

-rwxr-xr--: owner can read/write/execute; group can read/execute; others read only.

Leading char: - = file, d = directory, l = symlink.
Octal Notation
r=4, w=2, x=1 — add them up
Each 3-bit group becomes a digit:
7 = rwx (4+2+1) = full
6 = rw- (4+2) = read/write
5 = r-x (4+1) = read/execute
4 = r-- = read only
0 = --- = none

chmod 755 = owner full, group/others read+execute.
Ownership
chown — change who owns a file
Every file has an owner and a group. Only owner (or root) can change permissions.

chown alice file.txt
chown alice:devs file.txt — alice + devs group.
chown -R alice /project — recursive.

Use groups to see your memberships. id to see your UID/GID.
sudo
Superuser do — elevated + audited
sudo command — run as root temporarily. Requires your password + membership in the sudo group. Every call is logged.

su - — switch to full root shell. Not recommended — unaudited.

Rule: always prefer sudo over su for traceability.

Processes & the Shell
How Linux runs programs — and how to control them
Processes
Every running program is a process
Each process has a PID. PID 1 is systemd — ancestor of all. Every process is forked from another. Fork → exec is how new programs start.

ps aux — list all processes.
htop — interactive monitor.
pgrep nginx — find PIDs by name.
kill -9 PID — force kill.
Signals
How the OS talks to processes
Signals are software interrupts:

SIGTERM (15) — please exit gracefully.
SIGKILL (9) — die now, no cleanup possible.
SIGHUP (1) — reload config (servers use this).
SIGINT (2) — Ctrl+C.
SIGSTOP — pause (Ctrl+Z).

Programs can catch most signals — but never SIGKILL.
Redirection
stdin (0), stdout (1), stderr (2)
Every process has 3 standard streams:
stdin — input (default: keyboard)
stdout — normal output (default: terminal)
stderr — error output (default: terminal)

cmd > out.txt — redirect stdout.
cmd 2> err.txt — redirect stderr.
cmd >&2 — merge stdout into stderr.
Jobs
Background & foreground
./task & — run in background.
jobs — list background jobs.
fg %1 — bring job 1 to foreground.
bg %1 — push to background.
Ctrl+Z — pause current job (SIGTSTP).
nohup cmd & — keep running after logout.
systemd
PID 1 — init & service manager
Modern Linux: systemd manages services, boot, logging.

systemctl start nginx
systemctl enable nginx — start on boot.
systemctl status nginx
journalctl -u nginx -f — follow live logs.

Controversial in the community — but universal in major distros.
Shell
bash — the interpreter
The shell is a program that reads commands and runs them. bash is standard; zsh is bash-compatible with more features; fish is friendly but less scriptable.

~/.bashrc — runs every new terminal.
echo $PATH — where bash looks for programs.
which python — which binary runs.
# Process management
ps aux | grep python        # find python processes
kill -15 1234              # graceful terminate
kill -9 1234               # force kill
htop                       # interactive process monitor

# Redirection
ls -la > files.txt         # save stdout to file (overwrite)
ls -la >> files.txt        # append stdout
cat missing 2>/dev/null    # discard errors
cmd > out.txt 2>&1        # merge stderr into stdout

# Pipes
cat /var/log/syslog | grep ERROR | tail -20
Distributions
Same kernel — different philosophies
Debian / Ubuntu / Mint
apt — the dominant family
Debian: rock-solid, slower releases. Ubuntu: Debian + 6-month cadence + LTS every 2 years. Mint: Ubuntu + friendlier desktop.

apt update && apt upgrade
apt install packagename
apt remove packagename

Package format: .deb
RHEL / Fedora / Rocky
dnf — the enterprise family
RHEL dominates enterprise servers. Fedora is the bleeding-edge community version. Rocky Linux and AlmaLinux replaced CentOS as free RHEL clones.

dnf install packagename
dnf update

Package format: .rpm
Arch Linux
pacman — rolling release, build-your-own
Manual install, no defaults — you build from scratch. Rolling release: always latest, no version upgrades. AUR has almost everything.

pacman -Syu — full system update.
pacman -S packagename

Famous for the Arch Wiki — best Linux docs in existence.
Common Core
What every distro shares
Regardless of distro, these are identical across all Linux:

• Linux kernel (uname -r to check version)
• Filesystem hierarchy (/etc, /home, /var…)
• bash + core terminal commands
• User/group permission model (rwx)
• systemd (most distros)

Learn the core — the distro is just packaging.
