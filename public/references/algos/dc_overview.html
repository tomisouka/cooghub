Algorithm Paradigm

Divide & Conquer

Break the problem in half, solve each half recursively, combine the results. Master Theorem gives complexity.
①
Divide
Split problem into smaller subproblems of the same type
②
Conquer
Solve each subproblem recursively (base case when trivial)
③
Combine
Merge subproblem solutions into the final answer

Merge Sort — The Template
mergeSort(arr, lo, hi):
  if lo >= hi: return               // base case: 1 element
  mid ← (lo + hi) // 2
  mergeSort(arr, lo, mid)            // conquer left
  mergeSort(arr, mid+1, hi)          // conquer right
  merge(arr, lo, mid, hi)            // combine

merge(arr, lo, mid, hi):
  L ← arr[lo..mid], R ← arr[mid+1..hi]
  i ← j ← 0, k ← lo
  while i < len(L) and j < len(R):
    if L[i] <= R[j]: arr[k++] ← L[i++]
    else:            arr[k++] ← R[j++]
  // copy remaining elements
When to Use D&C
✓ Independent subproblemsno overlap needed
✓ Problem halves cleanlydivide by constant
✗ Overlapping subproblemsuse DP instead
✗ Single pass is enoughuse greedy/linear
D&C vs DP
Both break problems into subproblems.
D&C: subproblems are independent — no reuse.
DP: subproblems overlap — cache results.

Fibonacci with D&C = exponential. With DP = linear.
