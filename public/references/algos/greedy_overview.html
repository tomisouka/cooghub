Algorithm Paradigm

Greedy Algorithms

Make the locally optimal choice at each step. Fast — but only correct when the greedy choice property holds.
Two Requirements
① Greedy choice property
A globally optimal solution can be reached by making locally optimal choices
② Optimal substructure
Optimal solution contains optimal solutions to subproblems (shared with DP)
Properties
SpeedUsually O(n log n) or better
No backtracking✓ Commit immediately
Always optimal?✗ Only with proof
vs DPFaster but less general
Key Algorithms
Activity Selection
Sort by end time → greedily pick non-overlapping intervals
O(n log n)
Fractional Knapsack
Sort by value/weight ratio → take as much as possible greedily
O(n log n)
Huffman Coding
Always merge two lowest-frequency nodes; build optimal prefix tree
O(n log n)
Job Sequencing
Sort by deadline/profit → schedule to maximize profit within deadlines
O(n log n)
Kruskal's MST
Sort edges → greedily add cheapest edge that doesn't form a cycle
O(E log E)
Dijkstra's
Greedily always expand the nearest unvisited node
O((V+E) log V)

Activity Selection Pseudocode
activitySelection(activities):
  activities.sort(key=lambda a: a.end)   // sort by end time
  result ← [activities[0]]
  last_end ← activities[0].end

  for a in activities[1:]:
    if a.start >= last_end:              // no overlap
      result.append(a)
      last_end ← a.end

  return result
