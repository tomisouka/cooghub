Chapter One
Iteration: The Loop

A loop repeats a block of instructions. One stack frame. Flat memory. The program counter jumps back to the top. No new allocations per step — just mutation.

Chapter Two
Recursion: The Mirror

A function calls itself with a smaller problem until it hits a base case. Each call pushes a new frame. The answer is assembled on the way back up.

Chapter Four
Backtracking:
Try. Fail.
Undo.

Backtracking is recursion with a decision at each step. Try a choice, recurse forward — if you hit a dead end, undo that choice and try the next. The undo is the magic.

4-Queens — backtracking solver
1function place(row) {
2 if row === N: return true
3 for col = 0 → N-1 {
4 if !safe(row, col): continue
5 board[row] = col // ✓ place
6 if place(row+1): return true
7 board[row] = -1 // ↩ undo
8 }
9 return false // dead end
10}

How They Relate

Foundation

Iteration is the most fundamental. Every recursive algorithm can be converted to iteration using an explicit stack. Iteration is what the CPU actually executes.

Abstraction

Recursion is iteration with automatic state management. The call stack is your explicit stack — the language manages it for you. Elegant for self-similar problems.

Power

Combining both gives you the best of each: recursive structure for divide-and-conquer, iterative loops for linear sweep. Most real sorting & searching algorithms live here.

Search

Backtracking is recursion applied to constraint satisfaction. The undo step is what separates it from plain DFS — it allows exhaustive, systematic search with pruning.

When To Use Each

Iteration

Use when processing a flat sequence, accumulating a value, or when stack depth is a concern.

Recursion

Use when the problem is tree-shaped, self-similar, or when divide-and-conquer is natural.

Both

Use when recursion divides the problem but each level needs linear work (sort, parse, search).

Backtracking

Use when you need to explore choices and the solution must satisfy hard constraints.
The Most Important Word
What does
return
actually do?
stop · hand back a value · restore the caller
step 1Stop execution

The function stops immediately. Any code after return in the same function is skipped. This is true even inside a loop or an if-block — return exits the entire function, not just the block.

step 2Pop the frame

The function's stack frame is removed from the call stack. All local variables inside it (n, acc, i…) are discarded. They no longer exist.

step 3Hand back the value

Whatever is written after return is evaluated and given to the caller as the result of the function call expression. return n + sub first computes n + sub, then hands that number up.

step 4Resume the caller

The caller resumes exactly where it paused — the line that called the function. The returned value slots in where the function call was written. If you wrote x = f(5), now x holds the returned value.

Four Flavours of Return
Return a value
return n + sub

Evaluates the expression and hands the result to the caller. The most common form. Used to build up answers from sub-problems.

Return early (guard)
if (n === 0) return 0

Exits the function before reaching the main logic. Used for base cases in recursion and input validation. Keeps code flat — no deep nesting needed.

Return a boolean
return solve(next)

In backtracking, returning true or false propagates a signal up the call stack — "I found a solution" or "I hit a dead end." The caller decides what to do.

Return nothing (void)
return // or just fall off

Exits the function with no value. Used when the function works by side effect (printing, mutating, drawing). The caller gets undefined.

Common Confusions
✗ return inside a loop exits the loop
for (i = 0; i < n; i++) { if (arr[i] === target) return i // exits the FUNCTION }

No. return exits the entire function, not just the loop. The loop stops because the function stops. break exits just the loop.

✓ Recursive return must be forwarded
// WRONG — loses the value solve(next) // CORRECT — forwards it up return solve(next)

A recursive call without return discards the result. The function runs but its answer is thrown away. In backtracking this means true never propagates — the whole search appears to fail.

✗ return exits the whole program

No. return only exits the current function and gives control back to whatever called it. Only the outermost call returning (or process.exit()) ends the program.

✓ Multiple returns are fine
if (!valid) return false if (done) return true return recurse(next)

A function can have many return statements. Whichever one is hit first wins. This is idiomatic in recursive and backtracking code.
