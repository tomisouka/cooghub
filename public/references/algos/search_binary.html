1 — The Idea
The array is sorted. Check the middle element. If it's the target — done. If target is smaller, search the left half. If target is larger, search the right half. Each comparison eliminates half the remaining elements. After log₂n steps the search space is 1.

3 — Why O(log n) — The Halving Effect
Each step cuts the search space in half. Starting from n elements, after k steps only n/2ᵏ remain. When n/2ᵏ = 1, we're done. Solving: k = log₂n.

Key Properties
Halves Each Step
Every comparison eliminates half the remaining search space. 1 billion elements takes at most 30 comparisons.
O(log n)
Sorted Input Required
Only works on sorted arrays. If unsorted, the "go left/right" decision is meaningless. Sort first or use a BST.
sorted only
Random Access Required
Needs O(1) index access to compute and jump to mid. Doesn't work on linked lists — use a skip list instead.
arrays only
Off-by-One Caution
Classic bug: mid = (L+R)/2 can overflow for large indices. Safe version: mid = L + (R−L)/2.
watch overflow
