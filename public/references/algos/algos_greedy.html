01
DP with a Twist — Max Subarray Skip One
HOW TO EXTEND A KNOWN DP WHEN THE PROBLEM ADDS A CONSTRAINT · EX 5.9
▶
You see this type of problem when…
"variant of max subarray" "allowed to skip/exclude one element" "allowed to use at most X of Y" problem feels like maxsum but harder standard DP won't capture a new choice
The Problem
!
Ex 5.9 — Max Subarray, Skip Up to One Element
Given array A of positive and negative integers, find indices \(i \le k \le j\) maximizing \(A[i] + \cdots + A[j] - A[k]\). You may exclude any one element in the subarray (or exclude none from the ends).
Concrete exampleA = [−2, 5, −1, 3, −4]. Normal max subarray = 5−1+3 = 7. With skip: exclude −1 → 5+3 = 8. Or exclude −4 → 5−1+3 = 7. Best = 8.
The Mental Model — How to Think
Key Insight — Add a New State Dimension for Each Choice
1
Start from what you know — the standard MaxSum DP
Before adding the twist, write the standard recurrence you already know. Every DP extension starts from a working base. Don't redesign from scratch.
\[M_{in}[i] = \max(A[i],\; M_{in}[i-1] + A[i]) \quad\text{(best ending at i, no skip)}\] \[M_{out}[i] = M[i-1] \quad\text{(best not ending at i)}\]
2
What new choice does the twist add? — Give it its own state
The skip creates a binary status: "have I skipped yet?" Track it as a separate array. At index \(i\), you either:
• Haven't skipped: extend normally (same as maxsum)
• Just skipped A[i]: come from no_skip[i−1], pay −A[i]
• Already skipped: extend skip_used[i−1] normally
\[\text{no\_skip}[i] = \max(A[i],\; \text{no\_skip}[i-1] + A[i])\] \[\text{skip\_used}[i] = \max(\underbrace{\text{no\_skip}[i-1]}_{\text{skip A[i] now}},\; \underbrace{\text{skip\_used}[i-1] + A[i]}_{\text{already skipped}})\] \[\text{best}[i] = \max(\text{no\_skip}[i],\; \text{skip\_used}[i])\] \[\text{Answer} = \max_{i}\;\text{best}[i]\]
3
Base cases — initialize carefully
At i=1: no_skip[1] = A[1]. skip_used[1] = 0 (subarray of just one element, but we skipped it — so sum is 0, but this only makes sense if the subarray has more elements. Initialize skip_used[1] = −∞ to indicate "not valid yet unless subarray extends".
\[\text{no\_skip}[1] = A[1], \quad \text{skip\_used}[1] = 0\]
Why skip_used[1] = 0If you skip A[1], the subarray starts at 1 and ends at 1, but with the element removed — sum = 0. This is valid by problem definition (can skip the first or last element).
4
Runtime: count the states × work per state
n indices × 2 states × O(1) work per state = O(n) time, O(n) space (or O(1) space if you only keep previous values).
MaxSumSkipOne(A[1..n]) Output: max subarray sum with up to one element excluded
1no_skip[1] ← A[1]  best ending at 1, no skip used
2skip_used[1] ← 0  skip A[1], empty remainder = 0
3best ← max(no_skip[1], skip_used[1])
4for i ← 2 to n:
5no_skip[i] ← max(A[i], no_skip[i−1] + A[i])  extend or restart
6skip_used[i] ← max(no_skip[i−1], skip_used[i−1] + A[i])  skip A[i] OR extend
7best ← max(best, no_skip[i], skip_used[i])
8return best
Common Mistakes
✕
Trying to add the skip into the existing MaxSum states. You need a separate array to track "skip already used." Cramming it into M_in/M_out loses information about whether you still have a skip to use.
✕
Wrong skip_used transition. skip_used[i] has two sources: (1) skip A[i] now — comes from no_skip[i−1]. (2) skip was used earlier — comes from skip_used[i−1] + A[i]. Missing either source gives wrong answers.
The General Pattern
[CH5] DP EXTENSION TECHNIQUE
▶

When a problem adds a constraint to a known DP: don't redesign — extend. Add a new state dimension tracking the constraint's "usage." Each state = (index, constraint status). Transitions must update the status correctly.

Examples: maxsum + skip-one → add skip_used state. 0/1 knapsack + "at most 2 of each" → add count state. LIS + "at most 1 decrease" → add decrease-used state.

DP with Two Resources — Two-Tape Storage
HOW TO THINK WHEN THE STATE HAS TWO CAPACITY DIMENSIONS · EX 5.12
▶
You see this type of problem when…
"distribute items across two bins/tapes" "two knapsacks" "minimize worst of two groups" one-dimensional DP doesn't capture both choices minimax / minimize maximum objective
The Problem
!
Ex 5.12 — n Programs, Two Tapes, Minimize Worst-Case Access Time
Store n programs on two tapes, each of length \(\ell\). Each program has length \(\ell(i)\). Total lengths fit on one tape. Worst-case access time = \(\max(\sum_{i\in S_1}\ell(i),\;\sum_{i\notin S_1}\ell(i))\). Minimize this.
Key insightMinimize \(\max(\text{tape1 total}, \text{tape2 total})\). Since total is fixed (= \(\sum\ell(i)\)), minimizing the max is equivalent to making tape1 total as close to total/2 as possible. This is the partition/subset-sum problem.
The Mental Model — Reduce to Known DP
Visual — Two-Tape = Partition Problem = 0/1 Knapsack
1
Recognize the hidden reduction — minimax on fixed sum = balance
Whenever you see "minimize the maximum of two groups" and the total is fixed, it reduces to: find the partition that makes each group as equal as possible. This is always subset-sum / 0-1 knapsack.
\[\min\max(\text{tape}_1, \text{tape}_2) = \min\max(w, T-w) \iff w \text{ as close to } T/2 \text{ as possible}\]
2
State definition: dp[i][w] = "can first i items fill exactly weight w?"
This is the standard 0/1 knapsack boolean variant. The state fully captures: which items have been considered (i) and how much weight we've committed to tape 1 (w).
\[dp[i][w] = dp[i-1][w] \;\lor\; (w \ge \ell(i) \land dp[i-1][w-\ell(i)])\] \[dp[0][0] = \text{True},\quad dp[0][w] = \text{False}\; \forall w>0\]
3
Extract the answer from the filled table
Scan dp[n][w] for the largest w ≤ ⌊T/2⌋ that is True. That w* is the best tape-1 total. Answer = max(w*, T − w*).
To reconstruct which programs go on tape 1Add a backtrack array: when dp[i][w] = True because dp[i−1][w−ℓ(i)] = True, record "program i is on tape 1." Trace back from w* to get the assignment.
Common Mistakes
✕
Not recognizing the reduction. If you try to set up a 2D DP on (tape1 remaining, tape2 remaining) you get O(n · ℓ²) which is far worse. The key insight is that tape2 is fully determined once tape1 is chosen.
✕
Wrong answer extraction. You want max w ≤ T/2 where dp[n][w]=True, not just dp[n][T/2]. If no subset sums to exactly T/2, you need the closest achievable value.
The Reduction Mindset
[CH5] REDUCE TO KNOWN DP
▶

Before designing a new DP: ask "is this secretly a problem I already know?" Partition, subset-sum, and 0/1 knapsack all look different on the surface but share the same DP structure.

Minimax on fixed sum: always reduces to "find half." Minimax on variable sum: use 2D DP tracking both capacities.

Grid DP — Optimal Path on a 2D Grid
HOW TO THINK ABOUT ANY GRID TRAVERSAL WITH OPTIMAL SUBSTRUCTURE · EX 5.18
▶
You see this type of problem when…
"move right or down on a grid" "collect maximum dirt/coins/value" "minimum cost path" movement is restricted (no backtracking) grid has m×n cells with values
The Problem
!
Ex 5.18 — Cleaning Robot on m×n Grid
Machine starts top-left, can only move right or down. grid[i][j] = 1 if dirty, 0 if clean. Maximize total dirty cells cleaned on the path to bottom-right.
The Mental Model — Grid DP Template
Visual — Grid DP: Every Cell Depends on Two Predecessors
1
Restricted movement = the subproblem is the cell you're at
Whenever movement is restricted (right/down only, no backtracking), the cell (i,j) is your subproblem. You can only reach (i,j) from (i−1,j) or (i,j−1). That's exactly two predecessors — trivial to combine.
2
Fill in order — top-left to bottom-right
The fill order must ensure all predecessors of (i,j) are computed before (i,j). Top-left → bottom-right satisfies this since dp[i−1][j] and dp[i][j−1] are always already filled.
General principleFor any DP, ask: "in what order can I fill the table so every cell's predecessors are already done?" For grid DP: row by row. For interval DP: by length. For tree DP: leaves first.
3
Path reconstruction — backtrack from dp[m−1][n−1]
To find the optimal path: at each cell (i,j), check which predecessor gave the maximum. If dp[i−1][j] ≥ dp[i][j−1], you came from above. Otherwise from the left. Trace back to (0,0).
\[\text{path}[i][j] = \begin{cases}\text{UP} & \text{if } dp[i-1][j] \ge dp[i][j-1]\\ \text{LEFT} & \text{otherwise}\end{cases}\]
CleaningRobot(grid[0..m-1][0..n-1]) Output: max dirty cells cleaned, and the path
1dp[0][0] ← grid[0][0]
2for j ← 1 to n−1: dp[0][j] ← dp[0][j−1] + grid[0][j]  top row: right only
3for i ← 1 to m−1: dp[i][0] ← dp[i−1][0] + grid[i][0]  left col: down only
4for i ← 1 to m−1:
5for j ← 1 to n−1:
6dp[i][j] ← grid[i][j] + max(dp[i−1][j], dp[i][j−1])
7return dp[m−1][n−1]  answer
Common Mistakes
✕
Forgetting the base cases (top row and left column). These have only one predecessor each — the top row can only be reached from the left, the left column from above. Handle them separately before the main loop.
✕
Not collecting current cell's value. dp[i][j] = grid[i][j] + max(...). The current cell's dirt is picked up when you arrive. Omitting grid[i][j] gives wrong results.
The Grid DP Template
[CH5] GRID DPAPPLIES TO MANY PROBLEMS
▶

Any problem on a grid with restricted movement uses this exact structure. Longest path, minimum cost, maximum coins — same template: dp[i][j] = value[i][j] + f(predecessors).

Generalization: if you can move in more directions (e.g., also diagonal), just add more predecessors: dp[i][j] = v[i][j] + max(dp[i−1][j], dp[i][j−1], dp[i−1][j−1]).

Greedy Job Scheduling — Exchange Argument
HOW TO PROVE GREEDY IS OPTIMAL FOR SCHEDULING · EX 6.6
▶
You see this type of problem when…
"jobs with deadlines and profits" "schedule to maximize profit" "prove greedy gives optimal" greedy: sort by profit, add if feasible need exchange argument proof
The Problem
!
Ex 6.6 — n Jobs, Each Takes 1 Unit, Has Deadline d_i and Profit p_i
Select a subset F of jobs that can all be completed by their deadlines (one at a time, unit time each). Maximize total profit. Greedy: sort by p_i descending, add job if the new set is still feasible.
ExampleJobs: (p=10, d=2), (p=8, d=1), (p=6, d=2), (p=3, d=1). Sorted: p=10,8,6,3. Add 10 (slot 1 or 2 → use slot 2). Add 8 (d=1 → slot 1). Add 6 (d=2 → all slots full, skip). Add 3 (skip). F = {10, 8}, profit = 18.
The Mental Model — How to Prove Greedy with Exchange Argument
Visual — Exchange Argument: Transform OPT into Greedy Without Losing Value
1
The Exchange Argument — 3-Step Template
Every greedy optimality proof follows this structure. Memorize it.
\[\textbf{Step 1: } \text{Assume OPT differs from Greedy. Let it be "locally different" at one point.}\] \[\textbf{Step 2: } \text{Swap OPT's choice for Greedy's choice at that point.}\] \[\textbf{Step 3: } \text{Show the swap: (a) stays feasible, (b) doesn't decrease objective.}\] \[\textbf{Conclude: } \text{Repeat swaps until OPT} = \text{Greedy. So Greedy is optimal.}\]
2
Feasibility check — how to check in O(n log n)
A set F of jobs is feasible iff we can schedule all jobs in F by their deadlines. Key theorem: F is feasible iff, when sorted by deadline, job k can be scheduled in slot k (for k = 1...|F|).

So: sort F by deadline. Check job k has d_k ≥ k for all k.
\[\text{F feasible} \iff \text{sorted by } d_i:\; d_{(k)} \ge k \text{ for all } k = 1, \ldots, |F|\]
ImplementationMaintain F in a sorted set (e.g. sorted array or heap sorted by deadline). To check if adding job j with deadline d_j keeps F feasible: insert j in sorted order, check that job at position k still has deadline ≥ k. This is O(log n) per insertion.
Visual — Greedy Execution: Sort by Profit, Insert if Feasible
Common Mistakes
✕
Weak exchange argument. You must show BOTH that the swap stays feasible AND doesn't decrease the objective. Showing one without the other is incomplete.
✕
O(n²) feasibility check. Checking feasibility naively (try all orderings) is O(n²). The sorted-deadline check reduces it to O(log n) per insertion using a sorted set.
05
Greedy Ordering — Buy in Decreasing Rate Order
HOW TO FIND THE RIGHT GREEDY KEY AND PROVE IT · EX 6.10
▶
You see this type of problem when…
"find optimal order to buy/schedule" "price grows by factor r each month" "minimize total cost" exponential price growth prove via exchange argument on adjacent swap
The Problem
!
Ex 6.10 — n Software Products, Price Grows by Factor r_j Each Month
Buy one product per month. If you buy product j at month t (0-indexed), cost = \(100 \cdot r_j^t\). All rates distinct. Minimize total cost.
Small example (n=3)r₁=2, r₂=3, r₃=4. Buy at months 0,1,2. Best order: buy r₃=4 first (month 0: cost 100), then r₂=3 (month 1: cost 300), then r₁=2 (month 2: cost 400). Total = 800.
vs. buy r₁ first: 100 + 200 + 400·(wait) → costs more. Fastest-growing first!
The Mental Model — Finding the Greedy Key
1
Compute cost as a function of position — find what to optimize
If we buy products in order \(\pi_1, \pi_2, \ldots, \pi_n\), product at position \(t\) (0-indexed) costs \(100 \cdot r_{\pi_t}^t\). Total cost:
\[\text{Total} = \sum_{t=0}^{n-1} 100 \cdot r_{\pi_t}^t = 100 \cdot \left(r_{\pi_0}^0 + r_{\pi_1}^1 + r_{\pi_2}^2 + \cdots\right)\]
To minimize: put the largest growth rates earliest (smaller exponent = cheaper). Greedy: sort by \(r_j\) descending.
2
Prove it with an adjacent-swap exchange argument
Suppose in some optimal order, adjacent products j (at position t) and k (at position t+1) have \(r_j < r_k\). Swap them — show cost decreases.
\[\text{Before swap: } 100(r_j^t + r_k^{t+1})\] \[\text{After swap: } 100(r_k^t + r_j^{t+1})\] \[\text{Swap improves iff: } r_k^t + r_j^{t+1} < r_j^t + r_k^{t+1}\] \[\iff r_k^t - r_j^t < r_k^{t+1} - r_j^{t+1}\] \[\iff (r_k^t - r_j^t) < r_k^t(r_k - 1) - r_j^t(r_j - 1)?\]
Simplify differently: swap improves iff \(r_k^t \cdot r_j^{t+1} < r_j^t \cdot r_k^{t+1}\), i.e., \(r_j < r_k\). So whenever r_j < r_k and j comes before k, swap them to reduce cost. Optimal = sort descending by r.
3
Clean proof — divide both sides by \(r_j^t r_k^t\)
\[r_k^t + r_j^{t+1} < r_j^t + r_k^{t+1}\] \[\text{Divide by } r_j^t r_k^t:\quad \frac{1}{r_j^t} + \frac{r_j}{r_k^t} \cdot r_j < \frac{1}{r_k^t} + r_k\cdot\frac{1}{r_j^t}\] \[\text{Simplify: } \frac{r_k^t + r_j^{t+1}}{r_j^t r_k^t} = \frac{1}{r_j^t} + \frac{r_j}{r_k^t}\] \[\text{Swap better iff: } \frac{1}{r_j^t} + \frac{r_j}{r_k^t} > \frac{1}{r_k^t} + \frac{r_k}{r_j^t} \iff r_j < r_k \checkmark\]
Visual — Why Fastest-Growing First Minimizes Cost
Common Mistakes
✕
Wrong sort direction. Buy LARGEST rate FIRST. The item with the highest rate grows fastest — buying it at month 0 prevents paying r^(n-1) for it.
✕
Sloppy exchange argument. Must show the inequality holds for ALL t, not just t=0. The key step is dividing by r_j^t · r_k^t and reducing to r_j < r_k — a condition that doesn't depend on t.
Adjacent Swap — The Cleanest Exchange Argument
[CH6] GREEDY ORDERING PROBLEMS
▶

For any ordering problem: compare what happens when two adjacent items are swapped. If swapping always improves (or never helps), then the greedy sort is optimal.

The template: cost(j at t, k at t+1) vs cost(k at t, j at t+1). Simplify to a condition on j, k alone (not t). If that condition is j < k in some ordering, sort by that key.

Famous instances: shortest-job-first (sort by processing time), fractional knapsack (sort by value/weight ratio), this problem (sort by rate descending).

DP on Contiguous Partitions — Max Sum with Groups of Size ≤k
HOW TO THINK ABOUT INTERVAL/PARTITION DP · EX 6 (PROGRAMMING)
▶
You see this type of problem when…
"partition into contiguous subarrays" "each group's values become the max" "maximize total after grouping" group size ≤ k constraint DP on "last group" pattern
The Problem
!
HW2 Ex 6 — Partition Array into Groups of Size ≤k, Maximize Sum
Given array A[1..n] and integer k, partition into contiguous subarrays each of size ≤k. Each subarray's values all become its maximum. Maximize total sum.
ExampleA=[8,7,15,10,4,6,11], k=3. Group [8,7,15]→all become 15 (sum=45), [10]→10, [4,6,11]→all become 11 (sum=33). Total=88.
The Mental Model — "Last Group" DP Pattern
Visual — DP Decomposition: The Last Group Ends at Position i
1
Subproblem: dp[i] = best total sum for A[1..i]
The key decomposition is the "last group" pattern. To solve dp[i], consider all possible last groups A[j..i] where i−j+1 ≤ k. Each choice leaves dp[j−1] as a solved subproblem.
\[dp[i] = \max_{j=\max(1,\,i-k+1)}^{i}\left(dp[j-1] + \max(A[j..i])\cdot(i-j+1)\right)\] \[dp[0] = 0\]
2
Why this has optimal substructure
The optimal grouping of A[1..i] must have some last group A[j..i]. Once that group is fixed, the rest A[1..j−1] must also be optimally grouped — otherwise we could improve the overall grouping by replacing it. This is optimal substructure.
3
Compute max(A[j..i]) efficiently as j decreases
As j decreases from i to max(1, i−k+1), you're extending the window leftward. Maintain a running maximum:
\[\text{As } j \text{ decreases: } \text{running\_max} = \max(\text{running\_max},\; A[j])\]
This gives O(1) per iteration → O(k) total per i → O(nk) overall.
MaxSumPartition(A[1..n], k) Output: maximum total sum after grouping
1dp[0] ← 0  base case: empty prefix
2for i ← 1 to n:
3dp[i] ← −∞
4running_max ← −∞  max of current last group A[j..i]
5for j ← i downto max(1, i−k+1):  try all last group sizes ≤ k
6running_max ← max(running_max, A[j])  extend group leftward
7group_sum ← running_max × (i − j + 1)  all values become max
8dp[i] ← max(dp[i], dp[j−1] + group_sum)
9return dp[n]
Runtime: Outer loop n iterations. Inner loop ≤ k iterations each. Total: O(nk). Space: O(n) for dp array. For large n, this must be efficient — ensure running_max is computed inline, not by re-scanning A[j..i] each time.
Visual — Full DP Table for [8,7,15,10,4,6,11], k=3
Common Mistakes
✕
Recomputing max(A[j..i]) from scratch each time. That gives O(nk²). Use a running max variable updated as j decreases — O(1) per step.
✕
Off-by-one on the inner loop bound. Last group size ≤ k means j ≥ i−k+1. So j ranges from i downto max(1, i−k+1). Check this carefully.
✕
Forgetting dp[0] = 0. When j=1, you access dp[j−1] = dp[0]. This must be defined as 0 (empty prefix has 0 sum).
The "Last Group / Segment" DP Pattern
[CH5] PARTITION DPLAST SEGMENT TRICK
▶

Applies to: any problem where you partition A[1..n] into contiguous segments, each contributing a cost/value depending only on the segment itself.

Template: dp[i] = best value for A[1..i]. Try all last segments A[j..i] of valid size. dp[i] = max over j of (dp[j−1] + cost(A[j..i])).

Efficiency key: compute cost(A[j..i]) incrementally as j decreases. For max: running_max. For sum: running_sum. This gives O(1) per j, total O(nk).

Other problems using this pattern: matrix chain (segments of matrices), word wrap (segments of words), rod cutting (segments of length i).
