Stone Game — Parity Strategy
CH2 · STRONG INDUCTION · GAME THEORY · 15 PTS
▶
Problem
Exercise 2.8. Alice and Bob alternate turns; on each turn a player removes a proper divisor \(d \geq 1\) of the current pile size. The player who cannot move loses. Determine the winning strategy.
—
State and prove the winning rule using strong induction. (15 pts)
Proof — Winning Rule by Strong Induction
Winning Rule P(n)
current player wins iff n is even
▶
P(n): "The current player wins if and only if \(n\) is even."
Key observations: every even number has at least one odd divisor (namely 1); no odd number has an even divisor. So parity is flipped on every move from an even pile, and preserved (odd→odd) on every move from an odd pile.
1
Base Cases
\(n=2\): Alice must remove 1 (only proper divisor), leaving \(n=1\). Bob cannot move (no proper divisor of 1). Alice wins. 2 is even. ✓
\(n=3\): Alice must remove 1, leaving 2. Bob takes 1, leaving 1. Alice cannot move. Bob wins. 3 is odd. ✓
2
Inductive Hypothesis
Assume \(P(j)\) holds for all \(2 \leq j < k\): the current player wins iff \(j\) is even.
3
Inductive Step — Case k even
Since \(k\) is even, 1 is an odd proper divisor of \(k\) (1 divides all integers). The current player removes 1, leaving \(k - 1\) stones. Since \(k\) is even, \(k-1\) is odd. By the IH (since \(k-1 < k\)), the next player loses on \(k-1\). Therefore the current player wins. ✓
4
Inductive Step — Case k odd
Every proper divisor \(d\) of an odd number \(k\) is itself odd (odd numbers have no even divisors). So removing \(d\) leaves \(k - d\) stones where both \(k\) and \(d\) are odd, making \(k-d\) even. By the IH, the next player wins on \(k-d\). This holds for every possible move. Therefore the current player has no winning move and loses. ✓
5
Conclusion
By strong induction, \(P(n)\) holds for all \(n \geq 2\). Alice (first player) wins if and only if the initial pile size \(n\) is even. \(\blacksquare\)
✓ Winning Strategy The current player wins iff \(n\) is even. From an even pile: always remove 1 (odd divisor), forcing an odd pile on the opponent. From an odd pile: all moves lead to an even pile, so the current player always loses with optimal play.
Concept
[CH2] STRONG INDUCTIONGAME INVARIANT
▶

Strong induction pattern: Assume \(P(j)\) for all \(j < k\) (not just \(k-1\)). Needed here because the game can jump to any \(k-d\) for any divisor \(d\), not just \(k-1\).

Parity invariant: Identify a property (here, parity) that alternates with each move. Proving it alternates gives a complete characterisation of who wins.

Problem
Exercise 3.1. Solve \(T(n) = 2T(n/2) + n^2\), \(T(1) \leq c\), by three methods.
a
Substitution / induction. (7 pts)
b
Recursion tree. (7 pts)
c
Master Theorem (DC Recurrence Theorem). (6 pts)
Part A — Substitution / Strong Induction
Guess
T(n) ≤ bn²
▶
Guess \(T(n) \leq bn^2\) for some constant \(b\) to be determined.
1
Base case
\(T(1) \leq c \leq b \cdot 1^2 = b\) holds as long as \(b \geq c\). ✓
2
Inductive hypothesis
Assume \(T(m) \leq bm^2\) for all \(m \leq k\). Prove for \(k+1\).
3
Inductive step
\[\begin{aligned}T(k+1) &= 2T\!\Bigl(\frac{k+1}{2}\Bigr) + (k+1)^2 \\[4pt] &\leq 2b\!\left(\frac{k+1}{2}\right)^{\!2} + (k+1)^2 \quad\text{(IH, since }\tfrac{k+1}{2}\leq k\text{)}\\[4pt] &= \frac{b(k+1)^2}{2} + (k+1)^2 \\[4pt] &= (k+1)^2\!\left(\frac{b}{2}+1\right)\end{aligned}\]
We need \(\dfrac{b}{2}+1\leq b\), i.e. \(b\geq 2\). Choose \(b=\max(2,c)\). Then \(T(k+1)\leq b(k+1)^2\). ✓
✓ Part A\(T(n)=O(n^2)\) by substitution with \(b=\max(2,c)\).
Part B — Recursion Tree
1
Work per level
At level \(i\): \(2^i\) subproblems each of size \(n/2^i\), each doing \((n/2^i)^2\) non-recursive work.
\[\text{Level }i\text{ total} = 2^i\cdot\left(\frac{n}{2^i}\right)^{\!2} = \frac{n^2}{2^i}\]
2
Sum over all levels (depth = log₂ n)
\[\sum_{i=0}^{\log_2 n}\frac{n^2}{2^i} = n^2\sum_{i=0}^{\infty}\frac{1}{2^i} \leq 2n^2\]
Geometric series with ratio \(1/2\) sums to 2.
3
Base cases (leaves)
Depth \(\log_2 n\) gives \(2^{\log_2 n}=n\) leaves, each costing \(O(1)\). Total: \(O(n)\). Dominated by \(2n^2\).
✓ Part BWork is \(n^2+n^2/2+\cdots\leq 2n^2\) plus \(O(n)\) for leaves. Total: \(T(n)=O(n^2)\).
Part C — Master / DC Recurrence Theorem
1
Identify parameters
\(a=2,\; b=2,\; f(n)=n^2\).
2
Check the regularity condition
\[af(n/b) = 2\cdot\left(\frac{n}{2}\right)^{\!2} = \frac{n^2}{2} = \frac{1}{2}f(n) \implies c = \tfrac{1}{2} < 1\]
The "decreasing" case of the Master Theorem applies: \(af(n/b)\leq cf(n)\) with \(c=1/2 < 1\).
3
Conclude
Since \(c < 1\): \(T(n) = \Theta(f(n)) = \Theta(n^2)\).
✓ Part CMaster Theorem (decreasing case, \(c=1/2\)): \(T(n)=\Theta(n^2)\).
Concept
[CH3] MASTER THEOREMRECURSION TREESUBSTITUTION
▶

DC Recurrence Theorem (Master Theorem): For \(T(n)=aT(n/b)+f(n)\):
If \(af(n/b)\leq cf(n)\) with \(c<1\): \(T(n)=\Theta(f(n))\).
If \(af(n/b)=f(n)\): \(T(n)=\Theta(f(n)\log n)\).
If \(af(n/b)\geq cf(n)\) with \(c>1\): \(T(n)=\Theta(n^{\log_b a})\).

Recursion tree geometric series: When work per level decreases geometrically (ratio \(r<1\)), the total is dominated by the root: \(\sum_{i=0}^\infty r^i f(n) = f(n)/(1-r)\).

Heaviest & Lightest Stone in 3n/2 − 2 Weighings
CH3 · DIVIDE & CONQUER · RECURRENCE · INDUCTION · 20 PTS
▶
Problem
Exercise 3.9. Given \(n\) stones with distinct weights (\(n\) a power of 2) and a two-pan balance, find both the heaviest and lightest stone using at most \(3n/2 - 2\) weighings. Give a divide-and-conquer strategy and prove the bound.
—
Algorithm, correctness proof, and comparison-count proof by induction. (20 pts)
Algorithm and Analysis
Why 3n/2 − 2 is optimal▶
A lower bound argument shows any comparison-based algorithm needs at least \(3n/2-2\) comparisons: each stone except the overall max must "lose" at least one comparison, and each stone except the overall min must "win" at least one. By an adversary argument, \(3\lfloor n/2\rfloor\) contests are necessary, giving \(3n/2-2\) for even \(n\).
1
Algorithm description
Base cases: \(|S|=1\): return that stone as both max and min (0 comparisons). \(|S|=2\): one comparison determines max and min (1 comparison).

Recursive case: Split \(S\) into two equal halves \(L\) and \(R\) of size \(n/2\). Recursively find \((\text{max}_L, \text{min}_L)\) and \((\text{max}_R, \text{min}_R)\). Then:
— Compare \(\text{max}_L\) vs \(\text{max}_R\): the heavier is the overall max. (1 comparison)
— Compare \(\text{min}_L\) vs \(\text{min}_R\): the lighter is the overall min. (1 comparison)
2
Correctness
The heaviest stone overall must be the heaviest in at least one half. When we find the heaviest in each half and compare, the winner is the global maximum. The same argument (by symmetry) holds for the minimum. Formal proof by strong induction on \(n\).
3
Recurrence for comparisons
\[T(1)=0,\quad T(2)=1,\quad T(n)=2T(n/2)+2\]
4
Solve by induction: T(n) = 3n/2 − 2
Base: \(T(2)=1=3(2)/2-2=1\). ✓
IH: Assume \(T(k)=3k/2-2\) for some power of 2 \(k\).
\[\begin{aligned}T(2k) &= 2T(k)+2 = 2\left(\frac{3k}{2}-2\right)+2 = 3k-4+2 = 3k-2 = \frac{3(2k)}{2}-2\end{aligned}\]
The formula holds for \(2k\). By induction, \(T(n)=3n/2-2\) for all \(n\) that are powers of 2. \(\blacksquare\)
MinMax(S) Output: (max, min) of stone set S
1if |S| = 1: return (S[1], S[1])  trivial, 0 comparisons
2if |S| = 2: return (heavier(S[1],S[2]), lighter(S[1],S[2]))  1 comparison
3L ← S[1..n/2]; R ← S[n/2+1..n]
4(maxL, minL) ← MinMax(L)
5(maxR, minR) ← MinMax(R)
6globalMax ← heavier(maxL, maxR)  1 comparison
7globalMin ← lighter(minL, minR)  1 comparison
8return (globalMax, globalMin)
✓ Answer Recurrence: \(T(n)=2T(n/2)+2\). Solution: \(T(n)=3n/2-2\) comparisons (proved by induction). The divide-and-conquer correctly returns the overall maximum and minimum by comparing the sub-results at the merge step.
Concept
[CH3] D&C OPTIMALITYTOURNAMENT ARGUMENT
▶

Key insight: Finding max alone takes \(n-1\) comparisons; finding min alone takes another \(n-1\). But doing them together takes only \(3n/2-2\) because each comparison produces useful information for both subproblems simultaneously.

Copyright Infringement — Majority Detection
CH4 · DIVIDE & CONQUER · DECREASE & CONQUER · BOYER-MOORE · 30 PTS
▶
Problem
Exercise 4.15. Given \(n\) files and a same/different query machine, determine if at least \(n/2\) files are identical.
a
Divide-and-conquer algorithm using \(O(n\log n)\) queries. (15 pts)
b
Decrease-and-conquer (Boyer-Moore voting) algorithm using \(O(n)\) queries. (15 pts)
Part A — Divide and Conquer, O(n log n)
Key observation — majority must dominate one half▶
If a file appears \(\geq n/2\) times in an array of size \(n\), it must appear \(\geq n/4\) times in at least one of the two halves of size \(n/2\). So the majority candidate of the full array is also the majority candidate (or dominant file) in at least one half.
1
Algorithm — returns (candidate, count) or (∅, 0)
DCHalfIdentical(A[1..n]) Output: (candidate file, count) or (∅, 0)
1if |A| = 1: return (A[1], 1)  base case
2(lf, lc) ← DCHalfIdentical(A[1..n/2])
3(rf, rc) ← DCHalfIdentical(A[n/2+1..n])
4if lf = rf: return (lf, lc + rc)  same candidate both halves
5lc ← lc + |{x ∈ A[n/2+1..n] | x = lf}|  count lf in right half
6rc ← rc + |{x ∈ A[1..n/2] | x = rf}|  count rf in left half
7if lc ≥ |A|/2: return (lf, lc)
8else if rc ≥ |A|/2: return (rf, rc)
9return (∅, 0)
2
Runtime
Lines 5–6 scan the opposite half in \(O(n)\) queries. Recurrence: \(T(n)=2T(n/2)+O(n)\). By the Master Theorem (equal-work case): \(T(n)=\Theta(n\log n)\).
3
Correctness
By strong induction: the base case is trivial. For size \(n\), by the IH both recursive calls correctly return the majority candidate in their halves (if one exists). If both halves return the same candidate, the sum of counts is correct. If they differ, lines 5–6 count each candidate across the full array — whoever reaches \(n/2\) is flagged. This correctly identifies any file occurring \(\geq n/2\) times.
✓ Part A — O(n log n) D&C Recurrence \(T(n)=2T(n/2)+O(n)=\Theta(n\log n)\). Returns correct majority candidate by induction.
Part B — Decrease and Conquer (Boyer-Moore Voting), O(n)
Key Idea
majority survives cancellationcount > 0 iff majority possible
▶
Maintain a candidate and a counter. Increment when the next file matches; decrement when it doesn't. If count reaches 0, replace the candidate. If a file occurs \(>n/2\) times, it will end up as the candidate with positive count — it can never be fully cancelled.
1
FindCandidate — single linear scan
FindCandidate(A[1..n]) Output: (candidate, count) — candidate may occur ≥ n/2 times
1if n = 1: return (A[1], 1)
2(cand, count) ← FindCandidate(A[1..n−1])
3if A[n] = cand
4count ← count + 1  reinforce candidate
5else if count = 0
6cand ← A[n]; count ← 1  candidate exhausted; new candidate
7else
8count ← count − 1  cancel one occurrence
9return (cand, count)
HalfIdentical(A[1..n]) Output: True iff some file appears ≥ n/2 times
1(cand, count) ← FindCandidate(A, n)
2if count = 0: candb ← A[n]  edge: check last element too
3counta ← countb ← 0
4for i ← 1 to n:  verify candidates with a linear pass
5if A[i] = cand: counta ← counta + 1
6else if A[i] = candb: countb ← countb + 1
7return (counta ≥ n/2) or (countb ≥ n/2)
2
Runtime
\(\texttt{FindCandidate}\): \(T(n)=T(n-1)+1\), unwinds to \(T(n)=n=O(n)\). The verification pass is also \(O(n)\). Total: \(O(n)\).
3
Correctness
IH: Assume \(\texttt{FindCandidate}(A, k)\) correctly returns a candidate that occurs \(\geq k/2\) times in \(A[1..k]\) (if one exists). For the \(n\)-th element:
Case 1: \(A[n]=\text{cand}\) — count increases; if \(\text{cand}\) occurred \(\geq(n-1)/2\) times before, it now occurs \(\geq n/2\) times. ✓
Case 2: \(A[n]\neq\text{cand}\) and \(\text{count}>0\) — one occurrence of each is cancelled; if a file occurred \(>n/2\) times, it still has count \(>0\) after cancellation. ✓
Case 3: \(\text{count}=0\) — no file occurred \(\geq n/2\) times in \(A[1..n-1]\); \(A[n]\) becomes the new candidate with count 1. ✓
The verification pass confirms the final candidate actually meets the threshold. \(\blacksquare\)
✓ Part B — O(n) Boyer-Moore Voting \(\texttt{FindCandidate}\) uses \(T(n)=T(n-1)+1=O(n)\) operations. Verification pass: \(O(n)\). Total: \(O(n)\).
Edge case (count = 0): When \(\texttt{FindCandidate}\) ends with count 0, the true majority (if it exists with exactly \(n/2\) occurrences) might be the very last element. So we check \(A[n]\) as a second candidate. Example: \([1,2,1,3,1,4]\) returns candidate 1 (correct); \([2,1,3,1,4,1]\) returns candidate 4 (count 0 case — check \(A[6]=1\) separately).
Concept
[CH4] MAJORITY VOTEDECREASE & CONQUERCELEBRITY PROBLEM
▶

Boyer-Moore Voting Algorithm: Maintains one candidate and a counter. Any element that occurs more than half the time cannot be fully cancelled by all other elements combined — it will survive as the final candidate. A verification pass is needed to confirm the exact count.

Analogy to Celebrity Problem: In the celebrity problem, when person A doesn't know B, A is eliminated; when A knows B, A is eliminated. Similarly here: when candidate ≠ current, one "vote" from each is cancelled. The majority "celebrity" survives.

Exercise 6 (Programming). Given \(n\) 2-D points and a positive integer \(k \leq n\), return the \(k\) points closest to the origin. Use the median-of-medians linear selection algorithm with groups of 7 (not 5). Must run in \(O(n)\) worst-case time.

Algorithm description.
2

3
Correctness argument.
4

Part 1 — Algorithm Description
Distance metric and key idea▶
Distance from the origin: \(d(x,y) = \sqrt{x^2+y^2}\). Since \(\sqrt{\cdot}\) is monotone, we can compare \(x^2+y^2\) directly without computing the square root.
\[d^2(x,y)=x^2+y^2\]
The \(k\)-closest points problem reduces to: find the \(k\)-th smallest element by squared-distance, then return all points with squared-distance \(\leq\) that value.
1
High-level strategy
Use the median-of-medians algorithm (with group size 7) to find the \(k\)-th closest point as a pivot in \(O(n)\) time. Then partition the input around this pivot distance:
 • If \(|S_1|=k-1\) (points strictly closer than pivot): the pivot is the \(k\)-th closest — return \(S_1 \cup \{\text{pivot}\}\).
 • If \(|S_1| \geq k\): the answer lies entirely in \(S_1\) — recurse on \(S_1\) with the same \(k\).
 • If \(|S_1| < k-1\): the first \(|S_1|+1\) closest are known — recurse on \(S_2\) to find the remaining \(k-|S_1|-1\).

The median-of-medians pivot guarantees that each recursive call shrinks by a constant fraction, giving \(O(n)\) total work.
Part 2 — Pseudocode
KClosest(S, k) Output: k points in S closest to origin
1if |S| ≤ k: return S  base: all remaining points qualify
2── find pivot via median-of-medians with group size 7 ──
3Partition S into ⌈|S|/7⌉ groups of 7 (last group may be smaller)
4M ← median of each group (sort each group, take middle element)
5pivot ← KClosest(M, ⌈|M|/2⌉)  median of medians = median of M
6── partition around pivot distance ──
7S₁ ← {z ∈ S | d²(z) < d²(pivot)}
8S₂ ← {z ∈ S | d²(z) > d²(pivot)}
9── decide which subset to recurse on ──
10if |S₁| = k − 1: return S₁ ∪ {pivot}
11else if |S₁| ≥ k: return KClosest(S₁, k)
12else: return S₁ ∪ {pivot} ∪ KClosest(S₂, k − |S₁| − 1)
Part 3 — Correctness
1
Proof by strong induction on |S|
Base: \(|S|\leq k\) — all points qualify, return \(S\). ✓

IH: Assume \(\texttt{KClosest}(T,j)\) returns the \(j\) closest points in \(T\) for all \(|T|<|S|\).

Inductive step:
— By the IH, the call to \(\texttt{KClosest}(M, \lceil|M|/2\rceil)\) correctly finds the median of \(M\), i.e., the true median of medians (pivot).
— \(S_1\) contains exactly the points strictly closer to the origin than the pivot; \(S_2\) contains the strictly farther ones.
— Case \(|S_1|=k-1\): there are exactly \(k-1\) points closer than the pivot, so the pivot is the \(k\)-th closest. Return \(S_1\cup\{\text{pivot}\}\). ✓
— Case \(|S_1|\geq k\): there are \(\geq k\) points closer than the pivot, so all \(k\) closest are in \(S_1\). By the IH (since \(|S_1|<|S|\)), the recursive call returns the correct \(k\) closest. ✓
— Case \(|S_1|<k-1\): the \(|S_1|+1\) closest are \(S_1\cup\{\text{pivot}\}\); the remaining \(k-|S_1|-1\) closest come from \(S_2\). By the IH (since \(|S_2|<|S|\)), the recursive call on \(S_2\) returns them correctly. ✓ \(\blacksquare\)
✓ CorrectIn every branch the algorithm recurses on exactly the subset containing the remaining required closest points, with the pivot correctly classifying all elements.
Part 4 — Runtime Analysis (Groups of 7)
Pivot Quality with Groups of 7
≥ 4 elements per group above/below median≥ 2n/7 − 8 elements guaranteed on each side
▶
With \(\lceil n/7\rceil\) groups of 7, excluding the pivot's group and the last (possibly partial) group, at least \(\frac{1}{2}\lceil n/7\rceil - 2\) groups have \(\geq 4\) elements closer than the pivot. So: \[\text{elements closer than pivot} \geq 4\!\left(\frac{1}{2}\cdot\frac{n}{7}-2\right) = \frac{2n}{7}-8\] Similarly \(\geq 2n/7-8\) elements are farther. So each recursive call at line 11 or 12 handles at most \(n - (2n/7-8) = 5n/7+8\) elements.
1
Recurrence
\[T(n) \leq T\!\left(\left\lceil\frac{n}{7}\right\rceil\right) + T\!\left(\frac{5n}{7}+8\right) + O(n)\]
First term: finding the median of medians (\(|M|=\lceil n/7\rceil\)). Second term: recursive call on at most \(5n/7+8\) elements. Third: partitioning into groups, sorting them, building \(S_1,S_2\) — all \(O(n)\).
2
Prove T(n) = O(n) by substitution
Guess \(T(n)\leq cn\) for some constant \(c\). Assume \(T(k)\leq ck\) for all \(k<n\).
\[\begin{aligned}T(n) &\leq c\!\left(\frac{n}{7}+1\right)+c\!\left(\frac{5n}{7}+8\right)+\alpha n\\[4pt]&= \frac{cn}{7}+c+\frac{5cn}{7}+8c+\alpha n\\[4pt]&= \frac{6cn}{7}+9c+\alpha n\\[4pt]&\leq cn \quad\text{provided } \frac{6c}{7}+\alpha\leq c \;\Leftrightarrow\; c\geq 7\alpha,\text{ and }n\geq\frac{9c\cdot 7}{c}=63\end{aligned}\]
Choose \(c = 7\alpha\) (and verify base cases for small \(n\) directly). Then \(T(n)\leq cn = O(n)\). \(\blacksquare\)

Why groups of 7 (not 5) still gives O(n)
Groups of 5 give: \(T(n)\leq T(n/5)+T(7n/10+6)+O(n)\), where \(1/5+7/10=9/10<1\) ✓.
Groups of 7 give: \(T(n)\leq T(n/7)+T(5n/7+8)+O(n)\), where \(1/7+5/7=6/7<1\) ✓.
Both are \(O(n)\) because the fractions sum to \(<1\). Groups of 7 reduce the first recursive call but increase the second's constant slightly — overall still linear.
✓ Runtime: O(n) Recurrence \(T(n)\leq T(n/7)+T(5n/7+8)+O(n)\). Fractions \(1/7+5/7=6/7<1\). By substitution with \(c=7\alpha\): \(T(n)\leq cn=O(n)\). \(\blacksquare\)

7def median_of_medians(pts):

9groups = [pts[i:i+7] for i in range(0, len(pts), 7)]

11return median_of_medians(medians) recursive call on ⌈n/7⌉ medians

14def kth_closest(pts, k):
15if len(pts) <= k: return pts base case: return all
16pivot = median_of_medians(pts) O(n) pivot selection
17pd = dist2(pivot)
18closer = [p for p in pts if dist2(p) < pd]
19equal = [p for p in pts if dist2(p) == pd]
20farther = [p for p in pts if dist2(p) > pd]
21if len(closer) == k:
22return closer exactly k points closer
23elif len(closer) + len(equal) >= k:
24return closer + equal[:k - len(closer)] fill with pivot-distance pts
25else: need more from farther set
26need = k - len(closer) - len(equal)
27return closer + equal + kth_closest(farther, need)

Implementation notes:
• Lines 7–11: median_of_medians groups the input into chunks of 7, sorts each chunk (O(1) per chunk since size ≤ 7), and recurses on the list of group medians. This ensures the pivot is the true median of medians.
• Lines 18–20: Three-way partition into closer, equal, farther. Handling ties in distance with the equal bucket ensures correctness when multiple points share the pivot distance.
• Lines 21–27: Three branches corresponding to the pseudocode cases — exactly \(k\) closer, enough in closer+equal, or need some from farther. The recursion only calls kth_closest on farther (size \(\leq 5n/7+8\)), not the full array.

Why median-of-medians is O(n): The key is the pivot quality guarantee. With group size \(g\) and \(\lceil n/g\rceil\) groups, the pivot is larger than at least \(\lfloor g/2\rfloor \cdot (\lfloor \lceil n/g\rceil/2\rfloor - 1)\) elements. For \(g=7\): \(\geq 4\cdot(n/14-2)=2n/7-8\) elements are on each side. The fractions \(1/7+5/7=6/7<1\) ensure the recurrence is \(O(n)\).

Group size 7 vs 5: Both work. Group size 3 fails (\(1/3+2/3=1\), not \(<1\)). Larger groups improve the "smaller" recursive call but increase sorting cost per group. Group sizes 5 and 7 are the standard choices.

k-Closest vs k-th smallest: Finding the \(k\)-th closest point gives a threshold distance. All points with distance \(\leq\) that threshold are the answer. Handle ties carefully with the three-way partition.
