Computer Organization History

From room-sized calculators to billion-transistor chips

Timeline
1945
Von Neumann Architecture
John von Neumann's "First Draft" describes the stored-program computer — CPU, memory, I/O, with program and data in the same memory. Almost every computer since follows this model.
1947
Transistor Invented
Shockley, Bardeen, and Brattain at Bell Labs. Replaced fragile vacuum tubes. Enabled reliable, fast, compact switching. The transistor is the atom of modern computing.
1958
Integrated Circuit
Jack Kilby at TI and Robert Noyce at Fairchild independently invent the IC. Moore's Law (1965) predicts transistor count doubles every ~2 years — held for 50+ years.
1971
Intel 4004 — First Microprocessor
4-bit processor, 2,300 transistors, 740 KHz. Entire CPU on a single chip. Designed by Federico Faggin. Launched the era of general-purpose programmable chips.
1980
RISC Revolution
Patterson (Berkeley) and Hennessy (Stanford) independently develop RISC. Simpler instructions, faster clock speeds, better compiler optimization. MIPS architecture is still what most courses teach.
1989–1993
Superscalar & Out-of-Order Execution
Intel 486 and Pentium introduce superscalar execution — multiple instructions per clock cycle. Out-of-order execution lets the CPU reorder instructions to avoid stalls.
2005
Multi-Core Era
Power wall hits — clock speed stops scaling. Intel and AMD pivot to multi-core. Software must now be parallel to use new hardware. The free lunch of single-threaded speedup is over.
2018–present
Spectre/Meltdown & Security
Branch prediction and speculative execution — techniques that made CPUs fast — create side-channel attacks. Microarchitecture security becomes a first-class concern.

CPU Architecture
How a processor is structured — the hardware that executes every instruction
ALU
Arithmetic Logic Unit
Performs all arithmetic (+ - × ÷) and logic (AND OR NOT XOR) operations. Takes two inputs + opcode, outputs result + condition flags (zero, carry, overflow, negative). The computational core of the CPU.
Registers
Fastest Memory — On-Chip
Tiny storage directly on the CPU. Access in a single clock cycle. MIPS has 32 general-purpose 32-bit registers. x86-64 has 16 64-bit registers (RAX, RBX, RCX…).

Special registers: PC (program counter), SP (stack pointer), IR (instruction register), MAR/MDR (memory address/data).
Control Unit
Instruction Director
Fetches, decodes, and coordinates execution of instructions. Generates control signals that tell the ALU, registers, and memory what to do each cycle.

Hardwired CU: fixed logic, fast.
Microprogrammed CU: flexible, uses microcode lookup table.
Fetch-Decode-Execute
The Instruction Cycle
1. Fetch: PC → MAR → memory → MDR → IR, increment PC.
2. Decode: CU interprets opcode in IR, identifies operands.
3. Execute: ALU computes, result written to register or memory.

Every instruction on every processor follows this loop.

Temporal Locality
Recently used → used again soon
If you access address X, you'll probably access it again. Caches keep recently-used data hot. Example: a loop variable accessed thousands of times stays in a register or L1.
Spatial Locality
Nearby addresses accessed together
If you access address X, you'll probably access X+1, X+2, etc. Caches load blocks (cache lines, typically 64 bytes) at a time. Why arrays beat linked lists for iteration — array elements are adjacent; pointer nodes are scattered.
Cache Mapping
Where does a block go in cache?
Direct-mapped: each block has exactly one cache slot (fast, but conflicts).
Fully associative: block can go anywhere (flexible, expensive to search).
N-way set associative: middle ground — most real CPUs use 4–16-way.
Instruction Set Architecture
The contract between hardware and software
RISC vs CISC
Two philosophies
RISC (ARM, MIPS): few simple fixed-length instructions, load/store architecture, many registers. Each instruction takes 1 cycle. Compilers do the work.

CISC (x86): many complex variable-length instructions, memory operands allowed. Hardware does more per instruction. Internally translated to micro-ops anyway.
Addressing Modes
How operands are specified
Immediate: ADD R1, #5 — value in instruction.
Register: ADD R1, R2 — value in register.
Direct: LOAD R1, 0x1000 — address in instruction.
Indirect: LOAD R1, [R2] — register holds address.
Base+offset: LOAD R1, 8[SP] — for stack frames.
MIPS R-Format
32-bit instruction encoding
op[6] | rs[5] | rt[5] | rd[5] | shamt[5] | funct[6]

op: opcode (0 for R-type).
rs/rt: source registers.
rd: destination register.
shamt: shift amount.
funct: specific operation (add, sub, and, or…).
Pipelining
Overlap instruction execution — throughput over latency
5-Stage Pipeline
IF → ID → EX → MEM → WB
IF: Instruction Fetch — load from memory.
ID: Instruction Decode — read registers.
EX: Execute — ALU operation.
MEM: Memory access — read/write data.
WB: Write Back — result → register.

Like an assembly line — 5 instructions in flight simultaneously.
Data Hazards
Read-after-Write dependencies
Instruction needs a result that hasn't been written yet.

Solution 1 — Stalling: insert NOPs (bubbles) — wastes cycles.
Solution 2 — Forwarding: route result directly from EX/MEM output back to EX input — avoids most stalls.
Still needs 1 stall: load-use hazard (MEM hasn't run yet).
Control Hazards
Branches disrupt the pipeline
When a branch is taken, the 2–3 instructions already fetched may be wrong — must be flushed.

Branch prediction: CPU guesses which way a branch goes. Modern CPUs: >95% accuracy. Mispredict penalty: 15–20 cycles. Spectre/Meltdown exploited this.
I/O & Bus
How the CPU talks to everything else
Programmed I/O
CPU polls the device
CPU spins in a loop checking if the device is ready (busy-waiting). Simple but wastes 100% of CPU time waiting. Acceptable only for very fast devices or embedded systems where idle spinning is fine.
Interrupt-Driven I/O
Device signals the CPU
CPU starts I/O, goes off and does other work. Device sends an interrupt when done. CPU saves context, runs Interrupt Service Routine (ISR), resumes. Much more efficient — used for keyboards, network cards, timers.
DMA
Direct Memory Access
A separate DMA controller handles large data transfers (disk → RAM) without CPU involvement. CPU gives the DMA controller: source, destination, size. DMA does the transfer and interrupts CPU when done. CPU is fully free during the transfer.
