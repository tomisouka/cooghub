Topic 1 Proof Techniques

The 5 Core Methods

Method 1
Direct Proof
Assume p is true. Show, step by step using definitions, algebra, and known facts, that q must be true.
1.State what you're given (assume p)
2.Apply definitions and algebra
3.Arrive at q — conclude □
Method 2
Proof by Contrapositive
To prove p → q, instead prove ¬q → ¬p (logically equivalent). Assume ¬q and show ¬p follows.
1.Write: "We prove the contrapositive: assume ¬q"
2.Derive ¬p from ¬q
3.Conclude p → q □
Method 3
Proof by Contradiction
Assume ¬p (the opposite of what you want to prove) and derive a logical contradiction — something that is always false.
1.Write: "Suppose for contradiction that ¬p"
2.Derive consequences until you reach a⊥
3.Conclude p must be true □
Method 4
Mathematical Induction
Prove a statement P(n) holds for all n ≥ n₀.
B.Base case — verify P(n₀) directly
H.Inductive hypothesis — assume P(k) for some k ≥ n₀
S.Inductive step — prove P(k+1) using P(k)
∴P(n) holds for all n ≥ n₀ □
Method 5
Strong Induction
Like induction but the hypothesis is stronger: assume P(k) for all values n₀ ≤ k < n.
B.Verify base case(s) P(n₀), …, P(n₁)
H.Assume P(k) for all n₀ ≤ k < n
S.Prove P(n) using any/all prior cases
Method 6
Proof by Cases
When the domain splits into exhaustive, mutually exclusive cases. Prove the statement for each case separately.
1.Identify all cases (e.g. even/odd, positive/negative)
2.Prove the result holds in each case
3."In all cases, the statement holds" □

Logic Review: Contrapositive vs Converse

p → q
The original statement: "if p then q." This is what you're trying to prove.
¬q → ¬p
Contrapositive — logically equivalent to p → q. Always valid to prove this instead.
q → p
Converse — NOT equivalent to p → q. Proving the converse does NOT prove the original.
¬p → ¬q
Inverse — also NOT equivalent. Proving the inverse proves nothing about p → q.
p ↔ q
Biconditional — requires proving BOTH p → q AND q → p. Read "p if and only if q."
💡

Induction structure to memorize: Base case → IH → Step. In the step, you're not proving P(k) — you're assuming it (the IH) and using it to derive P(k+1). Don't try to prove the IH; that's circular.

⚠️

Contradiction vs Contrapositive: They're different. Contrapositive flips and negates both sides of an implication. Contradiction assumes the whole conclusion is false and finds any logical impossibility.

Topic 2 Combinations

Key Concepts

Combination C(n,k)
Number of ways to choose k items from n when order does not matter. Also written ⁿCₖ or "n choose k." Formula: C(n,k) = n! / (k!(n−k)!)
Binomial coefficient
(n choose k) — same as C(n,k). Appears as coefficients in (a+b)ⁿ expansion. Always an integer. Symmetric: C(n,k) = C(n, n−k). e.g. C(5,2) = 10; also C(5,3) = 10 — symmetry!
Binomial Theorem
(a + b)ⁿ = Σₖ₌₀ⁿ C(n,k) · aⁿ⁻ᵏ · bᵏ. Each term uses a binomial coefficient. Read: "sum over k from 0 to n of n-choose-k times a to the n-minus-k times b to the k."
Pascal's Identity
C(n,k) = C(n−1, k−1) + C(n−1, k). Each entry in Pascal's triangle is the sum of the two above it. Useful in proofs and recurrences.
Counting subsets
A set of n elements has 2ⁿ total subsets (including ∅ and the set itself). This equals the sum of all C(n,k) for k from 0 to n.
Multiset / Stars & Bars
Choosing k items from n with repetition allowed (unordered): C(n+k−1, k). Visualize as placing k stars among n−1 dividers.
Core Formulas C(n,k) = n! / (k!(n−k)!) ← "n choose k" C(n,0) = C(n,n) = 1 C(n,1) = n C(n,k) = C(n, n−k) ← symmetry Σₖ C(n,k) = 2ⁿ ← all subsets (a+b)ⁿ = Σₖ C(n,k) aⁿ⁻ᵏbᵏ ← binomial theorem
ℹ

Combos vs Perms in one sentence: Combinations count what you pick; permutations count what you pick and the order you pick it. P(n,k) = C(n,k) × k! — perms are just combos times all the orderings of the selection.

Topic 3 Permutations

Key Concepts

Permutation P(n,k)
Number of ways to arrange k items selected from n where order matters. Read "P of n, k" or "n permute k." Formula: P(n,k) = n! / (n−k)! = n × (n−1) × ⋯ × (n−k+1)
Full permutation
P(n,n) = n! — the number of ways to arrange all n items. e.g. 3 items → 3! = 6 arrangements: ABC, ACB, BAC, BCA, CAB, CBA.
Multiplication principle
If step 1 has m choices and step 2 has n choices (independently), there are m × n total outcomes. The engine behind permutation counting.
Permutations with repetition
Arranging n items where item type i repeats nᵢ times: n! / (n₁! n₂! ⋯ nₖ!). Called a multinomial coefficient. e.g. MISSISSIPPI = 11!/(1!4!4!2!).
Circular permutations
Arranging n items in a circle (rotations considered identical): (n−1)!. One item is fixed to remove rotational symmetry.
Relationship to C(n,k)
P(n,k) = C(n,k) × k!. First choose which k items (unordered, C(n,k) ways), then arrange them (k! ways).
Core Formulas P(n,k) = n! / (n−k)! ← ordered selection P(n,n) = n! ← all arrangements P(n,k) = C(n,k) × k! ← combo × orderings Multinomial = n! / (n₁!⋯nₖ!) ← repeated items Circular = (n−1)! ← circle arrangements
⚠️

Order matters? Ask: does swapping two selected items give a different outcome? If yes → permutation. If no → combination. "Choose a team of 3" = combo. "Award gold/silver/bronze to 3 people" = permutation.

Topic 4 Pigeonhole Principle

The Principle

Basic form
If n+1 (or more) objects are placed into n boxes, then at least one box contains 2 or more objects. Simple but powerful — proves existence without constructing the example.
Generalized form
If N objects are placed into k boxes, then at least one box contains ⌈N/k⌉ or more objects. Formula: at least one box has ≥ ⌈N/k⌉ objects.
Identifying "pigeons"
The objects being distributed — what you have "too many" of. Count these as N.
Identifying "holes"
The categories / boxes they go into. Count these as k. If N > k, some hole holds more than one pigeon.
The Principle Basic: N objects, k boxes, N > k → some box has ≥ 2 Generalized: N objects, k boxes → some box has ≥ ⌈N/k⌉ Example: 13 people in a room → 2 share a birth month (12 months, 13 people) Example: 5 points in a 2×2 grid → 2 are within √2 distance (4 unit squares)

Classic Examples

Birth months
Any group of 13 people must have at least 2 who share a birth month. Pigeons = 13 people, holes = 12 months.
Socks problem
If you have 10 red socks and 10 blue socks mixed in a drawer and draw blindly, you need to draw 3 socks to guarantee a matching pair. Holes = 2 colors, so ⌈3/2⌉ = 2.
Handshakes
In a party of n ≥ 2 people, at least 2 people have shaken the same number of hands. Degrees range 0 to n−1 but 0 and n−1 can't both occur → n people, n−1 holes.
Integer sequences
Any sequence of n²+1 distinct integers must have an increasing or decreasing subsequence of length n+1. (Erdős–Szekeres theorem — pigeonhole in disguise.)
💡

How to structure a pigeonhole proof: (1) Clearly define what the "pigeons" are. (2) Clearly define what the "holes" are. (3) Show #pigeons > #holes. (4) Conclude: by the pigeonhole principle, some hole contains ≥ 2 (or ≥ ⌈N/k⌉) pigeons.

Topic 5a Asymptotic Notation

The 5 Notations

O(f)
Big-O · upper bound
g grows no faster than f. Worst case ceiling.
∃c,n₀: g(n) ≤ c·f(n) for all n ≥ n₀
Ω(f)
Big-Omega · lower bound
g grows at least as fast as f. Best case floor.
∃c,n₀: g(n) ≥ c·f(n) for all n ≥ n₀
Θ(f)
Big-Theta · tight bound
g grows exactly like f. Both O and Ω. The "equals" of asymptotics.
g = O(f) AND g = Ω(f)
o(f)
Little-o · strict upper
g grows strictly slower than f. Like < (not ≤).
lim(g/f) = 0 as n→∞
ω(f)
Little-omega · strict lower
g grows strictly faster than f.
lim(f/g) = 0 as n→∞

Key Rules for Working with Big-O

Drop constants
O(5n²) = O(n²). Constant multipliers don't change the class. Only the dominant growth behavior matters.
Drop lower terms
O(n² + n) = O(n²). As n → ∞, lower-order terms become negligible.
Sum rule
O(f) + O(g) = O(max(f,g)). Sequential code blocks: take the dominant one.
Product rule
O(f) × O(g) = O(f·g). Nested loops multiply complexities.
Logs and exponents
log(n) ≪ nᵉ for any ε > 0. Any polynomial beats any log. Any exponential beats any polynomial: nᵏ ≪ cⁿ for any c > 1.
Transitivity
If f = O(g) and g = O(h), then f = O(h). The asymptotic order is a partial order.
💡

Proving f(n) = O(g(n)): Find explicit constants c > 0 and n₀ ≥ 1 such that f(n) ≤ c · g(n) for all n ≥ n₀. Show your work: pick c, pick n₀, verify the inequality.

⚠️

Big-O is not equality. Writing f = O(g) means "f is in the set O(g)" — it's a membership claim, not numerical equality. O(n²) is a class of functions, not a specific function.

Topic 5b Algorithm Analysis

Analyzing Algorithm Complexity

Time complexity
Number of "basic operations" (comparisons, assignments, etc.) as a function of input size n. Expressed in asymptotic notation.
Worst case
Upper bound on running time for any input of size n. What Big-O usually describes. Most commonly analyzed and reported.
Best case
Lower bound for the best possible input. What Big-Ω often describes. Less practically useful but relevant for some proofs.
Average case
Expected running time over all inputs of size n (often assuming uniform distribution). Requires probabilistic analysis.
Space complexity
Memory used as a function of n. Same Big-O notation applies. Can differ significantly from time complexity.

Analyzing Loops

Single loop
A loop running from 1 to n doing O(1) work per iteration → O(n) total.
Nested loops
Outer loop n times, inner loop n times → O(n²). Multiply the complexities of nested levels.
Halving loop
Loop where i doubles (or n halves) each iteration → O(log n) iterations. Classic: binary search, merging halves.
Recurrences
Many recursive algorithms satisfy T(n) = aT(n/b) + f(n). Solve with the Master Theorem or substitution/recursion tree.
Master Theorem (basic) T(n) = a·T(n/b) + O(nᵈ) Case 1: d > log_b(a) → T(n) = O(nᵈ) [work dominates] Case 2: d = log_b(a) → T(n) = O(nᵈ log n) [equal work at all levels] Case 3: d < log_b(a) → T(n) = O(n^log_b(a)) [recursive calls dominate] Example: Merge sort T(n) = 2T(n/2) + O(n) a=2, b=2, d=1 → log₂(2) = 1 = d → T(n) = O(n log n)
🔮

Counting step-by-step: To find T(n) for a code block, count: (1) loops at each level, (2) work per iteration, (3) multiply if nested, add if sequential. Then drop constants and lower-order terms to get the Big-O class.
