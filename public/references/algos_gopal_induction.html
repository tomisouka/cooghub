01
Comparing Growth Rates
HOW TO ORDER FUNCTIONS ASYMPTOTICALLY · EX 1.5(c)
▶
You see this type of problem when…
"order by growth rate" "show f = O(g)" "rank these functions" unfamiliar expressions like 2^√(log n) n^(1/log n) — looks weird
The Mental Model — How to Think
1
Is this function secretly something simpler?
Before anything else, simplify weird-looking expressions. Rewrite using log/exp identities. The whole problem changes if you spot \(n^{1/\log n} = 10\).
\[n^{1/\log n} = (10^{\log n})^{1/\log n} = 10 \quad\leftarrow\text{ constant!}\] \[2^{\lg n} = 2^{\log_2 n} = n \quad\leftarrow\text{ just }n\text{!}\]
Ask yourself"Can I rewrite this as \(10^{\text{something}}\) or \(e^{\text{something}}\)? Can I take \(\log\) of both sides and simplify?"
2
What class does each function belong to?
Every function lives in a growth class. Place it before computing anything. This alone tells you most of the ordering.
The Growth Hierarchy — Know This Cold
The Decision Tree — Which Tool to Use
Pick Your Weapon for Proving f = O(g)
3
Is the limit in \(\infty/\infty\) form? → L'Hôpital
When direct substitution gives \(\infty/\infty\), differentiate top and bottom. Repeat if needed. The key derivative facts you need:
\[\frac{d}{dn}\log n = \frac{1}{n\ln 2} \qquad \frac{d}{dn}n^k = kn^{k-1} \qquad \frac{d}{dn}c^n = c^n\ln c\]
Pattern\(\log n\) vs \(n^k\): L'Hôpital once gives \(\frac{1}{n\ln 2} / kn^{k-1}\) → goes to 0. Log always loses to polynomial.
4
Is the comparison hard directly? → Take log of both sides
When \(f\) and \(g\) are both exponential-looking, take \(\log\) of both sides first. Since \(\log\) is monotone, \(f = o(g) \iff \log f = o(\log g)\).
\[\log^6 n = O(2^{\sqrt{\log n}}) \iff 6\ln\log n = O(\sqrt{\log n})\]
Why it worksAfter taking log, you've reduced a hard exponential comparison to a simpler polynomial/log comparison that you already know how to handle.
5
Build the chain left to right — never skip steps
Once you have pairwise comparisons, the full ordering follows. You only need to prove adjacent pairs — transitivity does the rest. Don't try to prove \(f_1 = O(f_7)\) directly.
HW1 answer\(\frac{1}{n^3} \prec \frac{1}{n} \prec 10 \prec \log^6 n \prec 2^{\sqrt{\log n}} \prec \frac{n}{\log^2 n} \prec n \prec n\log n \prec n^3 \prec n^{\lg\lg n} \prec 1.1^n \prec n!\)
Common Mistakes
✕
Forgetting to simplify first. If you don't spot \(n^{1/\log n} = 10\), the whole chain is wrong from position 3 onward.
✕
Confusing \(\lg\) and \(\log\). In this course \(\lg = \log_2\). The identity \(2^{\lg n} = n\) only works for base 2.
✕
Applying L'Hôpital to the wrong variable. You're differentiating with respect to \(n\), not \(x\). Use \(\frac{d}{dn}\log n = \frac{1}{n\ln 2}\).
The 3-Second Rule
USE THIS ON ANY ORDERING PROBLEM
▶

Step 1 (3 sec): Simplify every expression. Spot constants, spot \(n\)-equivalences.

Step 2 (3 sec): Classify each into: negative → constant → log → sub-poly → poly → quasi-poly → exponential → factorial.

Step 3: For each adjacent pair, choose the right tool: direct limit, L'Hôpital, or log-both-sides.

The chain within a class (e.g. \(n^2\) vs \(n^3\)) is almost always trivial. The interesting comparisons are at class boundaries.

02
Mathematical Induction
HOW TO FIND THE INVARIANT AND STRUCTURE THE PROOF · EX 2.8
▶
You see this type of problem when…
"prove this algorithm is correct" "show it uses exactly X comparisons" "prove the winning strategy" game / recursive problem with a pattern claim involves n, n-1, or n/2
The Mental Model — How to Think
Induction Flowchart — From Problem to Proof
1
What is the invariant? — Play small cases first
Never start writing the proof. First, play the game manually for n = 2, 3, 4, 5, 6, 7, 8. Write down who wins. The pattern is your invariant.
Stone gamen=2 → first player wins. n=3 → loses. n=4 → wins. n=5 → loses. n=6 → wins.
Pattern: Win iff n is even. That's P(n).
2
Why does one step preserve the invariant?
Ask: "if P(k) holds, what happens after one move?" The proof IS this one-step argument, repeated. You need to show that the invariant cannot be broken.
\[\text{Even pile} \xrightarrow{-\text{odd}} \text{Odd pile} \xrightarrow{-\text{odd}} \text{Even pile} \xrightarrow{\cdots}\]
Stone gameEven pile: you can always move to odd (subtract 1). Odd pile: you can ONLY move to even (odd − odd = even). So whoever is on even controls the game.
3
Weak or Strong Induction?
Weak: P(k) → P(k+1). Use when each case only depends on the immediately previous case.
Strong: P(2)∧…∧P(k−1) → P(k). Use when a move can jump to any smaller value (like in games where the pile can shrink by different amounts).
Stone game needs StrongFrom pile n, you can move to n−1, n−3, n−5, etc. (any odd divisor). The next position isn't always n−1, so you need P(j) for ALL j < k.
4
Write the proof in this exact structure
Every induction proof has the same skeleton. Fill it in.
\[\textbf{1. Claim: } P(n) \text{ for all } n \ge n_0\] \[\textbf{2. Base case: } \text{verify } P(n_0) \text{ directly (and } P(n_0+1)\text{ if needed)}\] \[\textbf{3. IH: } \text{Assume } P(j) \text{ for all } j \in [n_0, k)\] \[\textbf{4. IS: } \text{Prove } P(k) \text{ using IH on a smaller instance}\] \[\textbf{5. Conclude: } P(n) \text{ holds for all } n \ge n_0 \quad\square\]
Visual — Stone Game: Every Move Flips Parity
Common Mistakes
✕
Starting with the proof before finding the invariant. If you don't know what P(n) is yet, no amount of algebra will save you.
✕
Using weak induction when you need strong. If the move can jump to n−3 or n−5, P(k−1) alone is not enough — you need P(j) for all j < k.
✕
Forgetting to check both cases. For the stone game, you must separately prove even→win AND odd→lose. One case doesn't imply the other.
03
Solving Recurrences
THREE METHODS — WHEN TO USE EACH · EX 3.1
▶
You see this type of problem when…
T(n) = aT(n/b) + f(n) T(n) = T(n-1) + something "analyze runtime of this D&C" recurrence doesn't fit Master Theorem "prove by induction T(n) = O(...)"
The Decision — Which Method?
Three Methods — Pick the Right One
The Mental Model — Master Theorem Cases
Visual — Who Does the Most Work?
1
Compute \(\log_b a\) — this is your critical exponent
For \(T(n) = aT(n/b) + f(n)\): the number of leaves is \(n^{\log_b a}\). Compare \(f(n)\) to this. Whichever is bigger dominates.
\[T(n) = 2T(n/2) + n^2: \quad \log_2 2 = 1 \implies \text{leaves} = \Theta(n^1) = \Theta(n)\] \[f(n) = n^2 \gg n \implies \textbf{root dominates (Case 3)} \implies T(n) = \Theta(n^2)\]
2
For induction: guess first, then verify the algebra closes
The guess comes from the answer you already know (from the tree or theorem). Then you need to show the algebra closes — meaning the constant you assumed is achievable.
\[\text{Guess: } T(n) \le bn^2. \text{ Plug in: } \frac{b}{2}n^2 + n^2 \le bn^2 \iff b \ge 2.\] \[\text{Choose } b = \max(2, c). \text{ Both base case and IS work.} \checkmark\]
Common Mistakes
✕
Applying Master Theorem when it doesn't apply. MT requires \(f(n) = \Theta(n^c)\) exactly. It fails for \(f(n) = n/\log n\) or mixed recurrences like \(T(n/5) + T(7n/10)\).
✕
Forgetting to verify the constant closes. In induction proofs, you must explicitly find what \(b\) needs to be and confirm it works for the base case too.
✕
Confusing the three cases. Case 2 result is \(\Theta(n^c \log n)\) — not just \(\Theta(n^c)\). The extra \(\log n\) comes from multiplying by the number of levels.
04
Designing a D&C Algorithm
THE 4-QUESTION FRAMEWORK · EX 3.9 (HEAVIEST + LIGHTEST)
▶
You see this type of problem when…
"give a divide-and-conquer algorithm" "find X in an array" "minimize the number of operations" doing the same job twice seems wasteful naive O(n²) exists, need better
The Mental Model — 4 Questions to Ask
D&C Design Flowchart
1
Q1: What's the smallest case?
This defines your base case. For most array problems it's n=1 (trivial) or n=2 (one comparison). Don't overthink — just answer the problem for the smallest possible input.
Heaviest + Lightestn=1: the one stone is both max and min. n=2: one weighing tells you which is heavier.
2
Q2: How do I split? — Usually halves, but think about what's preserved
Split down the middle. Ask: "does the property I care about survive the split?" The max of the full set is the max of the two halves' maxima. The min works the same way. ✓
Key insight for this problemIf you find max and min of each half simultaneously in the recursive call, you share comparisons. That's what gives \(3n/2 - 2\) instead of \(2n - 3\).
3
Q3: What does each recursive call return? — Design this carefully
This is where most students go wrong. You need to return everything the parent needs to combine correctly. If you only return the max, you can't compare mins.
\[\text{Return type: } (\max, \min) \text{ — a pair, not just one value}\]
GeneralizationIn the majority-file problem (Ex 5), returning just "yes/no" isn't enough — you need (candidate, count) so the parent can correctly check thresholds.
4
Q4: Combine — count the extra operations, write the recurrence
Count exactly how many operations the combine step uses. That's the \(f(n)\) in your recurrence.
\[T(n) = 2T(n/2) + 2 \quad\leftarrow \text{2 comparisons to combine (max vs max, min vs min)}\] \[\text{Unwind: } T(n) = 2 \cdot \frac{n}{2} - 2 + 2\log n = \frac{3n}{2} - 2\]
Common Mistakes
✕
Designing the return type too late. You must decide what the recursive call returns before writing any code. Otherwise the combine step won't work.
✕
Forgetting to prove correctness separately. Runtime and correctness are two separate arguments. Runtime = recurrence. Correctness = induction showing the property holds after each split and merge.
05
D&C vs Decrease & Conquer
HOW TO CHOOSE AND HOW TO THINK ABOUT EACH · EX 4.15
▶
You see this type of problem when…
"give an O(n) algorithm" "hint: celebrity problem" "process one element at a time" D&C gives O(n log n), need better majority / candidate / voting problems
The Mental Model — Two Different Ways to Shrink a Problem
D&C vs Decrease & Conquer — The Core Difference
1
The Celebrity Analogy — the key to Boyer-Moore
In the Celebrity Problem: ask "does A know B?" — one question eliminates one person. After n−1 questions, one candidate survives. Then verify.

Boyer-Moore voting works identically: compare current candidate against next file. One comparison eliminates a non-majority pair.
\[\text{Invariant: if a majority exists, it survives the cancellation process.}\] \[\text{Surplus of majority} \ge \frac{n}{2} - (n - \frac{n}{2}) = 0 \implies \text{always survives.}\]
2
Why D&C needs to return (candidate, count) — not just boolean
When combining two halves, you need to count how many times the left candidate appears in the right half (and vice versa). A boolean "is there a majority?" gives you nothing to combine with.
Design principleAsk: "what does the parent call need from me to do its job?" The parent needs the candidate AND its count to decide whether it exceeds n/2 in the combined array.
3
How to pick between D&C and Decrease & Conquer
Use D&C when splitting the input produces two independent subproblems that you can solve and combine.

Use Decrease & Conquer when processing one element at a time lets you maintain a running state that you update cheaply.
\[\text{D\&C: } T(n) = 2T(n/2) + O(n) = O(n\log n)\] \[\text{Dec\&C: } T(n) = T(n-1) + O(1) = O(n)\]
Rule of thumbIf "one question eliminates one element" is possible → Dec&C → O(n). If you need info from both halves simultaneously → D&C → O(n log n).
Visual — Boyer-Moore: Cancellation Leaves the Majority
Common Mistakes
✕
Returning boolean from D&C combine. If you return just true/false, you lose count information. The parent can't verify the threshold without the count.
✕
Forgetting to verify the Boyer-Moore candidate. FindCandidate returns A candidate — it could still be wrong if no majority exists. Always do a final linear scan to count.
06
Linear Selection — Median of Medians
WHY O(n) IS POSSIBLE AND HOW THE PIVOT GUARANTEE WORKS · EX 4.15
▶
You see this type of problem when…
"find k-th smallest in O(n)" "k closest points, O(n) time" "use linear-time selection" quickselect would be O(n²) worst case groups of 5 or 7 mentioned
The Core Question — Why Does Random Pivot Fail?
Random Pivot vs Median-of-Medians — The Critical Difference
The Mental Model — How to Think About the Algorithm
1
Why do we need a "good" pivot?
QuickSelect works like QuickSort but only recurses on one side. If the pivot splits the array roughly in half, we discard half the elements each step → \(T = T(n/2) + O(n) = O(n)\).

But if the pivot is always the min (sorted input), we discard 0 elements → \(T = T(n-1) + O(n) = O(n^2)\). We need a pivot that always cuts off at least 30%.
2
How does Median-of-Medians guarantee a good pivot?
The pivot is the median of the group medians. Think about it geometrically: arrange the groups in columns, sorted vertically. The pivot is the median of the middle row.
Visual — Why the Pivot Guarantees ≥ 2n/7 Elements on Each Side
3
How to prove T(n) = O(n) — the induction trick
The key is that \(1/7 + 5/7 = 6/7 < 1\). There's a \(1/7\) slack that absorbs the \(\alpha n\) work at each level.
\[\text{Guess: } T(n) \le cn. \text{ Plug in IH:}\] \[T(n) \le c\!\left(\frac{n}{7}\!+\!1\right) + c\!\left(\frac{5n}{7}\!+\!8\right) + \alpha n = \frac{6cn}{7} + 9c + \alpha n\] \[\le cn \iff 9c + \alpha n \le \frac{cn}{7} \iff c \ge \frac{7\alpha n}{n - 63}\] \[\text{For } n > 63\text{: choose } c = 14\alpha. \quad T(n) = O(n) \checkmark\]
The pattern to memorizeAny recurrence \(T(n) \le T(an) + T(bn) + O(n)\) where \(a + b < 1\) gives \(T(n) = O(n)\). The slack \((1 - a - b)\) absorbs the linear work.
4
Why group size ≥ 5? (Not 3, not 1)
Group size determines how many elements are guaranteed on each side. The constraint is \(a + b < 1\).
\[\text{Size 3: } a+b = 1/3 + 2/3 = 1 \implies T(n) = O(n\log n) \text{ ✗}\] \[\text{Size 5: } a+b = 1/5 + 7/10 = 9/10 < 1 \implies O(n) \text{ ✓}\] \[\text{Size 7: } a+b = 1/7 + 5/7 = 6/7 < 1 \implies O(n) \text{ ✓}\]
IntuitionLarger groups → more elements guaranteed on each side → smaller fraction left for recursion → more slack. Any odd group size ≥ 5 works. Groups of 7 used in HW1.
Common Mistakes
✕
Using group size 3. With groups of 3, the bound is \(T(n/3) + T(2n/3) + O(n)\). Since \(1/3 + 2/3 = 1\), this gives \(O(n \log n)\), not \(O(n)\).
✕
Forgetting the constants in the recurrence. The recursion on medians costs \(T(n/7 + 1)\) and the partition call costs \(T(5n/7 + 8)\). The +1 and +8 are needed to make the induction close.
✕
Not choosing c large enough. In the induction, you need \(c \ge 14\alpha\) AND \(n \ge 63\). Always state both conditions explicitly.
The One Thing to Remember
APPLIES TO ALL LINEAR-TIME SELECTION
▶

The key inequality is \(a + b < 1\). If the two recursive calls together cover a fraction strictly less than 1 of the input, the total work is \(O(n)\).

Median-of-medians forces this. By finding a pivot that is neither too small nor too large, we guarantee at least 30% of elements are discarded in every recursive step.

The proof structure is always: guess \(T(n) \le cn\) → plug in IH → collect terms → show \((a+b)cn + \text{const} \le cn\) → choose \(c\) large enough → done.
