01 Setup & Config 5 entries
  • Identity
  • git config --global user.name "Name" set your identity Sets the name attached to all your commits
  • git config --global user.email "email" set your email Sets the email attached to all your commits
  • git config --list show all config Prints all current git config values
  • git config --global core.editor "code --wait" set default editor Use VS Code (or vim, nano, etc.) for commit messages
  • Aliases
  • git config --global alias.st status create a shortcut git st now runs git status — define any alias you want
02 Init & Clone 4 entries
  • Starting a Repo
  • git init create a new repo here Initializes a .git folder in the current directory
  • git init <name> create new repo in folder Creates a new directory and initializes a repo inside it
  • git clone <url> copy a remote repo Downloads the full repo history into a new local directory
  • git clone <url> <name> clone into custom folder Same as clone but names the local directory
03 Staging & Committing 12 entries
  • Checking State
  • git status what's changed? Shows working tree status — staged, unstaged, and untracked files
  • git status -s compact status Short format — M=modified, A=added, ??=untracked
  • Staging
  • git add <file> stage one file Adds a specific file to the staging area (index)
  • git add . stage everything Stages all modified and new files in the current directory
  • git add -p stage interactively Walk through each change hunk — choose y/n to stage piece by piece
  • git restore --staged <file> unstage a file Removes file from staging area — keeps your changes in working dir
  • Committing
  • git commit -m "message" save a snapshot Commits staged changes with an inline message
  • git commit --amend fix the last commit Edit the last commit's message or add forgotten staged changes — rewrites history
  • git commit -am "message" stage tracked + commit Stages all tracked modified files and commits in one step
  • Diffing
  • git diff what changed (unstaged)? Shows diff between working directory and staging area
  • git diff --staged what's about to be committed? Shows diff between staging area and last commit
  • git diff <c1> <c2> diff two commits Shows all changes between any two commits — use SHA hashes
04 Branches 8 entries
  • Listing
  • git branch list local branches Lists all local branches — * marks the current one
  • git branch -a list all branches Lists local AND remote-tracking branches
  • Creating
  • git branch <name> create a branch Creates a new branch at the current commit — does NOT switch to it
  • Switching
  • git switch <name> switch to branch Moves HEAD to branch — modern replacement for git checkout
  • git switch -c <name> create and switch Creates a new branch and immediately checks it out
  • Deleting
  • git branch -d <name> delete merged branch Deletes branch only if it's fully merged — safe delete
  • git branch -D <name> force delete branch Deletes branch regardless of merge status — data loss if unmerged
  • Renaming
  • git branch -m <old> <new> rename a branch Renames a branch locally
05 Merging & Rebasing 9 entries
  • Merging
  • git merge <branch> merge branch in Merges branch into the current branch — creates a merge commit if diverged
  • git merge --ff-only <branch> fast-forward only Merges only if possible via fast-forward — fails otherwise
  • git merge --no-ff <branch> always make a merge commit Forces a merge commit even for fast-forwardable branches
  • git merge --abort cancel a merge Aborts an in-progress merge and restores pre-merge state
  • Rebasing
  • git rebase <branch> replay commits on top Replays current branch commits on top of branch — linear history
  • git rebase -i HEAD~N edit last N commits Interactive rebase — squash, reorder, drop, or edit commits
  • git rebase --abort cancel a rebase Stops and restores to pre-rebase state
  • git rebase --continue resume after conflict After resolving a conflict, stages the fix and continues rebasing
  • Cherry-pick
  • git cherry-pick <SHA> grab one commit Applies a specific commit from another branch onto the current branch
06 Remote 12 entries
  • Managing Remotes
  • git remote -v list remotes Shows all remote connections with their fetch/push URLs
  • git remote add <name> <url> connect to a remote Adds a remote — conventionally named 'origin'
  • git remote remove <name> disconnect a remote Removes the remote connection (doesn't delete the remote repo)
  • Fetching & Pulling
  • git fetch download without merging Downloads all remote changes — does NOT update working dir
  • git fetch origin fetch from origin Explicitly fetches from the 'origin' remote
  • git pull fetch + merge Fetches and merges remote branch into current branch
  • git pull --rebase fetch + rebase Fetches and rebases instead of merge — keeps history linear
  • Pushing
  • git push upload commits Pushes current branch to its tracked remote branch
  • git push origin <branch> push specific branch Pushes branch to origin explicitly
  • git push -u origin <branch> push and track Pushes and sets the upstream — future push/pull work without arguments
  • git push --force-with-lease safe force push Force pushes only if no one else pushed since your last fetch
  • git push origin --delete <branch> delete remote branch Removes the branch from the remote repository
07 Log & History 9 entries
  • Viewing Log
  • git log show commit history Full log — SHA, author, date, message for each commit
  • git log --oneline compact log One line per commit — short SHA + message
  • git log --oneline --graph --all visual branch graph ASCII art graph of all branches and merges
  • git log -n 5 last N commits Limits log output to the last N commits
  • git log --author="name" filter by author Shows only commits by a specific author
  • git log -- <file> history of one file Shows only commits that touched a specific file
  • Inspecting
  • git show <SHA> inspect a commit Shows full diff and metadata for a specific commit
  • git blame <file> who wrote each line? Annotates each line with the commit and author that last changed it
  • git shortlog -sn commit count by author Summarizes commits per contributor — sorted by count
08 Undoing Changes 8 entries
  • Working Directory
  • git restore <file> discard working dir changes Reverts file to last committed state — CANNOT be undone
  • git restore . discard all unstaged changes Reverts everything in working dir to last commit — destructive
  • Reset
  • git reset --soft HEAD~1 undo commit, keep staged Moves HEAD back one commit — changes stay staged
  • git reset HEAD~1 undo commit, keep files Default reset — unstages changes, keeps files in working dir
  • git reset --hard HEAD~1 undo commit and changes Moves HEAD back and DELETES all changes — truly destructive
  • Revert
  • git revert <SHA> undo safely (new commit) Creates a new commit that undoes a previous one — safe for shared branches
  • Cleanup
  • git clean -fd delete untracked files Removes untracked files (-f) and directories (-d) — cannot be undone
  • git clean -nfd preview clean Dry run — shows what would be deleted without actually deleting
09 Stash 8 entries
  • Basic Stash
  • git stash save work temporarily Stashes all staged and unstaged changes — working dir goes clean
  • git stash push -m "message" stash with a label Saves stash with a descriptive name — easier to identify later
  • git stash -u stash including untracked Also stashes new untracked files
  • Managing Stashes
  • git stash list see all stashes Lists all stashes — stash@{0} is the most recent
  • git stash pop restore and remove stash Applies the top stash and removes it from the stash list
  • git stash apply stash@{N} restore without removing Applies a specific stash but keeps it in the list
  • git stash drop stash@{N} delete a stash Removes a specific stash from the list without applying it
  • git stash clear delete all stashes Removes all stashes permanently
10 Tags 5 entries
  • Listing
  • git tag list tags Lists all tags in alphabetical order
  • Creating
  • git tag <name> create lightweight tag Tags current commit — a named pointer, no extra metadata
  • git tag -a <name> -m "msg" create annotated tag Stores tagger name, date, message — preferred for releases
  • Pushing
  • git push origin --tags push all tags Tags are not pushed by default — this sends them all to remote
  • Deleting
  • git tag -d <name> delete a local tag Removes a tag locally — does not affect remote
11 Worktree & Submodules 4 entries
  • Worktree
  • git worktree add <path> <branch> check out another branch simultaneously Creates a linked working tree — work on two branches at once
  • git worktree list list all worktrees Shows all active working trees linked to this repo
  • Submodules
  • git submodule add <url> embed another repo Adds a git repo as a subdirectory — tracked at a specific commit
  • git submodule update --init --recursive initialize submodules after clone Run this after cloning a repo that has submodules
12 Useful Inspection 6 entries
  • Reflog
  • git reflog history of HEAD movements Shows every place HEAD has pointed — safety net for recovering lost commits
  • Bisect
  • git bisect start start a bug hunt Begins binary search through commits to find when a bug was introduced
  • git bisect bad / good <SHA> mark commits in bisect Tell git which commits are broken vs working — it narrows down automatically
  • Search
  • git grep "pattern" search tracked files Searches all tracked files for a pattern — faster than grep for git repos
  • git ls-files list all tracked files Shows every file currently tracked by git in the index
  • git rev-parse HEAD get current commit SHA Prints the full SHA of the current HEAD commit
13 .gitignore 5 entries
  • Basics
  • .gitignore tell git what to skip File listing patterns git should never track — one pattern per line
  • git rm --cached <file> untrack without deleting Removes file from index but keeps it on disk — use after adding to .gitignore
  • Patterns
  • node_modules/ ignore a whole folder Trailing slash = ignore this directory
  • *.log ignore by extension Wildcard — ignores all .log files anywhere in the repo
  • !important.log un-ignore a specific file ! negates a pattern — tracks this file even if *.log is ignored
14 Concepts 10 entries
  • Core Concepts
  • SHA / commit hash a commit's unique ID 40-char hex string identifying a commit — first 7 chars usually enough
  • HEAD where you are now A pointer to the current commit — usually the tip of the current branch
  • detached HEAD HEAD points to a commit, not a branch Happens when you check out a SHA directly — new commits won't be on any branch
  • index / staging area what will go into next commit The intermediate area between working directory and commit
  • origin default remote name Convention — the remote your repo was cloned from. Just a name, not special to git
  • upstream what your branch tracks The remote branch a local branch is linked to for push/pull
  • Merge Concepts
  • fast-forward merge no divergence, just move pointer When target branch has no new commits — git just moves the pointer forward
  • 3-way merge branches diverged, need merge commit When both branches have new commits — git finds common ancestor and creates a merge commit
  • rebase vs merge linear vs preserved history Rebase = linear history, rewrites SHAs. Merge = preserves history, safe for shared branches
  • merge conflict two branches changed the same line Git can't auto-merge — marks conflict with <<<, ===, >>> markers. Resolve manually
15 GitHub Workflow 5 entries
  • Collaboration
  • fork your own copy of a repo GitHub feature — copies a repo to your account so you can make changes
  • pull request (PR) propose your changes Requests that your branch be merged into another branch, with review
  • git remote add upstream <url> track the original repo When working from a fork — adds the original repo as 'upstream'
  • git fetch upstream && git merge upstream/main sync fork with original Pulls in changes from the original repo into your local fork
  • squash and merge combine PR commits into one GitHub merge option — collapses all PR commits into a single commit on main
16 Common Flags 5 entries
  • Flags
  • -v / --verbose show more detail Works on many commands — e.g. git branch -v shows last commit on each branch
  • --dry-run preview without doing Available on git clean, git push, etc. — shows what would happen
  • -f / --force override safety checks Skips protections — use with caution. Prefer --force-with-lease for remote pushes
  • --all / -a include everything Context-dependent — git branch -a (all branches), git fetch --all (all remotes)
  • git --no-pager log skip the scroll viewer Prints output directly to terminal instead of opening the pager
