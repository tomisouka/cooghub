01 — What is Machine Learning?

Programs that learn rules
instead of being given them

Traditional software is explicit: a programmer writes rules — IF the email contains "congratulations you've won" THEN mark as spam. Machine Learning flips this: you provide thousands of examples of spam and not-spam, and the algorithm figures out the rules itself.

ML is not magic and it's not AI sentience. It's statistical pattern finding at scale. Given enough examples, well-designed algorithms can find patterns too complex for humans to write by hand — patterns in images, language, financial data, genomes, anything that can be represented numerically.

Critically: ML ≠ Deep Learning. Deep learning is one subset of ML using multi-layer neural networks. ML also includes decision trees, random forests, support vector machines, linear regression, k-means clustering, and dozens of other techniques — many of which outperform neural networks on structured tabular data.

03 — Classification

Drawing decision boundaries in data space

Classification is the most common ML task: given an input, assign it to one of N categories. A model learns a decision boundary — a surface in feature space that separates classes.

The shape of this boundary depends on the algorithm. Linear classifiers draw a straight line. SVMs find the maximum-margin boundary. Decision trees draw axis-aligned boxes. Neural networks can draw arbitrarily curved boundaries.

The key question: does the boundary generalize? A boundary that perfectly separates training data may fail on new data (overfitting). Finding the right level of complexity is the central challenge of supervised learning.

04 — Core Algorithms

The ML toolkit — beyond neural networks

Deep learning gets the headlines, but for structured tabular data — the most common data type in industry — classical ML algorithms often win. These are battle-tested, interpretable, and fast to train.

05 — Bias-Variance Tradeoff

The fundamental tension in ML

Every ML model faces a tradeoff between two sources of error:

Bias — error from wrong assumptions. A too-simple model that can't capture the true pattern (underfitting). Low complexity → high bias. A linear model trying to fit a curve has high bias.

Variance — error from sensitivity to training data noise. A too-complex model that memorizes the training set (overfitting). High complexity → high variance. A degree-20 polynomial fits the training points perfectly but wildly oscillates between them.

The goal: find the sweet spot — a model complex enough to capture the real pattern, but not so complex it memorizes noise. This is controlled by model choice, regularization, and training data size.

The formula

Total Error = Bias² + Variance + Irreducible Noise
Irreducible noise is the floor — it cannot be eliminated regardless of model quality.

06 — Decision Trees

ML you can read like a flowchart

A decision tree is the most interpretable ML model — it literally asks questions and branches based on answers. Starting at the root, each node asks a question about one feature (e.g., "Is age > 30?"). Based on the answer, you follow a branch until you reach a leaf node that gives the prediction.

Trees are trained greedily: at each node, find the split (feature + threshold) that best separates the classes, measured by impurity metrics like Gini impurity or information gain (entropy).

Single trees overfit easily. Random Forests (ensembles of hundreds of trees, each trained on a random sample) are dramatically more accurate — one of the most powerful general-purpose algorithms in ML.

07 — Evaluation

How we measure if a model actually works

Accuracy alone is deceptive. If 99% of your data is class A, a model that always predicts A is "99% accurate" but completely useless. Good evaluation requires understanding the full picture.

Train / Validation / Test split is the foundation. You train on the training set, tune on validation, and evaluate final performance on a held-out test set the model has never seen.

Cross-validation rotates the validation set across multiple folds — giving a more reliable performance estimate especially when data is limited.

Confusion matrix reveals the pattern of errors: false positives (predicted positive, actually negative) vs false negatives (predicted negative, actually positive). In medicine, a false negative (missed diagnosis) is far worse than a false positive — the metric you optimize should reflect this.
