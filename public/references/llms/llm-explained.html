01 — What is an LLM?

A model trained to predict text, at extraordinary scale

A Large Language Model is a neural network — a mathematical system of interconnected numbers — trained on a massive corpus of text to do one thing: predict the next token given what came before.

That's it. There's no comprehension happening, no reasoning in the way humans reason. What emerges is something powerful: a system that has implicitly encoded grammar, facts, logical relationships, code syntax, storytelling patterns, and more — because all of these were needed to predict text well.

"Large" is the critical qualifier. Small language models exist and can't do much. As models scale — more parameters, more data, more compute — emergent capabilities appear that weren't present at smaller sizes: reasoning, multi-step problem solving, following complex instructions.

Key Insight

LLMs do not retrieve answers from a database. They generate token by token, sampling from a probability distribution each time. The "knowledge" is baked into billions of parameters during training — there's no lookup table, no search index, no memory of individual conversations.

02 — Tokens

The atom of language — not words, but pieces

LLMs don't process words — they process tokens. Tokens are sub-word units produced by a vocabulary built during training (commonly using the BPE algorithm — Byte Pair Encoding).

Common words are often a single token. Rare or long words are split into multiple. "unbelievable" might be 3 tokens: un, believ, able. Code is tokenized differently from prose. Spaces before words are often included in the token.

This matters because: model pricing is per token, context windows are measured in tokens, and the model "sees" tokens — not words. Roughly 750 words ≈ 1,000 tokens in English prose.

03 — The Transformer

The architecture that changed everything — introduced in 2017

Before 2017, sequential models (RNNs, LSTMs) processed text one word at a time — slow, and bad at long-range dependencies. The Transformer ("Attention Is All You Need," Google, 2017) processes all tokens simultaneously, relating any token to any other via attention.

Each stage in the Transformer pipeline transforms the token representations in a specific way. Together, they allow the model to understand relationships across the entire context window simultaneously.

Depth = Abstraction

GPT-2 had 48 layers. GPT-3 had 96. Each layer refines representations — early layers capture syntax, middle layers capture semantics, deep layers capture abstract reasoning. Stacking layers is how depth creates intelligence.

04 — Attention

How the model decides what to focus on

The attention mechanism lets every token look at every other token and decide how relevant it is. For each token, it computes a weighted sum of all other tokens' values — weighted by relevance scores (called attention weights).

This is how "it" in "The animal didn't cross the street because it was tired" gets connected to "animal" rather than "street" — the model learns that "it" should attend to the subject, not the obstacle.

Multi-head attention runs this process in parallel across multiple "heads" — each learning a different type of relationship: syntactic, semantic, coreference, positional.

05 — Prediction

Generating text, one token at a time

After the forward pass through all layers, the model's final layer (the LM Head) projects the hidden state into a probability distribution over the entire vocabulary — often ~50,000 tokens. The model then samples from this distribution to pick the next token.

This is then appended to the context, and the whole process runs again. This is called autoregressive generation — each new token depends on all previous tokens.

06 — Training vs Inference

Building the model vs using the model

There are two entirely distinct phases in an LLM's life. Training is extraordinarily expensive — done once by the lab. Inference is what happens every time you send a message.

Training — done by the lab
📚Massive corpus — trillions of tokens from web, books, code, scientific papers. Carefully filtered.
🎯Objective: predict the next token. Loss = how wrong the prediction was. Minimize loss across all tokens.
⬅️Backpropagation — errors flow backward through the network, adjusting every weight by a tiny amount.
🔄Billions of steps across the full dataset (multiple epochs). Takes weeks on thousands of GPUs.
💰Cost: Frontier models cost $50M–$500M+ to train. GPT-4 reportedly ~$100M.
Inference — what happens when you chat
💬Your prompt is tokenized and fed into the frozen model (weights don't change during inference).
⚡Forward pass only — one pass through all layers, no backpropagation. Much faster than training.
🎲Token-by-token generation — each new token appended to context, then next pass begins.
📏Context window limits how much the model can see — from 4k tokens (GPT-3) to 200k (Claude).
💳Cost: priced per token. ~$0.003 per 1k tokens on GPT-4. Users pay for inference.
Fine-tuning and RLHF

A base model trained only on next-token prediction is not yet a helpful assistant — it just continues text. To make it useful, labs apply two more stages:

Supervised Fine-Tuning (SFT): The model is trained on curated examples of good conversations, written by human contractors. This teaches it the format of helpful responses.

RLHF — Reinforcement Learning from Human Feedback: Humans compare pairs of model outputs and rank them. These rankings train a "reward model." Then RL (specifically PPO) is used to optimize the LLM against this reward model. This is how Claude and ChatGPT learned to be safe, honest, and helpful.

RLHF Pipeline
STEP 1 Base model — pretrained on text. Can continue any prompt but won't follow instructions safely.
↓
STEP 2 SFT — trained on curated human-written conversations. Learns format + tone of helpfulness.
↓
STEP 3 Reward model trained on human rankings of model outputs. Encodes human preferences.
↓
STEP 4 RL optimization — model learns to maximize reward score. Output: a helpful, harmless assistant.

07 — Temperature & Sampling

Controlling randomness in generation

Every time the model generates a token, it produces a probability distribution. Temperature scales this distribution before sampling:

Low temperature (0–0.3): Distribution becomes sharp — the most likely token almost always wins. Deterministic, repetitive, predictable. Good for code and factual Q&A.

High temperature (0.8–1.5): Distribution flattens — rare tokens become more likely. Creative, varied, sometimes nonsensical. Good for brainstorming and creative writing.

Temperature = 0 is essentially greedy decoding — always pick the highest-probability token. Same input → same output every time.

08 — Limits & Failure Modes

What LLMs cannot do — and why

Hallucination
LLMs generate plausible-sounding text even when the content is false. They have no truth-checking mechanism — they optimize for token probability, not factual accuracy. Confident wrongness is a fundamental property, not a bug to be patched.
No persistent memory
Each conversation starts fresh. The model has no memory between sessions. "Memory" features in chat apps are implemented externally — relevant past conversations are injected into the context window, not stored in the model.
Knowledge cutoff
Training data has an end date. Events after the cutoff are unknown to the model. RAG (retrieval-augmented generation) injects current information into the context at inference time to mitigate this.
Context window limit
The model can only attend to what's in the current context window. Older Claude models had 8k tokens; Claude 3 supports 200k. Information beyond the window is simply invisible — the model cannot access it.
No real reasoning
LLMs can mimic reasoning steps, but they don't reason in the formal sense. Chain-of-thought prompting improves performance by forcing the model to generate intermediate steps — but it's still next-token prediction, not logical deduction.
Prompt sensitivity
The same question phrased differently can yield very different answers. Models are sensitive to framing, word order, and examples. This is why prompt engineering is a real skill — small changes in input can dramatically shift output quality.
