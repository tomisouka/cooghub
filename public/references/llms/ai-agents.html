01 — What is an AI Agent?

An LLM that can act on the world,
not just respond to it

A plain LLM takes an input and produces an output. One turn, one response, done. An AI agent is an LLM embedded in a loop — it can use tools, observe results, and keep going across many steps until a goal is achieved.

The key difference: agency. An agent doesn't just answer questions — it takes actions with real-world consequences. It can search the web, write and run code, read and write files, call APIs, send emails, control a browser. The LLM becomes the reasoning engine driving a system that acts.

This is why agents are the innermost ring in the AI hierarchy — they sit on top of all the layers below. A state-of-the-art agent is an LLM (transformer, deep learning, ML) that has been given tools and placed in a loop. Remove any layer and the agent stops working.

LLM vs Agent — the key distinction
Plain LLM
Input → LLM → Output
Single forward pass. No memory of what worked. No loop.

Why now?

Agents became practical when LLMs became reliable enough to follow complex instructions, use tools correctly, and recover from errors. GPT-4 and Claude 3 (2023–24) crossed the threshold where agents could complete real multi-step tasks without constant hand-holding.

02 — The Agent Loop

Reason, Act, Observe — repeat

Every agent, regardless of how complex, runs the same core loop. The LLM receives its current context (goal + history of what's happened so far) and decides what to do next: either call a tool, or produce a final answer.

ReAct (Reasoning + Acting) is the influential 2022 framework that formalized this: the model first writes out its thought (chain-of-thought reasoning), then an action (tool call), then receives an observation (tool result). This thought-action-observation trace becomes part of the context for the next iteration.

The loop terminates when: the agent decides the goal is complete, an error or limit is hit, or a maximum step count is reached. Without a termination condition, agents can run indefinitely — a real engineering concern.

agent_trace.log — ReAct loop
GOAL: Research current AI chip shortages and summarize key suppliers

→ Thought: I need to search for current information about AI chip shortages.
→ Action: web_search("AI chip shortage 2025 suppliers")
→ Observation: [10 results returned: TSMC, NVIDIA, Samsung…]

→ Thought: I should fetch the most relevant article for details.
→ Action: web_fetch("https://reuters.com/tech/ai-chips-2025")
→ Observation: [Article content: TSMC leads at 2nm, demand up 340%…]

→ Thought: I have enough information to write a comprehensive summary.
→ Final Answer: Based on current data, the three key AI chip suppliers are…

03 — Tools

How agents reach into the real world

Tools are functions the agent can call to interact with the world beyond its context window. The LLM doesn't directly execute code or browse the web — it outputs a structured tool call, an external system runs it, and the result comes back as an observation.

Modern LLMs are trained to emit tool calls in a structured format (usually JSON). The quality of tool use — knowing when to use which tool, and how to handle results — is a key determinant of agent capability.

tool_call_format.json
// The LLM emits this structured output when it wants to call a tool:
{
  "type": "tool_use",
  "name": "web_search",
  "input": {
    "query": "TSMC 2nm chip production 2025"
  }
}

// The tool runs, result injected back as a tool_result message:
{
  "type": "tool_result",
  "content": "TSMC plans mass production of 2nm chips in H2 2025, targeting AI accelerators…"
}
04 — Memory

The four types of agent memory

Memory is what separates a single-turn LLM from a persistent agent. Agents can have multiple memory systems, each operating on a different timescale and scope.

The context window is short-term memory

Everything the agent "knows" during a session lives in the context window. This is why context window size matters for agents — a 200k token window can hold far more history, tool results, and reasoning traces than an 8k window. When the context fills, earlier information is lost (or must be summarized).

06 — Multi-Agent Systems

Networks of agents working together

A single agent has limits — context window size, parallelism, specialization. Multi-agent systems address this by running multiple specialized agents in concert, coordinated by an orchestrator.

An orchestrator agent breaks a high-level task into sub-tasks and delegates to specialist subagents — one for research, one for writing, one for code execution. Results flow back to the orchestrator which synthesizes them.

This enables tasks that would exceed a single context window, benefit from parallel execution, or require different specialized capabilities. Claude Code, Devin, and AutoGPT all use multi-agent patterns internally.

Key challenges: coordination overhead, error propagation (one agent's mistake cascades), trust (should agents verify each other's outputs?), and cost (every agent step burns tokens).

07 — Risks & Challenges

What can go wrong — and why it matters

Agents are more powerful than plain LLMs — and more dangerous. When an agent can take real-world actions, mistakes compound across steps and may be hard to reverse. Understanding failure modes is essential.
