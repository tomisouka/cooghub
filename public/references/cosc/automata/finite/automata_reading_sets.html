Formal Languages  ·  Automata Theory  ·  Computability

Why sets feel weird: Set notation in automata theory packs a lot of meaning into a small space. The trick is learning to read left-to-right like a sentence — what are we collecting → where are elements drawn from → under what conditions. This guide builds that instinct step by step, grounded in computability examples.
🔬

Anatomy of a Set Expression

The three-part structure behind almost every set definition

Most sets in automata theory follow one template. Once you recognize it, any set expression becomes readable:

{ w ∈ Σ* | |w|ₐ = |w|_b }
{    w ∈ Σ*   |   |w|ₐ = |w|_b  }
braces — "the set of"
element + domain
condition — the "such that"
"The set of all strings w drawn from Σ*, such that the number of a's in w equals the number of b's in w."

The Four Parts

PartSymbol / FormWhat it says
Collector{ ... }"The set of all..."
Variable + Domainw ∈ Σ*"...strings w, drawn from Σ*..." — tells you what type of thing you're collecting
Separator|   or   :"...such that..." — both mean the same thing; usage is convention
ConditionP(w)"...the condition P holds." — the filter that decides what gets included
Reading Strategy Always say "the set of all ___ such that ___" out loud. The variable tells you the type; the condition tells you the filter. If you can't verbalize it naturally, you haven't fully parsed it yet.

Domains in Automata Theory

What the element's domain tells you about what you're working with

The domain after ∈ is your first clue about what kind of object you're dealing with:

DomainType of objectExample set definition
Σ*Any string over alphabet Σ{ w ∈ Σ* | w starts with 0 }
Σ⁺Non-empty strings{ w ∈ Σ⁺ | |w| is even }
QStates of an automaton{ q ∈ Q | δ(q, a) = q }
ℕNatural numbers{ n ∈ ℕ | n is prime }
LStrings inside a language L{ w ∈ L | |w| > 5 }
⟨M, w⟩Encoded TM-input pairs{ ⟨M, w⟩ | M accepts w }
Watch Out When the domain is omitted — like { w | P(w) } — it's implied from context. In automata this almost always means w ∈ Σ*. Always check what the surrounding text is discussing before assuming.

Reading the Condition

The part after the | — what actually filters membership

Simple Conditions

ConditionSay it as
|w| = n"the length of w is n"
|w| is even"the length of w is even"
w starts with 0"w starts with 0"
w = wʳ"w is a palindrome" — equals its own reverse
δ*(q₀, w) ∈ F"the DFA accepts w" — extended transition reaches an accepting state
M accepts w"Turing machine M halts and accepts w"

Conditions with Counting

A subscript on |w| means "count of that symbol in w":

|w|ₐ = |w|_b
"The number of a's in w equals the number of b's in w."
|w|₀ ≥ |w|₁
"The number of 0's in w is at least the number of 1's in w."

The nᵐ Exponent Pattern

The notation 0ⁿ1ⁿ means "n zeros followed by n ones." The variable n is implicitly existentially quantified:

{ 0ⁿ1ⁿ | n ≥ 0 }
"Strings of the form n zeros followed by n ones, for some n ≥ 0." Includes ε when n = 0.
{ aⁿbⁿcⁿ | n ≥ 1 }
"Strings with n a's, n b's, and n c's, for any n ≥ 1." Classic context-sensitive language — not context-free.
Key Insight When you see 0ⁿ1ⁿ, the same n is linking both counts together. That coupling is exactly what a DFA cannot check — it would need unbounded memory. Recognizing this linkage lets you immediately reason about computational power required.

Compound Conditions (∧ and ∨)

{ w ∈ Σ* | w starts with 1 ∧ |w| ≥ 3 }
"The set of strings that start with 1 AND have length at least 3." Both conditions must hold.
{ w ∈ {0,1}* | w contains 00 ∨ w contains 11 }
"Strings over {0,1} that contain '00' or '11' (or both)."

Languages as Sets

How automata theorists define what their machines recognize

A language is just a set of strings. L = { ... } defines which strings belong — equivalently, which inputs a machine should accept.

The Language of a Machine

L(M) = { w ∈ Σ* | M accepts w }
L(M) = { w ∈ Σ*  |  M accepts w }
"The language of M is the set of all strings w over Σ that machine M accepts."
PartMeans
L(M)The language recognized by M — just a name for the resulting set
w ∈ Σ*w is any string over the input alphabet
M accepts wRunning M on w reaches an accepting state (DFA/NFA) or halt-accepts (TM)

Classic Computability Problems as Sets

A_DFA = { ⟨B, w⟩ | B is a DFA and B accepts w }
⟨B, w⟩  |  B is a DFA  ∧  B accepts w
"The acceptance problem for DFAs." This language is decidable — we can simulate B on w in finite time.
A_TM = { ⟨M, w⟩ | M is a TM and M accepts w }
⟨M, w⟩  |  M is a TM  ∧  M accepts w
"The acceptance problem for Turing machines." Turing-recognizable but not decidable — M might loop forever on non-accepting inputs.
HALT_TM = { ⟨M, w⟩ | M is a TM and M halts on w }
⟨M, w⟩  |  M is a TM  ∧  M halts on w
"The halting problem: all (M, w) pairs where M eventually halts — accept or reject." Also undecidable.
Note on ⟨M, w⟩ encoding The angle brackets ⟨M, w⟩ denote an encoding — M and w serialized into a single string a TM can read. When a set is defined over ⟨M, w⟩, you're in the realm of computability. The condition after | is a statement about what M does when given input w.

Set Operations on Languages

Building new languages from existing ones

OperationWritten asRead as / Means
UnionL₁ ∪ L₂"strings in L₁ or L₂ (or both)" — NFA with ε-transitions to both machines
IntersectionL₁ ∩ L₂"strings in both L₁ and L₂" — product construction on DFAs
ComplementL̄ or Σ* \ L"all strings NOT in L" — swap accepting/non-accepting states in a DFA
ConcatenationL₁L₂ or L₁ · L₂"any string xy where x ∈ L₁ and y ∈ L₂"
Kleene starL*"zero or more concatenations of strings from L" — includes ε
DifferenceL₁ \ L₂"strings in L₁ but not in L₂" — same as L₁ ∩ L̄₂

Reading a Complement

L̄ = Σ* \ L = { w ∈ Σ* | w ∉ L }
w ∈ Σ*  such that  w ∉ L
"The set of all strings over Σ that are NOT in L." Complement flips membership. Regular and decidable languages are both closed under complement.
Closure Tip Regular: closed under ∪, ∩, complement, concatenation, and *. Context-free: closed under ∪, concatenation, and * — but not ∩ or complement. Decidable: closed under all Boolean operations. Recognizable: closed under ∪ and ∩ — but not complement.

Quantifiers Inside Set Conditions

When ∀ and ∃ appear inside the condition — read carefully

{ w ∈ Σ* | ∃x ∈ Σ*, w = 0x1 }
w ∈ Σ*  |  ∃x ∈ Σ* ,  w = 0x1
"Strings w such that THERE EXISTS some string x where w is '0' followed by x followed by '1'." Plain English: all strings that start with 0 and end with 1.
{ M | ∀w ∈ Σ*, M rejects w }
M  |  ∀w ∈ Σ* ,  M rejects w
"The set of Turing machines M such that FOR ALL strings w, M rejects w." This is TMs recognizing the empty language — undecidable by Rice's theorem.

∃ vs ∀ — The Key Distinction

QuantifierMeaningTo verify membership...
∃x, P(x)"there exists at least one x satisfying P"Find one witness — just needs one example
∀x, P(x)"for every x, P holds"Must rule out all counterexamples — much harder
Computability Implication When the condition has ∀w ranging over an infinite domain like Σ*, you generally can't check it by enumeration — this is why many universality and totality problems are undecidable. ∀ over an infinite set in a condition is a red flag for undecidability.

Step-by-Step Reading Method

A repeatable procedure for any set expression you encounter

  1. Find the braces. Everything inside { } defines the set. Note whether there's a | or : separator.
  2. Read the variable and domain. What type of object is this? (w ∈ Σ* = string, q ∈ Q = state, ⟨M, w⟩ = encoded TM-input pair)
  3. Say "such that" at the separator. The | is always "such that". Say it aloud — it forces you to connect both halves.
  4. Parse the condition left-to-right. Is it a predicate? A count? An equation? A quantified statement? Identify any ∧, ∨, ∀, ∃.
  5. Reconstruct in plain English. "The set of all [type] such that [condition]." If it sounds awkward, revisit step 4.
  6. Ask: what machine could recognize this? Checkable in finite memory (→ regular), with a stack (→ CFL), TM in finite time (→ decidable), or not at all (→ undecidable)?

Practice: Read These Sets

Try each one yourself first — click to reveal the reading

{ w ∈ {0,1}* | w contains equal numbers of 0s and 1s }
▶ Show reading
"The set of all binary strings that have exactly as many 0s as 1s." For example: ε, 01, 10, 0011, 0101, 1100... This language is context-free (recognized by a PDA) but not regular — a DFA can't count arbitrarily.
{ ⟨M⟩ | M is a TM and L(M) = ∅ }
▶ Show reading
"The set of all encodings of Turing machines M whose language is empty — i.e., M rejects every possible input." This is EMPTY_TM. By Rice's theorem, since "L(M) = ∅" is a non-trivial semantic property of TMs, this problem is undecidable.
{ w ∈ {a,b}* | w = xyx for some x, y ∈ Σ* with |x| ≥ 1 }
▶ Show reading
"Strings over {a,b} that can be written in the form xyx, where x is a non-empty string and y is any (possibly empty) string." In other words: strings where some non-empty prefix also appears again starting somewhere in the middle. This is non-regular.
EQ_DFA = { ⟨A, B⟩ | A and B are DFAs and L(A) = L(B) }
▶ Show reading
"The set of pairs of DFAs (A, B) that recognize exactly the same language." This is the DFA equivalence problem. It's decidable — check whether L(A) △ L(B) = ∅ using DFA minimization or product construction.
{ w | ∃u ∈ Σ*, uu = w }
▶ Show reading
"Strings w such that there exists some string u where w equals u concatenated with itself." In other words: strings that are perfect squares — two identical halves. Examples: abab, 0101, aa, 00. Not recognizable by a DFA, and not even context-free.

Common Confusions

Notation that regularly trips people up

The empty string ε is in Σ*

When a set is defined over Σ*, the empty string ε is always a candidate. Always check whether ε satisfies the condition. For { 0ⁿ1ⁿ | n ≥ 0 }, yes — ε is included (n=0). For { w ∈ Σ* | |w| ≥ 1 }, no — ε is excluded.

Σ* vs Σ⁺

DomainIncludes ε?Means
Σ*YesAll strings including the empty string
Σ⁺NoAll non-empty strings — Σ* minus {ε}

The | symbol has two meanings in the same expression

{ w ∈ Σ* | |w| = 3 }
The first | is the set-builder separator ("such that"). The |w| is length notation ("the length of w"). They look identical — the set-builder | sits between the variable clause and the condition; the length bars |·| surround a term.

L(M) is a set, not a machine

L(M) names the language (set of strings) that machine M recognizes. When you write L(M) = L(N), you're saying the two machines recognize the same set — not that the machines are identical or even similar in structure.

The condition can define a pattern, not just a predicate

In { w ∈ Σ* | w = 0ⁿ1ⁿ for some n ≥ 0 }, the condition describes a structural pattern — not an equation to solve. "w = 0ⁿ1ⁿ" means "w has the shape: exactly n zeros then n ones, for some specific n."
