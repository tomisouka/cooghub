1 — The ADT Interface
A Stack is an Abstract Data Type — it defines what operations exist, not how they're built internally. You can implement it with an array or a linked list — the interface stays the same.
Stack ADT — Operations
push(val) Add val to the top of the stack
pop() Remove and return the top element
peek() Return the top element without removing it
isEmpty() Return true if the stack has no elements
size() Return the number of elements
2 — LIFO — Stack of Plates
Always add to the top, always remove from the top. You never touch the middle or bottom.

3 — Two Implementations, Same Interface
The ADT doesn't care how it's built. Both give O(1) push and pop.
Array-Based
top index into array
push arr[++top] = val
pop return arr[top--]
memory contiguous, cache-friendly
overflow fixed capacity — needs resize
Linked List-Based
top head node
push insert at head
pop remove head
memory scattered, pointer overhead
overflow dynamic — grows as needed
4 — Array Implementation

Key Properties
ADT — Not a Structure
Stack defines behavior only: push, pop, peek. The internal structure is an implementation detail hidden from the user.
abstraction
LIFO
Last In, First Out. Whatever you pushed most recently is always the next thing that comes out.
last in = first out
Top Access Only
No random access. You can only ever see or touch the top element. Middle and bottom are unreachable.
top only
All Core Ops O(1)
Push, pop, and peek are constant time in both array and linked list implementations.
O(1)
Used In
Function call stack, undo/redo, expression parsing, backtracking, DFS, browser back button.
everywhere
