1 — Vertices and Edges — No Root, No Rules
A graph is a set of vertices (nodes) connected by edges. Unlike a tree — no root, no parent-child requirement, no hierarchy. Any vertex can connect to any other.
V = 6 vertices, E = 9 edges. No root. No level. A is connected to B, D, E — but not F directly. This is an undirected weighted graph.
2 — Four Graph Types
Graphs vary on two axes: directed vs undirected and weighted vs unweighted. These combine into four types.
Undirected · Unweighted
Edges go both ways. No cost on edges. Friends on social media — if A follows B, B follows A.
Directed · Unweighted
Edges are one-way arrows. Twitter follows — A can follow B without B following A.
Undirected · Weighted
Edges have costs — distances on a map. Road between two cities is the same distance both ways.
Directed · Weighted
One-way edges with costs. GPS routing, flight paths. Dijkstra's algorithm runs on this.

4 — BFS vs DFS Traversal
Starting from vertex A on this graph: A–B, A–C, B–D, B–E, C–F. Both visit every vertex exactly once in O(V+E).
BFS — Breadth First Search
Level by level. Uses a queue. Finds shortest path in unweighted graphs.
1Enqueue A. Visit A.
2Dequeue A. Enqueue neighbors B, C.
3Dequeue B. Enqueue D, E. Visit B.
4Dequeue C. Enqueue F. Visit C.
5Continue until queue empty.
DFS — Depth First Search
Go as deep as possible first. Uses a stack (or recursion). Detects cycles.
1Visit A. Push neighbors onto stack.
2Pop B. Visit B. Push D, E.
3Pop D. Visit D. No unvisited neighbors.
4Pop E. Visit E. Backtrack to C, F.
5Continue until stack empty.

BFS vs DFS
BFS uses a queue — finds shortest path. DFS uses a stack — detects cycles, explores deep paths. Both O(V+E).

Matrix for dense graphs — fast edge lookup. List for sparse graphs — saves space. Most real graphs are sparse.
