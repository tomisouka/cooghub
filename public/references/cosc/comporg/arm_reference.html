The Iron Law of Performance

Iron Law
CPU Time = Instruction Count × CPI × Clock Cycle Time = (IC) × (CPI) × (1 / Clock Rate)

Each factor is influenced by different things: IC → algorithm & compiler; CPI → ISA & microarchitecture; Clock Rate → technology & circuit design.

Amdahl's Law

Amdahl's Law — upper bound on speedup
Speedup = 1 / [ (1 − Fraction_enhanced) + (Fraction_enhanced / Speedup_enhanced) ]

Key insight: make the common case fast. If 10% of code is serial, max parallelism speedup is 10×, no matter how many cores.

Pipeline Hazards

Types of Hazards

Hazard TypeProblemCausesSolutions
Structural Hazardhardware conflictTwo instructions need same resource in same cycle (e.g., one memory for both instr. fetch and data)Separate instruction & data memory (Harvard); add more hardware units
Data Hazard (RAW)read before write completesInstruction needs result not yet written back by earlier instructionForwarding (bypassing), pipeline stalls (bubbles), compiler scheduling
Data Hazard (WAR)write before stale read completesOut-of-order: later write reaches dest before earlier read sees old valueIn-order pipelines: rarely an issue; out-of-order: register renaming
Data Hazard (WAW)two writes, wrong orderOut-of-order: second write completes before firstRegister renaming, in-order commit

Forwarding (Bypassing)

Instead of waiting for Write Back, route ALU result directly from EX/MEM or MEM/WB pipeline register back to the ALU input of a later instruction in EX stage.

Forwarding pathFrom where to whereHandles
EX-EX ForwardEX/MEM → ID/EX (ALU input)1-cycle-earlier dependency (immediate successor)
MEM-EX ForwardMEM/WB → ID/EX (ALU input)2-cycle-earlier dependency
Load-Use Hazardcannot forward in timeLDUR result not available until after MEM stage; need 1 stall (bubble) even with forwarding

Branch Prediction

StrategyWhat it doesAccuracy / Notes
Flush / Stallwait for branch outcomeAlways correct; 2-cycle penalty every branch
Predict Not Takenassume branch not taken; keep fetchingSimple; flush if wrong; good for forward branches
Predict Takenassume branch takenGood for backward branches (loops)
1-bit Predictorremember last outcomeMispredicts first and last iteration of loops
2-bit Predictorchange prediction only after 2 missesMuch better for loops; standard in modern CPUs
Tournament Predictorchoose between local & global predictors>95% accuracy typical; modern CPUs use neural/perceptron predictors

Pipeline Stall (Bubble)

A stall inserts a NOP-equivalent cycle (bubble) into the pipeline by holding the PC and IF/ID registers and inserting zeros into the ID/EX register. This gives earlier instructions time to complete.

Key Formulas & Quick Reference

Performance

Iron Law
CPU Time = IC × CPI × (1 / Clock Rate) = IC × CPI × Clock Cycle Time
Speedup
Speedup = Performance_new / Performance_old = Time_old / Time_new
Amdahl's Law
Speedup_overall = 1 / [(1 − Fraction_enhanced) + (Fraction_enhanced / Speedup_enhanced)]
MIPS
MIPS = IC / (CPU_Time × 10⁶) = Clock_Rate / (CPI × 10⁶)
Dynamic Power (CMOS)
P = α × C × V² × f where: α = activity factor, C = capacitance, V = supply voltage, f = frequency

Memory & Cache

AMAT
AMAT = Hit_Time + Miss_Rate × Miss_Penalty (for multi-level: AMAT_L1 + MissRate_L1 × AMAT_L2 + ...)
Cache Address Decomposition
Offset bits = log₂(block_size_in_bytes) Index bits = log₂(number_of_sets) Tag bits = address_bits − index_bits − offset_bits
Cache Sizing
Cache size = number_of_sets × associativity × block_size
Virtual Memory
Page Offset bits = log₂(page_size) VPN bits = virtual_address_bits − page_offset_bits Number of page table entries = 2^(VPN bits)

Pipelining

Pipeline Throughput (ideal)
CPI_ideal = 1 CPI_actual = 1 + Stalls_per_instruction Pipeline Speedup ≈ pipeline_depth (ideal, all stages equal, no hazards)
Branch Penalty
CPI_branch = CPI_base + Branch_frequency × Branch_penalty_cycles
