Basics & Structure

Every C++ program starts with main(). Source files end in .cpp; headers in .h or .hpp.

// Hello World — the classic start #include <iostream> int main() { std::cout << "Hello, World!" << std::endl; return 0; // 0 = success }

// commenthuman note, ignoredSingle-line; use /* */ for multi-line

Functions

Functions encapsulate reusable logic. In C++, they must be declared before use (forward declarations or definitions above call site).

// Declaration (prototype) — tells compiler it exists int add(int a, int b); // Definition — actual code int add(int a, int b) { return a + b; } // Default parameters void greet(std::string name, int times = 1); // Function overloading — same name, different params double add(double a, double b) { return a + b; } // Pass by value — copy void byValue(int x) { x = 99; } // caller's x unchanged // Pass by reference — alias void byRef(int& x) { x = 99; } // caller's x changes! // Pass by pointer void byPtr(int* x) { *x = 99; } // caller's x changes // Const reference — read without copy void readOnly(const std::string& s) { /* can't modify s */ } // Lambda (C++11) auto square = [](int x) { return x * x; }; auto capture = [&count](int x) { count++; return x; };

Classes & OOP

C++ supports four pillars of OOP: encapsulation, abstraction, inheritance, polymorphism.

class Animal { public: std::string name; // public member Animal(std::string n) : name(n) {} // constructor w/ init list virtual void speak() const { std::cout << "..."; } // virtual! virtual ~Animal() {} // virtual destructor — ALWAYS for base classes private: int age = 0; // private member }; class Dog : public Animal { // public inheritance public: Dog(std::string n) : Animal(n) {} // call base constructor void speak() const override { std::cout << "Woof!"; } };

Templates

Templates enable generic programming — write code once, use with any type. Instantiation happens at compile time.

// Function template template<typename T> T maximum(T a, T b) { return (a > b) ? a : b; } // Class template template<typename T, int Size> class Stack { T data[Size]; int top = 0; public: void push(T val) { data[top++] = val; } T pop() { return data[--top]; } }; // Usage int m = maximum(3, 7); // T deduced as int Stack<double, 10> myStack; // explicit instantiation // Template specialization template<> bool maximum<bool>(bool a, bool b) { return a || b; }

Exceptions

Exceptions handle unexpected error conditions. They unwind the stack, calling destructors (RAII cleans up automatically).

try { if (x < 0) throw std::invalid_argument("x must be positive"); if (x == 0) throw std::runtime_error("division by zero"); // ... } catch (const std::invalid_argument& e) { std::cerr << "Bad arg: " << e.what() << std::endl; } catch (const std::exception& e) { // catch all std exceptions std::cerr << "Error: " << e.what() << std::endl; } catch (...) { // catch absolutely anything std::cerr << "Unknown error!" << std::endl; }

Operator Precedence

Higher = evaluated first. When in doubt, use parentheses.

  1. Scope resolution: ::
  2. Postfix: x++ x-- f() a[] . ->
  3. Prefix/Unary: ++x --x +x -x ! ~ * & new delete sizeof
  4. Pointer-to-member: .* ->*
  5. Multiplicative: * / %
  6. Additive: + -
  7. Bitwise shift: << >>
  8. Three-way comparison: <=> (C++20)
  9. Relational: < > <= >=
  10. Equality: == !=
  11. Bitwise AND: &
  12. Bitwise XOR: ^
  13. Bitwise OR: |
  14. Logical AND: &&
  15. Logical OR: ||
  16. Ternary & throw: ?: throw
  17. Assignment: = += -= *= /= %= &= |= ^= <<= >>=
  18. Comma: , (lowest)

Pro Tips

Common Pitfalls — Context Matters!

  • = vs ==if (x = 5) assigns 5 (always true!); if (x == 5) compares. Use if (5 == x) to catch this bug.
  • int / intInteger division truncates: 7/2 == 3, not 3.5. Cast one side: (double)7/2 == 3.5
  • *ptr vs ptrptr is the address; *ptr is the value. Dereferencing null/invalid pointer = undefined behavior.
  • new vs new[]new int[n] must be freed with delete[], not delete. Mixing them = undefined behavior.
  • ++i vs i++Prefer ++i in loops — i++ creates a temporary copy. Same result here, but ++i is never slower.
  • include orderAlways include your own headers first, then system headers. This catches missing dependencies in your own headers.
  • virtual dtorIf a class has ANY virtual function, its destructor should also be virtual. Otherwise delete basePtr leaks derived data.
  • const & refsPass objects by const T& to avoid copies without modification. Prefer T&& (move) for temporaries.
  • RAIITie every resource (memory, file, lock) to an object's lifetime. Smart pointers, lock_guard, fstream all do this for you.
  • UBUndefined Behavior (signed overflow, out-of-bounds, null deref) lets the compiler do anything — even make demons fly out of your nose.
