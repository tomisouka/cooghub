Three-Way Divide · Sorted Array or Unimodal Functions
best O(1)
average O(log₃ n) = O(log n)
worst O(log₃ n)

1 — The Idea
Like binary search, but divide into three parts instead of two. Pick two midpoints — m1 at 1/3 and m2 at 2/3 of the search range. Compare target to both. This eliminates one third of the range each step instead of one half. Counterintuitively, this is not faster than binary search — it uses more comparisons per step.

3 — Ternary vs Binary: The Comparison Math
PropertyBinary SearchTernary Search
Comparisons per step12
Fraction eliminated1/21/3 (keeps 2/3)
Steps to solvelog₂ nlog₃ n = log₂n / log₂3
Total comparisonslog₂ n2 × log₃ n ≈ 1.26 × log₂ n
Real-world speedFaster~26% more comparisons
Best use caseSorted arraysUnimodal function optimization
Binary search wins for array searching. Ternary wins for finding the maximum of a unimodal (single-peaked) function where you can't check equality — only greater/less.
4 — Real Use Case: Unimodal Function Optimization
Finding the maximum of f(x) = −(x−5)² + 25 over [0, 10]
If f(m1) < f(m2): peak is in [m1, R] → eliminate left third.
If f(m1) > f(m2): peak is in [L, m2] → eliminate right third.
No equality comparison needed — just which side is higher.
Key Properties
Eliminates 1/3 Per Step
Two midpoints split the range into thirds. Each step eliminates one third — the smallest or largest third depending on which side the target is in.
O(log₃ n)
Slower Than Binary for Arrays
2 comparisons per step vs 1. Despite fewer iterations, total comparison count is ~26% higher than binary search.
use binary instead
Unimodal Optimization
Shines when finding the max/min of a function with one peak. No equality check needed — just compare f(m1) vs f(m2).
