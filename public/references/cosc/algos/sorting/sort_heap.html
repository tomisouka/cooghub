1 — The Idea
Two phases. First: heapify the array into a max-heap — the largest element sits at index 0. Second: repeatedly swap the root (max) to the end, shrink the heap by one, and sift the new root down to restore the heap property. The sorted region grows from the right.
2 — Phase 1: Build Max-Heap from [4, 1, 3, 5, 2]
Start from the last non-leaf and sift down each node. This costs O(n) — not O(n log n).

Key Properties
Two Phases
Build max-heap: O(n). Extract all maximums: O(n log n). Total: O(n log n) — no best/worst case difference.
O(n) + O(n log n)
In-Place
Heap stored in the original array. The sorted region and the heap share the same array, shrinking/growing in opposite directions.
O(1) space
Poor Cache Performance
Sift-down jumps between parent and children indices. Memory access pattern is non-sequential — poor cache utilization.
cache unfriendly
Guaranteed O(n log n)
Unlike quicksort, no bad input can trigger worst-case behavior. Useful when worst-case guarantees matter more than average speed.
always O(n log n)
