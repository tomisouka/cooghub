Quick.

Divide & Conquer · In-Place · Unstable
best O(n log n)
average O(n log n)
worst O(n²) — bad pivot
space O(log n) — stack
1 — The Idea
Pick a pivot element. Partition the array so everything less than the pivot is on the left, everything greater is on the right. The pivot is now in its final position. Recursively sort both halves. The work is in the partition step — no merging needed.
2 — The Partition Step
Lomuto partition: pick last element as pivot. Walk with pointer i. For each element less than pivot, increment i and swap.

4 — The Worst Case Trap
If the pivot is always the min or max — sorted or reverse-sorted array with last-element pivot — one partition gets n−1 elements and the other gets 0. The recursion tree degenerates into a linked list: O(n²).
Fix: median-of-three pivot selection (pick median of first, mid, last) or random pivot eliminates worst case in practice.

Key Properties
Partition is the Work
Everything happens in partition. The pivot ends up in its final position. No merging — just recursive partition.
partition → place
In-Place
Sorts within the original array. Only O(log n) stack space for recursion. Cache-friendly — huge practical advantage.
O(log n) space
Pivot Choice Matters
Bad pivot → O(n²). Random pivot or median-of-3 makes worst case extremely unlikely in practice.
O(n²) worst
Unstable
Partition swaps can move equal elements past each other. Order of equal elements is not preserved.
unstable ✗
