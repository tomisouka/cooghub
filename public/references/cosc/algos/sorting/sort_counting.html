Counting.

Non-Comparison Sort · Stable · Integer Keys Only
time O(n + k)
space O(k) — count array
n = number of elements
k = range of values (max−min)
1 — The Idea
No comparisons — instead, count how many times each value appears. Then convert counts to positions using a prefix sum. Finally, place each element at its computed position in the output array. Beats O(n log n) because it exploits the fact that keys are integers in a known range.

No comparisons made. O(n) to count + O(k) to build prefix sums + O(n) to place = O(n+k). When k is small relative to n, this beats any comparison sort.
Key Properties
No Comparisons
Breaks the O(n log n) lower bound for comparison sorts. Uses counting and arithmetic instead. Keys must be integers in a bounded range.
O(n + k)
Stable
Right-to-left placement preserves relative order of equal elements. Essential for Radix Sort, which uses Counting Sort as its subroutine.
stable ✓
When k is Large
If k ≫ n the count array wastes space and dominates. Sorting 10 numbers in range 0–1,000,000 is wasteful — use a comparison sort.
bad when k ≫ n
Used As Subroutine
Radix Sort uses Counting Sort digit by digit. TimSort uses insertion sort on small runs. Counting sort rarely used standalone.
