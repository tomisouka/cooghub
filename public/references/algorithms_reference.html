Algorithm Paradigms
Every algorithm is an instance of one of these problem-solving strategies
Divide & Conquer
Split → Solve → Combine
Break into subproblems, solve recursively, merge results. Subproblems are independent. Complexity via Master Theorem: T(n) = aT(n/b) + f(n)

Examples: Merge Sort, Quick Sort, Binary Search, FFT, Closest Pair of Points.
Dynamic Programming
Memoize Overlapping Subproblems
Like D&C but subproblems overlap — cache results to avoid recomputation. Two approaches: top-down (recursive + memo) or bottom-up (tabulation).

Examples: Fibonacci, Knapsack, LCS, Edit Distance, Matrix Chain, Kadane's.
Greedy
Locally Optimal → Globally Optimal
At each step, choose the locally best option and never look back. Works when the problem has the greedy choice property and optimal substructure.

Examples: Dijkstra, Kruskal, Prim, Huffman Coding, Activity Selection.
Backtracking
Explore + Prune
Build solution incrementally. Abandon (backtrack) when a partial solution can't lead to a valid complete solution. Exhaustive search with pruning.

Examples: N-Queens, Sudoku Solver, Subset Sum, Graph Coloring.
Randomized
Use Randomness to Simplify
Introduce randomness to avoid worst-case inputs or simplify analysis. Las Vegas: always correct, random runtime. Monte Carlo: always fast, probabilistically correct.

Examples: Randomized QuickSort, Karger's Min Cut, Skip Lists.
Two Pointers / Sliding Window
Linear Scan Tricks
Maintain two indices to avoid nested loops. Reduces O(n²) brute force to O(n).

Two pointers: sorted array problems, palindrome check.
Sliding window: max subarray sum, longest substring without repeat.

Searching Algorithms
Finding things — the most fundamental operation in computing
Linear Search
O(n) — scan everything
Check each element one by one. Works on unsorted data. O(n) time, O(1) space. The baseline — use when data is small or unsorted and the cost of sorting isn't worth it.
Binary Search
O(log n) — requires sorted data
Halve the search space each iteration. Requires sorted, random-access data. mid = lo + (hi - lo) / 2 avoids overflow.

Key insight: applies to any monotonic function — "find first x where f(x) = true."
BFS
Breadth-First Search
Explore layer by layer using a queue. Finds shortest path in unweighted graphs. O(V+E) time and space.

Use for: shortest path, level-order traversal, connected components, web crawlers.
DFS
Depth-First Search
Explore as deep as possible before backtracking. Uses a stack (implicit via recursion). O(V+E) time, O(V) space.

Use for: cycle detection, topological sort, strongly connected components, maze solving.
Graph Algorithms
The algorithms that power maps, networks, and compilers
Dijkstra's
Single-Source Shortest Path (non-negative weights)
Greedy — always expand the closest unvisited node. O((V+E) log V) with a min-heap. Fails on negative edges.

Use: GPS routing, network packet routing.
Bellman-Ford
Shortest Path with Negative Edges
Relax all edges V-1 times. O(VE). Slower than Dijkstra but handles negative weights and detects negative cycles.

Use: currency arbitrage detection, routing with costs that can be negative.
Floyd-Warshall
All-Pairs Shortest Path
Find shortest paths between ALL pairs of vertices. O(V³) — only practical for small V (<500). DP approach: for each intermediate vertex k, check if path through k is shorter.
Kruskal's / Prim's
Minimum Spanning Tree
Kruskal's: sort edges by weight, add if no cycle (Union-Find). O(E log E).
Prim's: grow MST from a seed vertex using min-heap. O(E log V).

Kruskal's better for sparse graphs, Prim's for dense.
Topological Sort
Order Dependencies
Linear ordering of DAG vertices where u→v means u comes before v. Only works on DAGs (cycle = impossible ordering). Two approaches: DFS finish-time reversal or Kahn's (BFS with in-degree counts).

Use: build systems, course prerequisites, task scheduling.
History of Algorithms
From ancient mathematics to modern computer science
~300 BC
Euclidean Algorithm
Euclid's Elements describes an algorithm to find the greatest common divisor. Arguably the first algorithm ever written down. Still used today in cryptography (RSA key generation).
~820 AD
Al-Khwarizmi
The word "algorithm" comes from his name. His book on arithmetic introduced systematic step-by-step problem solving — the foundation of algorithmic thinking.
1843
Ada Lovelace
Wrote the first published algorithm intended for a machine — Bernoulli numbers on Babbage's Analytical Engine. First programmer.
1936
Turing Machine
Alan Turing formalizes computation itself. The Turing Machine defines what problems are computable — and which ones aren't (the Halting Problem).
1956
Dijkstra's Algorithm
Edsger Dijkstra designs the shortest path algorithm in 20 minutes while sitting in a café with his fiancée — without pen and paper. Published 1959.
1959–1962
Dynamic Programming Formalized
Richard Bellman names and formalizes dynamic programming (1957). Floyd-Warshall (1962) gives the iconic all-pairs shortest path DP.
1965
Fast Fourier Transform
Cooley and Tukey rediscover the FFT, reducing DFT from O(n²) to O(n log n). One of the most important numerical algorithms ever — enables digital audio, image compression, and 5G.
1971
NP-Completeness
Stephen Cook proves SAT is NP-complete. Karp (1972) shows 21 more problems are NP-complete. The P vs NP question — whether every verifiable problem is also efficiently solvable — remains unsolved.
1977
RSA Encryption
Rivest, Shamir, Adleman publish RSA — the algorithm that secures the internet. Based on the hardness of integer factorization. Every HTTPS connection uses a descendant of this idea.
