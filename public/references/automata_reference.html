Automata History

From Turing's theoretical machines to the compilers running your code

Timeline
1936
Turing Machine
Alan Turing publishes "On Computable Numbers." Defines a theoretical machine that can simulate any algorithm. Establishes the limits of computation — the Halting Problem proves some questions are undecidable.
1943
McCulloch-Pitts Neurons
Warren McCulloch and Walter Pitts model the neuron as a binary threshold device — an early finite automaton. First formal model of a neural network and a precursor to FSM theory.
1951
Finite Automata (Kleene)
Stephen Kleene formalizes finite automata and introduces regular expressions — the notation we still use today. Kleene's theorem: regular languages = languages accepted by finite automata = languages described by regex.
1956
Chomsky Hierarchy
Noam Chomsky publishes "Three Models for the Description of Language." Establishes the four-level grammar hierarchy: regular → context-free → context-sensitive → recursively enumerable. Still the organizing framework for language theory.
1959
NFAs & Subset Construction
Rabin and Scott prove that nondeterministic finite automata (NFAs) are equivalent in power to DFAs. The subset construction algorithm converts any NFA to an equivalent DFA — exponential in the worst case but always finite.
1961
Pushdown Automata
Oettinger and Chomsky independently connect pushdown automata to context-free grammars. PDAs add a stack to finite automata — enough power to recognize nested structures like balanced parentheses and arithmetic expressions.
1965
Pumping Lemma
Bar-Hillel, Perles, and Shamir publish the pumping lemma for context-free languages. Becomes the canonical tool for proving a language is NOT context-free — a rite of passage in every theory of computation course.
1969
Cook-Levin & Complexity
Stephen Cook proves SAT is NP-complete (1971). Connects decidability to complexity — not just "can a TM solve it?" but "how efficiently?" P vs NP becomes the central open question in computer science.
1972–present
Compilers & Tools
Lex (1975) and Yacc (1975) bring automata theory into practice — DFAs for lexing, CFGs for parsing. Every modern compiler uses these ideas. JFLAP (1990s) makes automata visual and interactive for students.

Automata Theory Reference

Deterministic Finite Automata
Exactly one transition per symbol — the simplest machine that can recognize patterns
Definition
5-Tuple (Q, Σ, δ, q₀, F)
Q — finite set of states.
Σ — alphabet (finite set of symbols).
δ: Q × Σ → Q — transition function. Exactly one next state for every (state, symbol) pair.
q₀ ∈ Q — start state.
F ⊆ Q — set of accept states.
Computation
How a DFA Processes Input
Start in q₀. For each symbol in the input string, follow the transition δ(current, symbol) → next state. After reading all symbols, accept if current state ∈ F, reject otherwise. DFAs never get stuck — δ is total.
Regular Languages
What DFAs Can Recognize
A language is regular iff some DFA recognizes it. Regular languages are closed under union, concatenation, star (Kleene), complement, and intersection. Proved via product construction or De Morgan's laws.
Pumping Lemma (Regular)
Proving Non-Regularity
If L is regular with pumping length p, then any string s ∈ L with |s| ≥ p can be split into s = xyz where: |xy| ≤ p, |y| ≥ 1, and xyiz ∈ L for all i ≥ 0.

To prove non-regular: pick s cleverly, show no valid split exists. Classic: 0ⁿ1ⁿ is not regular.
Nondeterministic Finite Automata
Multiple possible transitions — same power as DFAs, easier to design
Definition
5-Tuple with Power Set
Like a DFA but δ: Q × Σε → 𝒫(Q). Each (state, symbol) maps to a set of next states (possibly empty). ε-transitions allowed — move without consuming input. An NFA accepts if any computation path reaches an accept state.
Subset Construction
NFA → DFA Conversion
Each DFA state = a set of NFA states. Start state = ε-closure(q₀). For each set S and symbol a: compute ε-closure(⋃q∈S δ(q,a)). DFA accepts if any NFA accept state is in the subset. Worst case: 2|Q| DFA states.
ε-Closure
Following ε-Transitions
ε-closure(q) = all states reachable from q by following zero or more ε-transitions. Essential for subset construction. Computed via BFS/DFS on ε-edges.

ε-transitions make NFA design cleaner — they don't add expressive power but allow modular construction.
Equivalence
NFA = DFA in Power
Theorem (Rabin & Scott, 1959): For every NFA there exists an equivalent DFA. Therefore NFAs recognize exactly the regular languages. NFAs are preferred for design; DFAs for implementation and analysis.
Regular Expressions
Algebraic notation for regular languages — equivalent to DFAs and NFAs
Base Cases
Atomic Regular Expressions
∅ — empty language. No strings.
ε — language containing only the empty string.
a (for a ∈ Σ) — language containing only the string "a".

These three are the atomic building blocks. Everything else is built from them.
Operations
Union, Concat, Star
R₁ ∪ R₂ — strings in R₁ or R₂ (or both).
R₁ ∘ R₂ — strings xy where x ∈ R₁ and y ∈ R₂.
R* — zero or more concatenations of strings from R. Always includes ε.
R⁺ = R ∘ R* — one or more. Does not include ε unless R does.
Kleene's Theorem
Regex ↔ DFA ↔ NFA
A language is regular iff it is described by a regular expression.

Regex → NFA: structural induction on the regex (Thompson construction).
DFA → Regex: state elimination (GNFA method) — convert states to transitions labeled with regexes, eliminate states one by one.
Common Patterns
Useful Regex Idioms
Strings starting with 1: 1(0∪1)*
Even number of 0s: build a DFA first, then convert.
Strings containing "001": (0∪1)*001(0∪1)*
At least two consecutive 1s: (0∪1)*11(0∪1)*
Strings of even length: ((0∪1)(0∪1))*
Context-Free Grammars
One level up from regular — powerful enough to describe nested structures and programming languages
Definition
4-Tuple (V, Σ, R, S)
V — variables (nonterminals).
Σ — terminals (the actual alphabet).
R — rules of the form A → w where A ∈ V and w ∈ (V ∪ Σ)*.
S ∈ V — start variable.

A string is in the language if it can be derived from S by applying rules.
Derivations
Leftmost & Parse Trees
A derivation is a sequence S ⇒ w₁ ⇒ w₂ ⇒ … ⇒ w.
A leftmost derivation always replaces the leftmost variable.
A parse tree shows the hierarchical structure.
Ambiguity: a grammar is ambiguous if some string has two distinct parse trees — a problem for compilers.
Chomsky Normal Form
CNF — Every Rule is A→BC or A→a
Every CFG can be converted to CNF. Required for the CYK parsing algorithm (O(n³)).

Steps: eliminate ε-rules, unit rules, and useless variables, then break long rules into binary. CNF grammars are clean but often much larger than the original.
Pumping Lemma (CFL)
Proving Non-Context-Freeness
For CFL L with pumping length p: any s ∈ L with |s| ≥ p can be split as s = uvxyz where |vy| ≥ 1, |vxy| ≤ p, and uvixyiz ∈ L for all i ≥ 0.

Classic non-CFL: aⁿbⁿcⁿ. The CFL pumping lemma is strictly harder to apply than the regular one.
Pushdown Automata
NFAs with a stack — exactly the machines that recognize context-free languages
Definition
6-Tuple (Q, Σ, Γ, δ, q₀, F)
Q — states. Σ — input alphabet. Γ — stack alphabet.
δ: Q × Σε × Γε → 𝒫(Q × Γε) — transitions consume input and pop/push stack symbols.
q₀ — start state. F — accept states.

PDAs are nondeterministic by default — deterministic PDAs (DPDAs) are strictly less powerful.
Stack Operations
Push, Pop, Peek
A transition reads (state, input symbol or ε, top of stack or ε) and writes (new state, symbol to push or ε).

Notation: a,b→c means "read a from input, pop b from stack, push c."
Use a bottom-of-stack marker (e.g. $) to detect empty stack.
Equivalence
PDA ↔ CFG
Theorem: A language is context-free iff some PDA recognizes it.

CFG → PDA: push S, then repeatedly pick a variable on the stack and nondeterministically apply a rule. Match terminals against input.
PDA → CFG: more involved — states become variables in the grammar.
Classic Example
Recognizing 0ⁿ1ⁿ
Push a marker for each 0. When 1s start, pop a marker for each 1. Accept if stack is empty when input ends.

This is the canonical example of a language that needs a stack — a DFA can't count arbitrarily deep. The stack provides the "memory" of how many 0s were seen.
Turing Machines
The most powerful computational model — a finite automaton with an infinite read/write tape
Definition
7-Tuple
(Q, Σ, Γ, δ, q₀, qaccept, qreject)

Γ — tape alphabet (includes blank ⊔ and all of Σ).
δ: Q × Γ → Q × Γ × {L,R} — read symbol, write symbol, move left or right.
Computation halts when it enters qaccept or qreject. May also loop forever.
Church-Turing Thesis
TMs Capture All Computation
Any algorithm that can be computed by any reasonable model of computation can be computed by a Turing Machine. Not a theorem — a philosophical claim. Supported by the equivalence of TMs, lambda calculus, recursive functions, and modern CPUs.
Variants
Multi-Tape, Nondeterministic, Enumerators
Multi-tape TM: multiple tapes and heads — equivalent to single-tape but polynomially faster.
Nondeterministic TM: equivalent in power but exponentially faster in some cases.
Enumerator: prints strings to an output tape — recognizes exactly the Turing-recognizable languages.
Decidable vs Recognizable
The Key Distinction
A language is Turing-decidable (recursive) if a TM always halts and accepts or rejects. Turing-recognizable (recursively enumerable) if a TM accepts all strings in L but may loop on strings not in L.

Every decidable language is recognizable. The converse is false.
Decidability & Undecidability
The hard limits of computation — problems no algorithm can solve
The Halting Problem
HALTTM is Undecidable
There is no TM that decides whether an arbitrary TM M halts on input w.

Proof (diagonalization): assume a decider H exists. Build a machine D that runs H on itself and does the opposite. D(D) leads to contradiction. Therefore H cannot exist.
Reductions
Proving Undecidability
To show problem B is undecidable: reduce a known undecidable problem A to B. If B were decidable, then A would be decidable — contradiction.

ATM = {⟨M,w⟩ | M accepts w} is the canonical undecidable language. Most undecidability proofs reduce from ATM.
Rice's Theorem
All Non-Trivial Properties are Undecidable
Any non-trivial property of the language recognized by a TM is undecidable. Non-trivial = some TMs have it, some don't.

Consequence: you cannot decide if a TM accepts all strings, accepts any string, accepts a finite language, or recognizes a regular language.
Complexity Preview
P, NP, and Beyond
P — decidable in polynomial time on a deterministic TM.
NP — decidable in polynomial time on a nondeterministic TM (equivalently: solutions verifiable in poly time).
NP-complete — hardest problems in NP. SAT, 3-SAT, Vertex Cover, Subset Sum.
P ⊆ NP. Whether P = NP is unsolved.
