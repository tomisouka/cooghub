Key Concepts to Nail
These are exam-heavy topics in most DB courses — understand them deeply
Normalization
The most exam-tested topic
Given a relation and FDs, determine the normal form and decompose to 3NF/BCNF. Practice finding all FDs, computing closures, and checking BCNF violations.

Key algorithm: find all FDs → check every non-trivial FD → if LHS isn't superkey, BCNF violation → decompose.
ER → Relational Mapping
8-step algorithm
You will draw ER diagrams and convert them to tables. Know the rules cold:

1:N → FK in N-side.
M:N → new relation with both PKs as composite PK.
Weak entity → include owner's PK.
Multi-valued attr → separate table.
Transactions & ACID
Atomicity, Consistency, Isolation, Durability
Atomicity: all or nothing — rollback on failure.
Consistency: DB goes from valid state to valid state.
Isolation: concurrent transactions appear sequential.
Durability: committed transactions survive crashes.

Isolation levels: READ UNCOMMITTED → READ COMMITTED → REPEATABLE READ → SERIALIZABLE.
DBMS Internals
Storage, indexing, locking
Storage: heap files, pages, slotted pages.
Indexing: B+ trees (most DB indexes), hash index. B+ tree: O(log n) search, all data in leaves.
Query optimizer: parses SQL → logical plan → physical plan (chooses join algorithm, index scans).
Locking: shared (read) vs exclusive (write). 2PL for serializability.

Functional Dependencies
Foundation of normalization
X → Y means: knowing X uniquely determines Y.

Closure: X⁺ = all attributes determined by X.
Minimal cover: minimal set of FDs equivalent to original.
Armstrong's axioms: reflexivity, augmentation, transitivity.

Practice computing closures — exam questions always ask for this.

SQL Patterns to Memorize
These query shapes appear on every DB exam
-- Multi-table JOIN with aggregation
SELECT e.name, d.dept_name, COUNT(p.project_id) AS num_projects
FROM Employee e
JOIN Department d ON e.dept_id = d.dept_id
LEFT JOIN Works_On w ON e.ssn = w.essn
LEFT JOIN Project p ON w.pno = p.pnumber
GROUP BY e.ssn, e.name, d.dept_name
HAVING COUNT(p.project_id) > 2
ORDER BY num_projects DESC;
-- Correlated subquery: employees earning more than dept average
SELECT e.name, e.salary
FROM Employee e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM Employee e2
    WHERE e2.dept_id = e.dept_id  -- references outer query
);
-- EXISTS: departments with at least one manager over 40
SELECT d.dept_name
FROM Department d
WHERE EXISTS (
    SELECT 1
    FROM Employee e
    WHERE e.ssn = d.mgr_ssn
    AND e.age > 40
);
-- Transaction with rollback on error
BEGIN;
    UPDATE Account SET balance = balance - 500 WHERE id = 1;
    UPDATE Account SET balance = balance + 500 WHERE id = 2;
    -- if either fails, ROLLBACK undoes both
COMMIT;
-- Normalization example: find BCNF violations
-- Relation: R(A, B, C, D) with FDs: AB→C, C→D, D→A
-- Check: is C a superkey? C⁺ = {C,D,A} ≠ all attrs → BCNF violation
-- Decompose: R1(C,D,A) and R2(A,B,C)
-- Verify lossless: R1∩R2 = {A,C} → C→A, A⊆R1 → lossless ✓

-- Relational algebra notation:
-- σ_{salary>50000}(Employee)          -- select
-- π_{name, salary}(Employee)          -- project  
-- Employee ⋈_{ssn=essn} Works_On      -- natural join
