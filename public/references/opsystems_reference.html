Processes & Threads
The OS illusion: each program thinks it owns the whole machine
Process
Program in execution
A process has its own: address space (virtual memory), open files, PCB (Process Control Block), PID. Isolated — one process can't touch another's memory by default.

States: New → Ready → Running → Waiting → Terminated. Context switch saves/restores PCB.
Thread
Lightweight process — shared memory
Threads within a process share: code, heap, global data, open files. Each thread has its own: stack, registers, program counter.

Cheaper to create than processes (no address space copy). Race conditions are the price of shared memory.
fork() & exec()
Unix process creation
fork() — creates a copy of the current process. Returns 0 to child, PID to parent. Uses copy-on-write — pages only copied when written.

exec() — replaces current process image with a new program. Shell: fork to create child, exec to run the command.
IPC
Inter-Process Communication
Pipes: unidirectional byte stream. | in shell.
Message queues: structured messages, OS-buffered.
Shared memory: fastest — processes map same physical page.
Sockets: work across machines too.
Signals: async notifications (SIGKILL, SIGTERM, SIGSEGV).

Who runs next? The policy shapes everything users experience as "speed"

Linux CFS (Completely Fair Scheduler): uses a red-black tree ordered by virtual runtime. Every process gets equal CPU time weighted by priority — no quantum, just fair shares.
Memory Management
Virtual memory — the illusion that every process has the whole address space
Virtual Memory
Isolation + more RAM than you have
Each process has a private virtual address space (e.g., 0 to 2⁴⁸ on 64-bit). The MMU translates virtual → physical via page tables.

Benefits: process isolation, can use more memory than physical RAM (swap), easier linking/loading, copy-on-write.
Paging
Fixed-size chunks
Virtual and physical memory divided into fixed-size pages (typically 4 KB). Page table maps virtual page → physical frame. OS stores pages on disk when RAM is full (swapping).

TLB (Translation Lookaside Buffer): hardware cache of recent virtual→physical translations. TLB miss = expensive page table walk.
Page Replacement
Which page to evict when RAM is full?
OPT: evict page not used for longest time — optimal but requires future knowledge.
LRU: evict least recently used — excellent in practice, expensive to implement exactly.
Clock (≈LRU): circular buffer with reference bits — approximates LRU cheaply. Used by Linux.
Thrashing
When swapping dominates
If a process's working set doesn't fit in RAM, it constantly page-faults and swaps. CPU spends all time on paging, zero on useful work.

Fix: working set model — only run as many processes as can fit their working sets in RAM. Suspend the rest.
Synchronization & Deadlocks
Concurrent access to shared data is the source of the hardest bugs
Race Condition
Outcome depends on timing
Two threads read-modify-write the same variable without synchronization. Result depends on scheduling — non-deterministic, hard to reproduce.

Critical section: the code that accesses shared data. Must be executed by at most one thread at a time.
Mutex & Semaphore
The two fundamental locks
Mutex (mutual exclusion): binary lock. Only the thread that locked it can unlock it. For protecting critical sections.

Semaphore: integer counter. wait() decrements (blocks if 0), signal() increments. Used for resource counting and producer-consumer.
Deadlock
Four necessary conditions (Coffman)
1. Mutual exclusion: resource held by one at a time.
2. Hold and wait: holding one, waiting for another.
3. No preemption: can't force release.
4. Circular wait: A waits for B, B waits for A.

Break any one condition to prevent deadlock.
Classic Problems
The three you'll be asked about
Producer-Consumer: bounded buffer — semaphores for empty/full slots + mutex for buffer access.
Readers-Writers: multiple readers OR one writer — readers don't block each other.
Dining Philosophers: 5 philosophers, 5 forks — circular wait → deadlock if all grab left fork first.
File Systems
Persistent storage abstraction — files and directories on top of raw blocks
inode
The metadata node (Unix)
Every file/directory has an inode: permissions, owner, timestamps, size, and pointers to data blocks. Filename is stored in the directory, not the inode — this is why hard links work (two names, one inode).

Indirect blocks extend addressing to huge files.
FAT vs ext4 vs NTFS
Common filesystem formats
FAT32: simple, universal, max 4 GB file — used for USB drives, embedded.
ext4: Linux default. Journaling, extents, large file support.
NTFS: Windows. Journaling, ACLs, compression, encryption.
APFS: Apple. Copy-on-write, snapshots, native encryption.
Journaling
Crash recovery without fsck
Before modifying filesystem structures, write the intended changes to a journal (log). If a crash occurs mid-write, replay the journal on boot to reach a consistent state.

Write-ahead logging — the same concept powers database durability (the D in ACID).
History of Operating Systems
From bare metal batch processing to containerized cloud infrastructure
1950s
No OS — Bare Metal
Programmers booked time on the machine, loaded programs by hand, and ran them directly. One program at a time. Expensive hardware sat idle between jobs. The "OS" was the human operator.
1956–1965
Batch Systems
Jobs collected on punch cards, submitted in batches, run sequentially. GM-NAA I/O (1956) is considered the first OS. IBM OS/360 (1964): one OS for an entire product line. Expensive programmers still waiting while slow I/O ran.
1961–1967
Time-Sharing & Multiprogramming
CTSS (MIT, 1961) first time-sharing system — multiple users simultaneously on one machine. Multics (MIT/Bell Labs/GE) attempts ambitious multi-user OS. Too complex, but spawns Unix.
1969–1971
Unix
Ken Thompson and Dennis Ritchie at Bell Labs write Unix on a discarded PDP-7. Rewritten in C (1973) — first OS written in a high-level language, making it portable. "Everything is a file" philosophy. Parent of Linux, macOS, Android, iOS.
1981–1985
Personal Computing OS
MS-DOS (1981) ships with IBM PC. Single-user, single-tasking, no memory protection. Apple Lisa (1983) and Macintosh (1984) bring GUI to consumers. The OS becomes something ordinary people interact with daily.
1991
Linux
Linus Torvalds, 21 years old, posts: "I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu)." Linux becomes the most widely deployed OS kernel in history — runs most of the internet, Android phones, and supercomputers.
2000–2010
Virtualization & Cloud
VMware brings x86 virtualization to enterprises (1999). Amazon EC2 (2006) launches cloud computing — OS abstracted from hardware. You rent CPU time, not machines. The hypervisor becomes as important as the OS itself.
2013–present
Containers & Beyond
Docker (2013) popularizes Linux containers — lightweight OS-level virtualization using namespaces and cgroups. Kubernetes (2014, Google) orchestrates containers at scale. The OS boundary blurs: your app runs in a container, on a VM, on shared hardware, managed by software.
